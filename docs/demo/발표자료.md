# 데모데이 발표자료 — PPT 8장 · 3분

09-08(화) 밤 12시까지 유튜브에 올릴 **3분 영상**용입니다. PPT 를 만들고 그것을 발표하는
화면을 녹화해서 냅니다. 09-09 데모데이의 5분 발표에도 같은 장을 씁니다.

이 문서에는 **슬라이드에 타이핑할 글자**와 **입으로 할 말**이 장마다 나뉘어 있습니다.
슬라이드에는 짧게 적고 긴 문장은 말로 합니다. 슬라이드에 말할 문장을 그대로 적으면
읽는 발표가 되고, 3분 안에 안 들어갑니다.

그림으로 뽑아 둔 같은 내용의 PNG 8장도 이 폴더에 있습니다. PPT 를 직접 만들 때는
아래 글자를 쓰고, 시간이 없으면 PNG 를 그대로 슬라이드에 깔아도 됩니다.

```
python docs/demo/make_slides.py    # S1 ~ S6
python docs/demo/make_boards.py    # C1 · C2
```

## 2장 · 문제 — 30초

**슬라이드에 적을 것**

```
5시간, 그리고 11분

"낸 날에는 몰랐습니다.
 이틀 뒤 밤에 첨삭해 주는 분이 표시해 줘서 알았습니다."

· 직접 만난 5명 중 3명은 남이 찾아 줘서 알았다
· 고치는 데 11분 · 11분 · 11분 · 24분 · 1시간 25분
· 5명 전부 이미 스스로 해결을 시도했다 (4명은 돈을 썼다)
```

**말**

> 실기 시험은 5시간입니다. 저희가 직접 만난 다섯 명 중 세 명은 빠뜨린 것을 자기가 아니라
> 친구나 첨삭해 주는 사람한테 들어서 알았습니다. 고치는 데 11분에서 1시간 25분이 들었고
> 그 시간 때문에 남은 검토를 잃었습니다. 혼자 준비하면 찾아 줄 사람이 없습니다.

**주의** — 인용은 원문 그대로 쓰고 **이름은 가려 씁니다.** 학교 이름도 슬라이드에
넣지 않습니다. 근거는 [인터뷰 5건](../interviews.md) 입니다.

> 기하공차, 주서, 표제란입니다. 나머지 30점, 투상도를 잘 골랐는지는 조건식으로 못 적어서
> AI가 봅니다. 확실하지 않으면 감점하지 않고 사람 확인 필요로 남깁니다.

## 4장 · 실제 화면 — 60초 · **슬라이드를 띄우지 않습니다**

운영진 안내에 "슬라이드보다 실제 화면이 낫습니다"라고 적혀 있습니다. 이 60초는
PPT 를 끄고 **CADLens 화면을 그대로 녹화한 것**을 넣습니다. 영상에서 제일 긴 구간입니다.

| 초 | 화면 | 말 |
|---|---|---|
| 0~5 | 도면 파일을 `새 도면 검사` 상자로 **끌어다 놓는다** | (말 없음. 손이 먼저 움직인다) |
| 5~20 | 점수와 지적 목록이 뜬다 | "올리면 몇 초 안에 점수와 지적이 나옵니다" |
| 20~40 | **도면 미리보기로 이동. 번호 마커 하나를 눌러 그 자리로 확대** | "여기가 저희가 다른 점입니다. 지적을 글로만 주지 않고 도면 위 그 자리에 번호로 찍습니다" |
| 40~50 | 질문 버튼 `왜 감점이야?` 를 누른다 | "왜 깎였는지, 어디를 고쳐야 하는지도 같이 나옵니다" |
| 50~60 | 고친 파일을 올려 **재검사 비교**가 뜬다 | "고쳐서 다시 올리면 전과 비교해서 보여줍니다" |

**20~40초가 이 영상의 핵심 장면입니다.** 번호와 도면 선이 같이 보이게 확대하세요.
번호가 안 보이면 이 구간이 무의미해집니다.

**녹화 전 확인**

- 쓸 도면을 **한 번 미리 검사해 둡니다.** 두 번째부터는 저장해 둔 AI 답을 써서 빠르고
  **점수도 안 튑니다.** 시연 중 점수가 튀면 설명이 꼬입니다.
- **표제란에 이름이 있는 도면은 쓰지 않습니다.** 결과 화면에 그대로 뜹니다.
- 말하면서 클릭하지 말고 **클릭한 뒤에 설명합니다.**
- 시연 도면 두 벌은 `python docs/demo/make_demo_pair.py` 로 만듭니다
  (`시연_고치기전.dxf` · `시연_고친뒤.dxf`).

## 5장 · 고치면 오른다 — 15초

**슬라이드에 적을 것**

```
고치면 점수가 오릅니다

고치기 전            고친 뒤
41 / 60점            55 / 60점
오작(실격)            오작 아님
지적 6건             지적 2건

검사 1초 미만
```

**말**

> 지적대로 고치면 점수가 오릅니다. 왼쪽이 고치기 전 41점에 오작, 오른쪽이 고친 뒤
> 55점입니다. 지적은 6건에서 2건으로 줄었고 검사는 1초가 안 걸립니다.

**그림을 넣으려면** — 이 폴더의 `도면_시연_고치기전.png` · `도면_시연_고친뒤.png` 가
DXF 를 그대로 그린 미리보기입니다. 주서 글자가 네모로 나오니, **실제 결과 화면을 캡처해서**
같은 이름으로 덮어쓰면 `make_slides.py` 가 그것을 씁니다.

## 6장 · 이번 주에 찾은 것 — 15초

**슬라이드에 적을 것**

```
가지고 있던 도면 9장이 전부 오작으로 찍혔습니다
실기 도면 두 장은 기하공차가 눈으로 보이는데도 못 찾았습니다

왜
실기 도면은 기하공차 기호를 전용 글꼴로 알파벳 한 글자를 찍어 만든다
화면에는 기호로 보이지만 파일에 남는 글자는 그냥  b

고친 뒤 — 실기 도면 2장 오작에서 빠짐
합성 도면 100장 — 100장 완전 일치, 그대로
```

**말**

> 이번 주에 가지고 있던 도면 9장을 검사했더니 9장이 전부 오작으로 나왔습니다.
> 실기 도면은 기하공차 기호를 전용 글꼴로 알파벳 한 글자를 찍어 만드는데,
> 파일에 남는 글자는 그냥 b 라서 저희가 못 읽고 있었습니다. 고쳤습니다.
> 합성 도면 100장 숫자는 그대로였습니다. 넉 달 동안 안 보이던 것입니다.

**이 장을 넣는 이유** — 잘 되는 것만 보여주는 발표보다 무엇을 어떻게 알아냈는지가
남습니다. 근거는 [문제점 P17](../../plan/문제점/P17-GDT글꼴기하공차.md) 입니다.

## 만들 때 지킬 것

- 한 장에 **글자 다섯 줄 안쪽.** 문장이 아니라 조각으로 적습니다.
- 숫자는 크게 씁니다. 41 / 55 / 9장 / 100장이 이 발표에서 기억에 남는 것입니다.
- 애니메이션은 넣지 않습니다. 3분에서 시간만 먹습니다.
- **소리 내어 읽어 보고 시간을 잽니다.** 글은 짧아 보이고 말은 깁니다.
  낭독 분량 160초는 초당 4.5자로 계산한 값이라 실제로는 더 걸릴 수 있습니다.

# 시연 영상 — 발표 도우미 3장

`presenter/video/demo.mp4`(1920×1080 · 60fps · 32초 · 소리 있음)를 만드는 도구다. 실제 CADLens 화면을 찍고, 그 위에
커서 · 카메라 · 자막을 얹고, 부분마다 그 사람 목소리(AI 합성)를 넣는다. 도면은 W4 영상의 `../영상시연/1차/본체.dxf`(팀이 만든 도면).

| 부분 | 목소리 | 화면 |
|---|---|---|
| ① | 안대열 | 도면을 끌어다 놓는다 — "놓기만" 이 끝날 때 놓는다 |
| ② | 장우영 | 실격 카드 · 도면 위 번호 · 목록의 번호 |
| ③ | 박지완 | "누르면" 에 번호를 누르고 그 자리로 확대 |
| ④ | 김승준 | "수정 예시입니다" 할 때 커서가 그 단추 위, 다음 문장 "누르면" 에 누르고 "빠진 치수를" 과 함께 초록 Ø20.5 · "위치와 값이" 에서 값으로 다가간다 |

```bash
# 1. 로컬 서버 — 통계는 임시 DB 로. Cloudflare 값을 비워야 공개 지표에 사람 검사로 안 섞인다
env -u CLOUDFLARE_API_TOKEN -u CLOUDFLARE_ACCOUNT_ID -u CADLENS_D1_STATS CADLENS_STAT_DB="$TEMP/demo_stats.db" \
  .venv/Scripts/python.exe -m uvicorn main:app --host 127.0.0.1 --port 8010

# 2. 이 폴더에서 (브라우저는 깔린 Chrome 을 쓴다 · ffmpeg 는 PATH 에)
npm i
node capture.js            # 실제 화면을 cap/ 에 3배 해상도로 찍는다 — 약 1분 30초
node render.js             # presenter/video/demo.mp4(목소리를 섞어 넣음) · demo.jpg — 약 3분
node render.js 0 1800 60   # 영상 대신 그 프레임만 check/ 에 PNG 로 (미리 보기)
```

- 콘티(시간 · 커서가 지나는 길)는 `story.js`, 카메라와 자막은 `compose.html` 의 `buildShots` · `CAPS`.
- 앱의 CSS 애니메이션을 멈춰 두고 프레임마다 시간을 맞춰 찍는다(`capture.js` 의 `__vc`). 찍는 속도와 상관없이
  스티커 · 끌어다 놓을 때 테두리 · 번호를 눌렀을 때 확대가 60fps 로 정확하다.
- OGQ 스티커 그림만 공개 서버(`/api/sticker/…` — 통계를 세지 않는 주소)에서 받아 공개 화면과 같게 한다.
- 늦게 오는 AI 답변(`/api/ai-extra`)은 찍는 동안 붙잡아 둔다. 오면 지적 목록을 다시 그려 화면이 바뀐다.
- 검사를 기다리는 몇 초는 "빨리 감기"라고 화면에 표시하고 줄인다.

## 목소리 (`voice/`)

`voice/v1 · v2 · v3 · v4a · v4b · v4c.wav` 가 영상에 들어간 대사다(-18 LUFS · 48kHz). 섞으면 약 -16.7 LUFS.
놓이는 시각과 대사 글은 `story.js` 의 `VOICE`, 누르는 순간은 낱말 시각(`voice/report.json`)으로 정했다.
팀원이 7월에 녹음한 소개 영상 음성(각 30초 안팎)이 바탕이다 — 원본 녹음은 저장소에 넣지 않는다.

**1. 실제 말투를 쟀다** (`voice/style.py` — 녹음을 낱말 시각까지 받아쓰기)

| | 문장 하나 말하는 빠르기 | 문장 사이 쉼 | 말버릇 |
|---|---|---|---|
| 안대열 | 6.54 음절/초 | 0.44~0.68초 | "저희는 ~" 으로 시작, "그래서 저희는 ~ 만들었습니다" |
| 장우영 | 6.64 | 0.64~1.04초 | "~하면 ~합니다" 로 기능을 차례대로 설명 |
| 박지완 | 5.50 | 0.78~0.98초 | "하지만 · 또한" 으로 잇는 설명, "~하는 방식입니다" |
| 김승준 | 7.11 (가장 빠름) | 0.46~0.88초 | "처음에는 ~했지만 · 앞으로는 ~할 계획입니다" |

첫 판은 이 빠르기와 어긋나 있었다 — 같은 문장 기준으로 안대열 14% 빠르고 장우영 4% 빠르고 박지완 9% ·
김승준 21~26% 느려, 부분마다 빠르기가 7.5 → 6.9 → 5.0 → 5.4 로 튀었다(사용자 — "실제 사람이 읽는 느낌이 안 나고
통일성이 떨어진다").

**2. 다시 만들었다** (`voice/gen.py`)

- 한 가지 길로 통일 — Chatterbox 다국어 TTS 가 그 사람 녹음의 말투로 바로 읽는다(첫 판은 두 길을 섞었다)
- 대사마다 후보 8개 → 받아쓰기 오류율 0 → 목소리 닮음(WavLM) + 자연스러움(UTMOS) + 그 사람 빠르기와의 차이로 고름
- 빠르기가 3% 넘게 어긋나면 음높이는 그대로 두고 늘이거나 줄임 — ① 0.89배 · ② 1.05배 · ④ 둘째 문장 1.06배
- 결과 빠르기 — ① 6.60 ② 6.64 ③ 5.61 ④ 7.05 · 7.11 · 7.03 (목표 6.54 · 6.64 · 5.50 · 7.11)
- 말이 끝난 뒤 따라붙은 숨·잡음 꼬리를 잘랐다(`voice/tail.py` — ② · ④ 둘째 문장에 0.7초씩). 자른 뒤 다시 받아써
  여섯 개 모두 오류율 0
- 사람 사이 쉼 0.48초 · 같은 사람 문장 사이 0.55초 — 위에서 잰 쉼의 아래쪽

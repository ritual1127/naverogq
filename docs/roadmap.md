# CADLens 발전 계획

앞으로 무엇을 어떤 순서로 할지 적어 둔 문서입니다. 기준일은 **2026년 8월 11일**입니다.

지금 무엇이 되고 무엇이 안 되는지는 [검사 정확도](accuracy.md)에, 다른 종목으로 넓힐 수
있는지는 [`example/`](../example/)에 있습니다.

---

## 우선순위

번호가 곧 순서입니다. 위에 있는 게 안 되면 아래 것을 해도 의미가 없습니다.

### 1. 실제 수험생 도면으로 정확도 다시 재기

지금 정확도 100%는 **저희가 직접 만든 연습용 도면 18장** 기준입니다. 도면을 만든 사람과
검사 규칙을 만든 사람이 같아서, 이 숫자만으로는 실제 시험 도면에서도 맞는다고 말할 수
없습니다. **이게 안 되면 나머지가 다 의미 없습니다.**

- [ ] 기계과 학생 도면을 이름 지운 상태로 모으기
- [ ] 같은 방식으로 다시 측정해 [검사 정확도](accuracy.md)의 표를 실제 도면 기준으로 교체
- [ ] 자체 제작 도면과 실제 도면의 결과 차이를 그대로 공개

### 2. AI 점수 안정시키기

투상도 30점은 AI가 매기는데 **같은 도면을 다시 넣으면 점수가 흔들립니다.** 확정 점수가
아니라고 화면에 적어 두긴 했지만, 흔들리는 폭 자체를 줄여야 합니다.

- [x] 같은 도면을 여러 번 돌려 편차가 몇 점인지 먼저 측정 — `variance.py`, 결과는 [검사 정확도](accuracy.md)에 있습니다 (2026-08-22)
- [ ] **단위가 mm가 아닌 도면의 백지 렌더 고치기.** 편차를 재다 드러났습니다. 도면 범위를 그대로 밀리미터로 보는 탓에 AI가 백지를 채점하고 있었습니다. 여기부터 고쳐야 아래 항목들이 의미가 있습니다
- [ ] 규칙으로 옮길 수 있는 건 옮기기 — 뷰 개수, 제3각법 배치는 좌표로 계산할 수 있을지 검토
- [ ] 그래도 남는 부분은 여러 번 물어 중앙값을 쓰는 방식 검토 (정확해지지만 비용이 늘어남)
- [ ] AI가 틀린 사례를 모아 두기. "AI를 어떻게 검증했나"에 답할 근거가 됩니다

### 3. 못 잡는 것 줄이기

[검사 정확도](accuracy.md)의 약점 표를 하나씩 지웁니다.

- [ ] 선으로만 그린 표면거칠기 기호 (지금은 문자로만 찾음)
- [ ] 직접 그린 기하공차 기입틀 (지금은 TOLERANCE 엔티티와 문자로만 찾음)
- [ ] 이름이 CENTER 계열이 아닌 중심선 레이어
- [ ] 선 4개로 그린 윤곽선 (지금은 닫힌 사각형만 인식)

#### 검사 자체가 없는 항목 (2026-08-27 설문에서)

위 넷은 "있는데 못 찾는" 것이고, 아래는 **검사 코드가 아예 없는** 것입니다.
[폼 응답 1건](interviews.md#폼-응답--대면-인터뷰와-따로-셉니다)에서 답한 사람이
빠뜨렸다고 고른 9개를 `exam.py`의 검사 24개와 하나씩 대조해 나왔습니다.
**9개 중 우리가 온전히 잡는 것은 3개였습니다.**

| 빠뜨렸다고 한 것 | 지금 | 무엇을 해야 하나 |
|---|---|---|
| 모떼기·필렛 주서 | ✅ `EX_NOTE_ITEM` | — |
| 투상도 하나 통째 빠뜨림 | ✅ `EX_FEW_VIEWS` · `AI_PROJECTION` | — |
| 표면거칠기 기호 | ✅ `DQ_NO_SURFACE_SYMBOL` | — |
| 척도 표기 | 🔺 부분 | `DQ_SCALE`은 **비표준 값**만, `EX_VIEW_NO_SCALE`은 뷰별만 봅니다. 표제란에 척도를 **아예 안 적은** 경우는 안 잡습니다 |
| 재질 기입 | ❌ 없음 | `_material`은 주서의 **열처리 문구만** 봅니다. 부품란의 재료 기호(SM45C, SCM415, GC200)가 있는지는 검사하지 않습니다 |
| 스퍼기어·스프링 요목표 | ❌ 없음 | 요목표 검사가 없습니다. 기어·스프링이 있는 도면에서 요목표는 채점 항목입니다 |
| 표면거칠기 비교표 | ❌ 없음 | 주서 옆 비교표(√w √x √y 대조)가 있는지 안 봅니다. **기호를 넣고도 비교표를 빠뜨리는 것은 따로 감점됩니다** |
| A4로 출력해서 잘림 | ❌ 범위 밖 | 출력 설정은 DXF에 없습니다. 도면 크기(`DQ_SHEET_SIZE`)와는 다른 문제입니다 |
| 파일 날림·저장 실패 | ❌ 범위 밖 | CAD 도구 문제입니다 |

표본이 **1명**입니다. 이것만으로 검사 항목을 늘리지 않고, 08-28 선생님 인터뷰와
나머지 응답에서 같은 말이 나오는지 먼저 봅니다.

#### 대면 인터뷰 5건에서 더 나온 것 (2026-08-29)

[대면 인터뷰 5건](interviews.md#대면-인터뷰-5건)에서 각자 말한 **가장 최근 실수**를
검사 24개와 대조했습니다. **다섯 중 온전히 잡는 것은 둘**이었습니다.

| 빠뜨렸다고 한 것 | 지금 | 무엇을 해야 하나 |
|---|---|---|
| 표면거칠기 기호 한 개 누락 (박\*후) | ✅ `EX_SURFACE_FEW` | — |
| 기하공차·데이텀 전부 없음 (배\*후) | ✅ `DQ_NO_GEOMETRIC_TOL` · `EX_FCF_NO_DATUM` | — |
| **뷰 척도가 요구와 다름** (박\*호 — 전체 1:1인데 커버만 2:1) | ❌ 없음 | `DQ_SCALE`은 비표준 값만, `EX_VIEW_NO_SCALE`은 표기 유무만 봅니다. **2:1은 표준 척도라 안 걸립니다.** 도면 안에서 척도가 섞였는지, 요구 척도(보통 1:1)와 같은지는 검사하지 않습니다 |
| 내부 형상에 **단면도가 없음** (손선생님) | 🔺 부분 | `EX_FEW_VIEWS`는 뷰 개수만 셉니다. "안쪽에 구멍·턱이 있는데 단면이 없다"는 판정은 `AI_PROJECTION` 몫이고, 그 AI가 [P02](../plan/문제점/P02-AI점수편차.md)로 열려 있습니다 |
| 프린터 A4 설정으로 잘림 (최\*영) | ❌ 범위 밖 | 폼 응답 1건과 **같은 항목이 두 번째**입니다. 출력 설정은 DXF에 없습니다 |

**우선순위가 바뀝니다.** 다섯 명의 최근 실수가 전부 다른 항목이었고, 5명 중 4명은
제출 전에 스스로 또는 옆 사람에게서 찾았습니다. 고치는 데 11~85분이 들었습니다.
즉 값어치는 "누락을 알려 주는 것"보다 **작업 도중에 더 일찍 알려 주는 것**에 있습니다.
근거는 [인터뷰 — 우리가 틀리게 알고 있던 것](interviews.md#우리가-틀리게-알고-있던-것).

### 4. 지원 형식 넓히기

- [ ] 3D 모델 채점은 2D가 안정된 뒤에 합니다

### 5. 다른 종목으로 넓히기

`exam.py`의 판정 함수와 루브릭이 KS 제도 규칙에 기반해 있어 다른 종목에도 상당 부분
그대로 쓸 수 있습니다. 어디까지 되는지는 미리 조사해 [`example/`](../example/)에 남겼습니다.

| 종목 | 규칙 재사용 | 순서 |
|---|---|---|
| 기계설계산업기사 | 약 90% | 1순위 |
| 일반기계기사 | 약 60% | 2순위 (작업형 한정) |
| 사출금형산업기사 | 약 55% | 3순위 |
| 프레스금형산업기사 | 약 50% | 4순위 |

- [ ] **0단계 — 구조 정리.** `exam.py`가 기능사 기준값을 모듈 상수로 박아 두고 있어 두 번째
      종목이 들어오면 막힙니다. 값을 종목별로 분리하되 **검사 함수 안에 종목 분기는 넣지
      않습니다.** 종목이 늘어나면 분기가 규칙마다 퍼져 손댈 수 없게 됩니다
- [ ] 종목별 공개문제를 3개 회차 이상 확보하기 전에는 코드를 건드리지 않습니다.
      확인되지 않은 기준으로 검사 규칙을 만들면 응시자에게 틀린 지적을 하게 됩니다

## 얼마나 쓰이는지 재는 방법

지금은 **아무것도 세지 않습니다.** 사람을 모으는 것보다 먼저 고칠 게 남았다고 봤고,
쓰는 사람 대부분이 미성년자라 함부로 붙일 수도 없었습니다.

CADLens는 [공개 고지](policy.md)에서 **추적 코드가 없고, 회원가입이 없고, 개인을 알아볼 수
있는 정보를 받지 않는다**고 약속했습니다. 지표가 필요하다고 그 약속을 깨면 정직함으로 쌓은
걸 스스로 무너뜨리는 것이라, **약속을 지키면서 셀 수 있는 것만** 세기로 했습니다.

**셀 것**

| 지표 | 어떻게 | 개인 식별 |
|---|---|---|
| 검사 횟수 (일별·월별) | 검사가 끝날 때 숫자만 +1 | 없음 |
| 재방문율 | 브라우저에 이미 있는 `cadcheck.history`로 "2회 이상 검사한 브라우저" 비율 | 없음. 기기 안에서 판단하고 결과 숫자만 보고 |
| 재검사 비율 | 같은 파일 이름을 다시 올린 비율 (= 고치고 다시 온 사람) | 없음 |
| 점수 개선 폭 | 재검사 때 점수가 몇 점 올랐는지 | 없음 |
| 언어·다크모드 분포 | 이미 브라우저에 있는 설정값 집계 | 없음 |

**안 셀 것** — IP, 쿠키, 광고 ID, 도면 내용, 파일 이름 원본, 위치, 기기 지문.

**대표로 삼을 숫자는 방문자 수가 아닙니다.** CADLens에서 의미 있는 건
**"검사 → 고침 → 재검사로 점수가 오른 사람의 비율"** 입니다. "몇 명이 왔다"가 아니라
**"몇 명이 실제로 나아졌다"** 는 뜻이라, 도면을 봐주는 도구로서 훨씬 정확한 숫자입니다.

집계를 시작하면 [임팩트](impact.md)와 README의 해당 절을 실제 숫자로 바꿉니다.

## 문서를 어떻게 관리할지

숫자가 문서마다 다르면 그 자체로 신뢰를 잃습니다.

- [ ] 정확도를 다시 잴 때마다 README · [검사 정확도](accuracy.md) · [임팩트](impact.md)의
      숫자를 같이 맞춥니다
- [ ] 응시자 통계는 [`example/96_응시자_통계.md`](../example/96_응시자_통계.md)를 원본으로
      두고 다른 문서는 그걸 인용합니다. 아직 1차 출처(통계연보)로 대조하지 않았다는 것도
      그 문서에 적어 뒀습니다
- [ ] 문서가 코드의 함수 이름이나 상수를 언급하면, 그게 실제로 있는지 확인하고 씁니다

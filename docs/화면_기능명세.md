# CADLens 화면 기능 명세 — 디자인 교체 참고용

이 문서는 화면을 새로 디자인할 때 참고할 **기능 정보만** 담았습니다. 색, 글꼴, 간격, 모양, 애니메이션 같은 디자인 요소는 일부러 뺐습니다. 지금 화면의 배치도 따를 필요가 없습니다. 대신 여기 적힌 기능, 데이터, 상태, 문구 조건은 새 화면에서도 빠짐없이 동작해야 합니다.

- 기준 코드: `static/index.html`(화면 전체), `main.py`(API), `exam.py`(규칙 채점), `ai_review.py`(AI 채점), `stats.py`(사용 현황), `dwg.py`(도면 읽기·미리보기)
- 기준 시점: 2026-09-15 `main` 브랜치
- 응답 예시는 로컬 서버에서 예제 도면으로 실제로 받은 값이고, 길이 때문에 일부 배열과 숫자를 줄였습니다. 분석 결과 예시는 AI 채점을 끄고 받은 것이라, AI 지적(7-8 아래쪽)은 모양만 보여 주려고 값을 비웠습니다.

아래 본문(0~11장)은 개편 전 화면을 기준으로 썼습니다. API와 채점은 그대로이고, 화면에서 달라진 점은 이 표에 모았습니다.

| 부분 | 바뀐 점 |
|---|---|
| 글꼴·장식 | 나눔스퀘어라운드 R·B·EB를 `static/fonts/`에 넣어 씀(OFL, 외부 요청 없음). 일본어·중국어는 영문·숫자만 이 글꼴, 가나·한자는 시스템 글꼴. three.js와 3D 로고를 없애고 도면 위에 번호가 찍히는 SVG 그림으로 바꿈 |
| 헤더 | 메뉴(소개 · 사용법 · 채점 기준 · 자주 묻는 질문), `사용 안내` 버튼 추가. 서버 상태 표시는 없앰. 로고를 누르면 홈 맨 위로 |
| 홈 | 첫 화면에 `도면 올리기`(파일 선택 창 열기)·`예제로 먼저 보기` 버튼. 아래로 소개(README 문제 3가지) · 사용법 4단계 · 채점 기준(100점 막대) · 검사 근거 · 사용 현황 · 자주 묻는 질문 6개 섹션. 예제 카드에 서버 설명(`note`)을 보여 줌(영·일·중은 화면 번역). 검사 항목 선택기는 업로드 카드 안 접이식 패널 |
| 첫 방문 안내 창 | 4장(뭐 하는 곳 · 올리는 법 · 결과 보는 법 · 고쳐서 다시 올리기). 처음 한 번 자동으로 뜨고 `사용 안내`로 다시 열림. Esc·바깥 클릭·← →키 지원, 포커스는 창 안에서만 돎. 본 기록은 `localStorage['cadcheck.intro']` |
| 검사 중 | 화면 전체 로딩 창에 파일 이름과 경과 초를 표시. 로딩 중에는 추가 업로드·예제 검사를 받지 않음 |
| 검사 항목 0개 | 업로드·예제 모두 검사를 막고 "검사 항목을 1개 이상 켜 주세요." 안내 |
| 오류 | 홈에서는 업로드 카드 안, 결과 화면에서는 오른쪽 맨 위에 표시 |
| 결과 화면 | 상단 바에 `고친 파일 다시 올리기`(결과 화면에서 바로 파일 선택). 점수는 원형 게이지. 지적사항 · 채점 항목 · 파일 정보를 탭으로 나눔(← →키 이동). 지적 등급을 아이콘+글자로 표시하고, AI 지적에도 `AI` 배지. 마커 칩은 키보드로 누를 수 있는 버튼. 질문 답 영역에 `aria-live`. 좁은 화면에서 뷰어 높이는 44vh |
| 파일 정보 | `_`로 시작하는 내부 값(`_has_title_block`)은 보여 주지 않음. 보여 줄 값이 없으면 탭을 숨김 |
| 문구 | 검사 개수는 서버 값({n})으로, 규칙 70점 + AI 30점, 점수 주석 "합격선 60% 기준", 개인정보 고지에 AI 채점기 네 곳과 안내 창 기록을 반영 |
| 번역 | 템플릿이 없던 규칙 지적 7개(`DQ_NO_FIT` 등)를 영·일·중으로 채우고, 쓰지 않는 `EX_NO_FIT` 템플릿과 쓰지 않는 문구 키(`ready`, `cmpClear` 등)를 지움 |
| 푸터 | 공개 고지 4개를 접지 않고 펼쳐서 보여 줌 |

11장에 적었던 화면 문제 중 **문구 불일치 6개, 번역 템플릿 7개, 키보드 접근 2개, `aria-live`, 로딩 중 중복 업로드, 검사 항목 0개, `_has_title_block` 표시**는 개편에서 고쳤습니다. API에만 있고 화면에 안 쓰는 값 중에서는 `samples[].note`만 쓰게 됐습니다.

개편 뒤 확인하다 새로 찾은 것 하나: 예제 `sample_autocad.dxf`에서 마커 칩을 누르면 빈 곳으로 확대됩니다. 서버가 주는 `svg_tf`로 계산한 마커 좌표(SVG 기준 약 748450, 813200)가 SVG에 실제로 그려진 마커 위치(약 588800, 587000)와 달라서입니다. 화면의 확대 계산은 개편 전과 같고, 합성 도면 `005_undimensioned.dxf`에서는 제자리로 확대됩니다.

## 0. 새 화면이 지켜야 할 조건

### 기술 조건
1. **화면은 `static/index.html` 한 파일입니다.** HTML, CSS, JS가 한 파일에 들어 있고 빌드 도구와 프레임워크가 없습니다. 서버는 `GET /` 요청에 이 파일을 그대로 돌려줍니다. 새 화면도 이 파일 하나(필요하면 `/static/` 아래 정적 파일 추가)로 끝나야 서버 코드를 바꾸지 않아도 됩니다.
2. 외부 CDN을 쓰지 않습니다. 쓰는 라이브러리는 서버에 같이 올려 둔 `/static/vendor/three.min.js`(3D 로고) 하나뿐입니다.
3. 쓰는 이미지 파일: `/static/logo.png`, `/static/favicon.ico`(32px), `/static/favicon.png`(180px, apple-touch-icon 겸용).
4. 4개 언어(한국어 `ko`, 영어 `en`, 일본어 `ja`, 중국어 `zh`)를 새로고침 없이 바꿀 수 있어야 합니다. 화면에 고정된 문구는 모두 4벌이 필요합니다(9장).
5. 밝은 화면과 어두운 화면을 모두 지원해야 합니다.
6. 좁은 화면(휴대폰)에서도 동작해야 합니다. 지금은 폭 980px 이하에서 모든 블록이 한 열로 쌓이고, 서버 상태 표시와 브랜드 부제("도면 자동 검사")를 숨깁니다.

### 공개 고지에 이미 약속한 것 (새 화면이 어기면 안 됨)
푸터 고지와 README에 적어 둔 약속입니다. 새 화면에 기능을 더할 때 이 목록과 부딪히지 않는지 먼저 확인해야 합니다.

- 회원가입, 로그인, 이름·연락처 입력란이 없습니다.
- 쿠키, 외부 분석 도구, 광고, 추적 코드, 결제가 없습니다. 외부 폰트나 CDN을 새로 넣으면 접속 정보가 제3자에게 가므로 고지 문구와 함께 검토해야 합니다.
- 채팅, 댓글, 프로필처럼 사용자끼리 접촉하는 기능이 없습니다.
- **AI에게 문장을 직접 입력하는 곳이 없습니다.** 지적마다 붙는 질문 버튼은 미리 정한 3개뿐이고, 답도 채점할 때 미리 만들어 둔 것입니다.
- AI가 매긴 결과에는 AI 표시를 붙입니다.
- "공식 채점이 아니다"를 밝히고, "합격" 대신 "합격선"이라고 씁니다.
- 언어, 화면 설정, 재검사 기록은 사용자 브라우저에만 저장합니다.

## 1. 서비스 요약

- **무엇:** 전산응용기계제도기능사 실기 도면(DWG·DXF)을 올리면 37개 항목을 자동으로 검사합니다. 공개 채점 기준 8개 항목(100점)으로 점수와 오작(실격) 여부를 보여 주고, 치수가 빠진 구멍 위치를 도면 미리보기 위에 번호로 찍어 줍니다.

- **가장 중요하게 보는 지표:** 주간 재검사 사용자 수(한 주에 두 번 이상 검사한 사람). 그래서 "다시 올리기"와 "비교"가 쉬워야 합니다.
- 공개 주소: https://naverogq.onrender.com

## 2. 화면 구조와 상태

한 페이지 안에서 **홈**과 **결과** 두 화면을 숨겼다 보였다 합니다. 주소(URL)는 바뀌지 않습니다.

```
공통 헤더  : 브랜드 · 테마 토글 · 언어 4개 · 서버 상태 표시
홈 화면    : 소개 · 업로드 · 상태 영역(로딩/오류) · 예제 도면 · 검사 항목 선택 · 채점 기준 · 실격 조건 · 검사 근거 · 사용 현황
결과 화면  : 파일 이름/메타 · 다른 도면 검사 버튼 · 도면 미리보기 · 파일 정보 · 재검사 비교 · 점수 · 지적사항 · 채점 항목 · AI 총평 · 면책 문구
공통 푸터  : 공개 고지 4개 (접이식)
```

### 상태 전환

```
[페이지 열림] ── /api/health, /api/samples, /api/stats 동시 요청 ──> [홈: 대기]
[홈: 대기]   ── 파일 선택 / 파일 끌어다 놓기 / 예제 버튼 ─────────> [홈: 검사 중]
[홈: 검사 중] ── 성공 ──> [결과]
[홈: 검사 중] ── 실패 ──> [홈: 대기 + 오류 문구]
[결과]       ── "다른 도면 검사" ──> [홈: 대기]
[결과]       ── 언어 변경 ──> [결과] (같은 데이터를 그 언어로 다시 그림)
```

- `/api/health` 요청이 실패하면 상태 영역에 "앱을 준비하지 못했습니다. 잠시 뒤 다시 시도해 주세요."가 뜨고 검사 항목 선택기가 비어 있습니다.
- 브라우저 뒤로가기를 누르면 홈으로 가지 않고 사이트를 떠납니다. 새로고침하면 결과가 사라집니다. 결과를 공유하는 링크, 인쇄, 내보내기 기능은 없습니다.

### 4-2. 업로드

**드롭존**
- 누르면 파일 선택 창이 열립니다(숨긴 `<input type="file">`을 `<label>`로 감싼 구조).

- 안내 문구: "새 도면 검사", "파일 선택 또는 드래그", "도면 파일을 놓으세요", "{지원 확장자} 또는 zip 패키지"

## 5. 결과 화면

검사가 성공하면 홈을 숨기고 결과 화면을 띄운 뒤 맨 위로 스크롤합니다.

### 5-1. 파일 이름 · 메타 · 돌아가기
- 파일 이름: `file`
- 메타 한 줄(` · `로 이음)
  - 종류: `kind`의 이름. 지금 DXF와 DWG는 모두 `kind: "dwg"`로 와서 항상 "2D 도면"입니다. `part`/`drawing`/`assembly`(부품/도면/조립품) 이름표는 코드에 남아 있지만 지금은 오지 않습니다.
  - 규격: `standard`. 지금 서버가 항상 `null`을 보내서 나오지 않습니다.
  - 투상법: `first_angle`이 `true`면 "제1각법", `false`면 "제3각법", `null`이면 생략
  - `Job {12자리 id}`
- "다른 도면 검사" 버튼: 홈으로 돌아가 오류·로딩 문구를 지우고 작업 영역을 보여 준 뒤 맨 위로 스크롤합니다. 방금 본 결과를 다시 여는 버튼은 없습니다.

### 5-2. 도면 미리보기
- 응답에 `svg` 문자열이 있으면 뷰어를 보여 주고, 없으면 뷰어를 숨기고 `svg_note` 문구를 보여 줍니다.
  - `svg_note` 예: "이 형식은 2D 도면 미리보기를 만들지 않습니다.", "도면 미리보기를 만들지 못했습니다 — {오류}"
  - 한국어가 아니면 `svg_note` 대신 "이 파일은 2D 도면 미리보기를 만들 수 없습니다."의 번역을 보여 줍니다.
- SVG는 서버가 만든 문자열을 그대로 DOM에 넣습니다.

**조작**

| 입력 | 결과 |
|---|---|
| 마우스 휠 | 커서 위치를 기준으로 확대·축소(한 칸에 1.18배). 뷰어 위에서는 페이지 스크롤을 막습니다. |
| 끌기(마우스·터치·펜) | 이동 (pointer capture 사용) |
| `+` / `−` 버튼 | 가운데 기준 1.4배 확대 / 축소 |
| "자동 맞춤" 버튼 | 도면을 뷰어 크기의 98%로 맞춰 가운데 둠 |
| 창 크기 변경 | 자동 맞춤을 다시 실행 (사용자가 바꾼 배율은 풀림) |

- 배율 표시: 자동 맞춤 상태를 100%로 한 백분율. 범위는 40% ~ 4500%.
- 두 손가락 확대(핀치 줌)는 없습니다.

**번호 표시(마커)**
- **서버가 SVG 안에 직접 그려서 보냅니다.** 원(구멍 둘레) + 선 + 번호가 적힌 원판이 빨간 레이어로 그려져 옵니다. 화면이 따로 그리는 겹침 요소가 아니라서, 모양을 바꾸려면 `dwg.py`의 `_arrow()`를 고쳐야 합니다.
- 새 화면에서 마커를 직접 겹쳐 그리고 싶으면 `svg_tf`로 DXF 좌표를 SVG 좌표로 바꿀 수 있습니다. 이 경우 서버가 그린 마커와 겹치므로 서버 쪽도 함께 바꿔야 합니다.
  - `svgX = dxf_x × scale + off_x`
  - `svgY = off_y − dxf_y × scale`
  - `svg반지름 = dxf_r × scale`
- 지금 마커가 붙는 지적은 **치수 없는 원·구멍** 두 가지(`EX_DIM_MISSING`, `EX_NO_DIMS`)뿐입니다.

**지적 카드의 마커 칩을 눌렀을 때**
- 해당 위치를 가운데 두고 확대합니다. 원의 반지름이 뷰어 높이의 약 18%가 되도록 하되, 자동 맞춤 배율의 4~14배 사이로 제한합니다.
- 누른 칩을 활성 상태로 표시하고 다른 칩의 활성 표시는 지웁니다.
- 폭 980px 이하에서는 뷰어가 화면 가운데 오도록 부드럽게 스크롤합니다.

### 5-3. 파일 정보
- 이름·값 목록이고 값이 있는 것만 보여 줍니다. 하나도 없으면 블록을 숨깁니다.
- `props`(표제란 속성에서 읽음, 빈 문자열이면 숨김): 품번 `part_number`, 재료 `material`, 설계자 `designer`, 설명 `description`, 개정 `revision`

  - `props`에는 내부용 `_has_title_block`(불리언)도 섞여 옵니다. 지금 코드는 이 값이 `true`면 "_has_title_block / true" 줄을 그대로 보여 주게 되어 있으니 새 화면에서는 걸러야 합니다.
- `stats`(`null`·빈 문자열이면 숨김, 0은 보여 줌): 시트 `sheets`(지금 항상 1), 치수 `dims`, 미치수 원 `undimensioned`, 투상도 `views`, 표제란 `title_block`(예: `"표제란(문자)"` 또는 `null`)
  - 불리언이면 "있음"/"없음"으로 보여 줍니다.
  - "부품 수"(`occurrence_count`)는 이름표만 있고 지금 서버가 보내지 않습니다.
- 표제란에 적힌 설계자 이름이 여기 뜹니다. 개인정보 고지에 "남기고 싶지 않으면 지우고 올리세요"라고 안내하고 있습니다.

### 5-4. 재검사 비교
**비교 조건**
- 이 브라우저에서 **같은 파일 이름**을 검사한 적이 있으면 비교합니다. 서버가 아니라 `localStorage['cadcheck.history']`를 씁니다.
- 파일 이름마다 가장 최근 1건만 남기고, 최대 20개 파일까지 저장합니다. 넘치면 오래된 것부터 지웁니다.

**처음 검사한 파일**: 안내 한 줄 "같은 파일을 고쳐서 다시 올리면 이전 결과와 비교해 드립니다."

**비교가 있을 때**
- 머리: "재검사 비교" + "{방금 / N분 전 / N시간 전 / N일 전} · 전 검사와 비교"
- 실격 배너(바뀐 경우에만)
  - 이전에는 실격, 지금은 아님: "실격 항목이 해결됐습니다"
  - 이전에는 아님, 지금은 실격: "실격 항목이 새로 생겼습니다"
- 점수: `이전 % → 지금 %` + 차이(`+N`, `-N`, `0`). 올랐는지, 내렸는지, 같은지 구분해서 보여 줍니다. 값이 없으면 `—`.
- 태그 3개: 고쳐짐 N, 그대로 N, 새로 생김 N
- 목록: 고쳐진 항목 이름들, 새로 생긴 항목 이름들("그대로"는 개수만 보여 줌)
- 고쳐짐과 새로 생김이 모두 0이면 "지적사항이 그대로입니다"

**비교 방식**
- 지적의 **코드 종류**로 비교합니다. 같은 코드의 지적이 5곳에서 1곳으로 줄어도 "그대로"로 셉니다.
- 점수는 반올림한 `percent`끼리 뺍니다.
- 비교가 뜰 때마다 서버에 `recheck` 이벤트를 한 번 보냅니다(파일 이름은 보내지 않음). 같은 결과를 언어만 바꿔 다시 그릴 때는 보내지 않습니다.
- "기록 지우기"(`cmpClear`) 문구가 4개 언어로 준비되어 있지만 이 문구를 쓰는 버튼은 없습니다.

### 5-5. 점수
**① 실격일 때** (`scorecard.disqualified === true`, 즉 켠 검사에서 `severity: "fail"` 지적이 하나 이상 나옴)
- 판정: "불합격 — 오작"
- 큰 글: "실격"
- 설명: "점수와 무관하게 불합격 처리되는 조건입니다."
- 실격 사유 목록: `disqualifiers`(한국어가 아니면 번역한 fail 지적 제목)
- 주석: "규칙 60점 기준 · 공식 채점이 아닙니다"
- 점수 숫자는 보여 주지 않습니다.

**② 실격이 아닐 때**
- `Math.round(percent) >= 60`이면 "합격선 통과", 아니면 "합격선 미달"
- 큰 글: `{반올림 percent}%`
- "자동 채점 `{auto_score} / {auto_max}`"
- 개수 3칸: 오류(`summary.error`), 경고(`summary.warn`), 참고(`summary.info`)
- 주석: "규칙 60점 기준 · 공식 채점이 아닙니다"

**`auto_max`는 AI 상태에 따라 바뀝니다.** AI가 투상도를 채점했으면 100, 못 했으면 70(투상도 30점을 빼고 계산)입니다. 그래서 퍼센트의 분모도 달라집니다.

### 5-6. 지적사항
**등급 필터**
- "전체 N" 버튼과, 1건 이상 있는 등급만 "실격 N", "오류 N", "경고 N", "참고 N" 버튼으로 보여 줍니다.
- 누르면 그 등급만 보이고, 선택한 버튼을 표시합니다.
- 새 도면 결과가 오면 "전체"로 돌아가고, 언어만 바꿀 때는 선택을 유지합니다.

**정렬**: 서버가 실격 → 오류 → 경고 → 참고 순으로 정렬해서 보냅니다.

**빈 목록**: "해당 지적사항이 없습니다."

**지적 카드 — 접힌 상태**
- 등급 표시 (지금은 카드 테두리 색으로만 구분)
- 제목 `title`
- 메타: 채점 항목 이름(`item` 코드를 이름으로 바꿈) · "{deduct}점 차감"(0이면 생략)
- 마커 칩(5-2의 두 지적만): `{번호} Ø{지름, 소수 1자리} · {개수}곳` (예: `1 Ø28.5 · 1곳`)
- 펼침 버튼(`aria-expanded`로 상태 표시)

**지적 카드 — 펼친 상태**
- 설명 `detail`
- 고치는 법 `fix` (설명과 구분해서 보여 줌)
- **질문 버튼** (`followups[현재 언어]`가 있을 때만 = 지금은 AI 지적만)
  - 제목: "이 지적이 궁금하면"
  - 버튼 3개: "왜 감점이야?", "어디를 눌러?", "고친 뒤 확인은?"
  - 누르면 미리 만들어 둔 답이 펼쳐집니다. 서버를 다시 부르지 않습니다.
  - 한 번에 답 하나만 열리고, 같은 버튼을 다시 누르면 닫힙니다.
  - 아래 안내: "채점할 때 미리 만들어 둔 답입니다"
- 위치: "위치 · {sheet} · {view} · {sketch} · {feature}" (있는 값만. 확인한 예제에서는 모두 비어 있었음)

**등급**

| `severity` | 화면 이름 | 뜻 |
|---|---|---|
| `fail` | 실격 | 오작. 하나라도 있으면 점수와 상관없이 불합격 |
| `error` | 오류 | 규칙 위반 |
| `warn` | 경고 | 주의가 필요한 항목 |
| `info` | 참고 | 참고 정보 |

감점 여부는 등급이 아니라 `deduct` 값으로 따로 옵니다.

### 5-7. 채점 항목 · AI 총평
- 8행이고 서버가 배점이 큰 순으로 정렬해서 보냅니다.
- 행마다: 항목 이름, `mode`가 `ai`면 "AI" 표시, 값, 막대
  - 항목 이름: 한국어는 서버 `label`(긴 이름), 다른 언어는 `CHECK_LABELS`
  - 값: `{score} / {max}`, 사람 확인이면 `확인 / {max}`
  - 막대 길이: `score / max`, 사람 확인이면 0

| `mode` | 뜻 |
|---|---|
| `auto` | 규칙 채점 |
| `ai` | AI 채점 (투상도 선택과 배열만) |
| `review` | 사람 확인 필요 (AI 채점이 안 됐을 때의 투상도, `score: null`) |

- AI 총평: `ai_verdict`가 있으면 "AI 총평 (AI 생성) · {문장}"
  - 한국어가 아니면 `ai_verdict_i18n[언어]`를 쓰고, 없으면 일반 문구("AI review is available for human confirmation." 등)를 보여 줍니다.

### 5-8. 면책 문구
- "자동 검사는 제출 전 확인을 돕는 보조 도구입니다. 최종 제출 전에는 도면 기준과 지시사항을 함께 확인하세요."
- `review_points`가 0보다 크면 뒤에 " {N}점은 사람이 직접 확인해야 하는 항목입니다."를 붙입니다.

## 7. API

모든 요청은 같은 도메인으로 보냅니다. 오류 응답은 `{"detail": "한국어 문장"}`과 HTTP 상태 코드입니다.

### 7-1. `GET /api/health`
페이지를 열 때 한 번 부릅니다. 서버 상태 확인(Render health check, GitHub Actions 깨우기)에도 씁니다.

```json
{
  "ok": true,
  "supported": [".dwg", ".dxf"],
  "ai": true,
  "ai_provider": "gemini",
  "ai_model": "gemini-3.6-flash",
  "local": false,
  "dwg_converter": true,
  "dwg_via": "LibreDWG",
  "oda": null,
  "checks": [
    {"id": "DQ_NO_SURFACE_SYMBOL", "label": "표면거칠기 기호가 아예 없음",
     "group": "오작", "group_label": "오작(실격)", "default": true}
  ],
  "exam": {"sheet": "A2", "third_angle": true}
}
```

| 필드 | 뜻 | 지금 화면에서 |
|---|---|---|
| `ok` | 서버 준비됨 | 씀 |
| `supported` | 열 수 있는 확장자(DWG 변환기가 없으면 `.dwg` 빠짐) | 씀 |
| `ai` | AI 채점기를 쓸 수 있는지 | 씀 |
| `ai_provider`, `ai_model` | 첫 번째 AI 채점기와 모델 | 안 씀 |
| `local` | 이 컴퓨터에서 접속했는지 | 안 씀 |
| `dwg_converter`, `oda` | DWG 변환기 유무, ODA 경로 | 안 씀 |
| `dwg_via` | DWG 변환기 이름 | 씀 ("DWG 변환 준비됨") |
| `checks[]` | 검사 카탈로그 37개. `group`은 `오작` 또는 채점 항목 코드 | 씀 |
| `exam.sheet` | 요구 용지 | 씀 |
| `exam.third_angle` | 제3각법 요구 여부 | 안 씀 |

### 7-3. `GET /api/stats`

```json
{
  "available": true,
  "store": "sqlite",
  "missing_env": ["CLOUDFLARE_ACCOUNT_ID", "CADLENS_D1_STATS", "CLOUDFLARE_API_TOKEN"],
  "today": {"visitors": 0, "checks": 2},
  "week": {"since": "2026-09-14", "visitors": 0, "checks": 2, "recheckers": 1, "rechecks": 0},
  "total": {"visits": 9, "checks": 19, "samples": 10, "rechecks": 6, "done": 29,
            "days": 4, "since": "2026-09-06"},
  "daily": [{"day": "2026-09-06", "visitors": 1, "checks": 5}]
}
```

- 로컬 서버 값입니다. 공개 서버는 Cloudflare D1에 저장해서 `"store": "d1"`이고 `missing_env`가 없습니다.
- 조회에 실패하면 `{"available": false}`만 옵니다.
- **`daily`(최근 14일 일별 접속·검사 수), `total.rechecks`, `total.done`은 지금 화면에서 쓰지 않습니다.**
- 세는 시점: `visit`은 `GET /`, `check`는 파일 업로드, `sample`은 예제 검사, `done`은 결과가 실제로 나감, `recheck`는 화면이 보낸 이벤트

### 7-4. `POST /api/analyze` — 파일 업로드
- `multipart/form-data`
  - `file`: 도면 파일 (필수)
  - `checks`: 켠 검사 id를 쉼표로 이은 문자열 (선택. 없거나 빈 값이면 전체 검사)
- 응답: 7-8의 분석 결과

### 7-5. `POST /api/analyze-sample` — 예제 검사
- JSON: `{"name": "sample_plate.dxf", "checks": ["DQ_NO_FIT", "..."]}`
  - `checks`를 빼거나 `null`이면 전체 검사, `[]`이면 0개 검사
- 응답: 7-8의 분석 결과

### 7-6. `POST /api/analyze-path` — 로컬 경로 검사 (지금 화면에 없음)
- JSON: `{"path": "C:\\도면\\a.dxf", "checks": [...]}`
- 서버와 같은 컴퓨터에서 접속할 때만 됩니다. 원격이면 403 "경로 분석은 이 컴퓨터에서만 사용할 수 있습니다. 원격에서는 파일을 업로드하세요."

### 7-7. `POST /api/event`
- JSON: `{"kind": "recheck"}`
- 지금 받는 종류는 `recheck` 하나뿐입니다. 다른 값이면 400 "셀 수 없는 이벤트입니다."

## 8. 데이터 사전

### 8-1. 지적(`findings[]`)

| 필드 | 뜻 |
|---|---|
| `code` | 검사 코드(8-5). AI 지적은 모두 `AI_PROJECTION`. 검사 코드 자체가 실패하면 `EX_RULE_ERROR`(info, "검사 오류: …", "개발자에게 알려주세요.")가 오고, 이 코드는 켠 항목과 상관없이 늘 보입니다. |
| `severity` | `fail` / `error` / `warn` / `info` |
| `title`, `detail`, `fix` | 한국어 제목, 설명, 고치는 법 |
| `item` | 속한 채점 항목 코드(8-4) |
| `deduct` | 감점(점). 0이면 감점 없음 |
| `where` | `{sheet, view, sketch, feature}` 중 있는 것 |
| `i18n` | AI 지적만. `{en: {title, detail, fix}, ja: {...}, zh: {...}}` |
| `followups` | AI 지적만. `{ko: [답1, 답2, 답3], en: [...], ...}`. 답 3개가 다 갖춰진 언어만 들어 있음. 순서는 왜 / 어디 / 확인 |

- AI 지적 1건의 감점은 최대 12점이고, AI 지적 감점의 합은 최대 30점입니다. `severity`는 AI가 정하며 값이 없으면 `warn`입니다.

### 8-2. 채점표(`scorecard`)

| 필드 | 뜻 |
|---|---|
| `auto_score` / `auto_max` / `percent` | 채점한 항목의 점수 합 / 배점 합 / 백분율(소수 1자리) |
| `review_points` | 사람 확인이 필요한 배점 합(AI 채점이 안 됐으면 30, 됐으면 0) |
| `items[]` | 8개 채점 항목 `{code, label, max, score, mode}` |
| `disqualified`, `disqualifiers[]` | 실격 여부, 실격 지적 제목들 |
| `ai_verdict`, `ai_verdict_i18n`, `ai_model` | AI 총평(한국어), 언어별 총평, 채점한 모델 |
| `enabled_count`, `total_checks` | 켠 검사 수, 전체 검사 수 |
| `summary` | 등급별 지적 수 `{total, fail, error, warn, info}` |

### 8-3. 마커(`marker_index[]`)

| 필드 | 뜻 |
|---|---|
| `n` | SVG에 그려진 번호 |
| `diameter_mm` | 구멍 지름(mm) |
| `count` | 같은 지름 구멍 개수 |
| `sheet` | 시트 이름 |

## 11. 새 화면을 만들 때 알아 둘 현재 동작

모두 코드를 읽거나 로컬 서버를 실제로 호출해서 확인한 내용입니다.

### 화면 문구와 서버 값이 다른 곳

| 위치 | 화면 문구 | 서버 값 |
|---|---|---|
| 검사 근거 카드 | "24개 검사 항목" (고정) | 카탈로그 37개. 같은 페이지 소개 영역 숫자는 서버 값이라 37로 나옵니다. |
| 검사 근거 카드 | "규칙 60점 + AI 30점", "치수와 공차 60점은 규칙으로 채점" | 규칙 70점 + AI 30점 = 100점 (`exam.RUBRIC`) |
| 점수 카드 주석 | "규칙 60점 기준" | 합격선 판정은 `percent >= 60`이고, 분모는 AI 상태에 따라 70 또는 100 |
| AI 생성물 고지 | "나머지 60점과 실격 판정은 AI를 쓰지 않는 규칙 검사입니다." | 규칙 채점은 70점 |
| AI 생성물 고지 | "AI가 매긴 항목에는 AI 배지가 붙습니다." | 배지는 채점 항목 줄에만 있고, AI 지적 카드(`AI_PROJECTION`)에는 없습니다. |
| 개인정보 고지 | "도면을 그림으로 바꿔 Google Gemini API로 보냅니다." | 같은 푸터의 AI 고지와 서버 설정은 Gemini · Cloudflare Workers AI · Mistral · Groq 네 곳을 순서대로 씁니다. |

### 번역 템플릿이 없는 규칙 지적
아래 7개 코드는 `FINDING_I18N`의 en/ja/zh 모두에 템플릿이 없어서, 한국어가 아닐 때 항목 이름과 일반 문구로 나옵니다. 반대로 `FINDING_I18N`에는 지금 쓰지 않는 `EX_NO_FIT` 템플릿이 남아 있습니다(서버 코드는 `DQ_NO_FIT`).

`DQ_NO_FIT`, `EX_LAYOUT_FIRST_ANGLE`, `EX_LINEWEIGHT_FLAT`, `EX_LINEWEIGHT_NONE`, `EX_NO_ROUGH_TABLE`, `EX_NO_SPEC_TABLE`, `EX_TEXT_SIZE`

### 입력·조작
- 드롭존은 `<label>` 안에 `display:none`인 input이 들어 있고 `tabindex`가 없어서, 키보드만으로는 파일 선택 창을 열 수 없습니다. 키보드로 할 수 있는 검사는 예제 버튼뿐입니다.
- 마커 칩은 `<span>`에 클릭 처리만 달려 있어서 키보드로 누를 수 없습니다.
- 질문 버튼의 답이 펼쳐질 때 스크린리더 알림(`aria-live`)이 없습니다.
- 로딩 중 중복 업로드를 막지 않습니다(4-3).
- 검사 항목을 0개 켜면 업로드와 예제의 결과가 다릅니다(4-6).
- `props._has_title_block`이 `true`면 파일 정보에 내부 키 이름이 그대로 나오는 코드입니다(5-3).

### API에는 있지만 화면에 안 쓰는 것
- 예제 설명 `samples[].note`
- 최근 14일 일별 통계 `stats.daily`, 전체 재검사 수 `total.rechecks`, 결과를 본 횟수 `total.done`
- 채점한 AI 모델 `health.ai_model`, `scorecard.ai_model`
- 도면에서 읽은 주서 문장 `notes_text`
- 켠 검사 수 `scorecard.enabled_count` / `total_checks`
- 로컬 경로 검사 `POST /api/analyze-path`
- "기록 지우기" 문구(`cmpClear`, 버튼 없음)

## 부록 B. 공개 고지 전문 (한국어)

**제목:** 개인정보 · AI 생성물 · 저작권 · 미성년자 안전 안내

**개인정보**
회원가입과 로그인이 없고 이름·연락처를 받지 않습니다. 올린 도면은 검사에만 쓰고 서버에서 최대 1시간 안에 지웁니다. 쿠키와 외부 분석 도구를 쓰지 않습니다. 다만 접속 수와 검사 횟수는 저희 서버에서 직접 셉니다 — IP 를 그 주에만 쓰는 값과 함께 해시한 16자만 남기고 IP 원본은 저장하지 않습니다. 언어, 화면 설정, 재검사 기록은 사용자 브라우저에만 저장됩니다. 다만 투상도 배열 검사를 위해 도면을 그림으로 바꿔 Google Gemini API로 보냅니다. 도면 표제란에 이름이 있으면 결과 화면에 표시되니, 남기고 싶지 않으면 지우고 올리세요.

**AI 생성물 표기**
투상도 선택과 배열 30점, 그리고 AI 총평 문장은 AI(Gemini · Cloudflare Workers AI · Mistral · Groq 중 한 곳)가 생성한 결과입니다. 나머지 60점과 실격 판정은 AI를 쓰지 않는 규칙 검사입니다. AI가 매긴 항목에는 AI 배지가 붙습니다. 같은 도면이라도 AI 점수는 달라질 수 있으며, 확정 채점이 아닙니다.

**저작권**
도면의 저작권은 그린 사람에게 있습니다. CADLens는 도면을 AI 학습에 쓰지 않고 재배포·판매하지 않습니다. 검사 기준은 KS 규격과 공개된 채점 기준만 근거로 하며, 비공개 채점표를 복제하지 않았습니다. CADLens는 공식 채점이 아니고 한국산업인력공단·Q-Net과 제휴 관계가 없습니다. 프로젝트 코드는 MIT 라이선스로 공개합니다.

**미성년자 안전**
주 사용자가 미성년 수험생이라는 전제로 만들었습니다. 개인정보 입력란, 결제, 광고, 추적 코드가 없습니다. 채팅·댓글·프로필 같은 사용자 간 접촉 기능이 없습니다. AI는 도면 채점 역할로 고정되어 있고 정해진 형식의 응답만 화면에 나옵니다. 지적의 질문 버튼도 미리 정해 둔 세 가지뿐이며 답도 채점할 때 함께 만들어 둔 것이라, 문장을 입력해 AI와 자유롭게 대화할 수 있는 곳이 없습니다. 올린 도면은 최대 1시간 뒤 서버에서 지우며 AI 학습에 쓰지 않습니다.

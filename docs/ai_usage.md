## 프로덕트 안에서 쓰는 AI — 투상도 30점 채점

90점 중 60점은 규칙 코드(`exam.py`)가 채점하고, AI는 **정답을 조건식으로 못 적는
30점(투상도 선택·배열)만** 맡습니다. `ai_review.py`가 도면을 PNG 1장으로 바꿔
아래 순서로 물어보고, 앞이 막히면 다음으로 넘어갑니다.

| 순서 | 제공자 | 모델 | 고른 이유 | 어디에 기여하나 |
|---|---|---|---|---|
| 1 | Google Gemini | `gemini-3.6-flash` | 무료 티어가 있고 멀티모달(이미지+텍스트) 응답을 JSON 스키마로 강제할 수 있어, 도면 그림을 보고 정해진 형식(`severity`·`title`·`detail`·`fix`·`deduct`)으로만 답하게 만들 수 있다. 응답 속도도 빨라 검사 한 번의 체감 대기시간에 맞는다 | 30점 채점의 1순위 경로. 대부분의 검사가 여기서 끝난다 |
| 2 | Cloudflare Workers AI | `@cf/meta/llama-4-scout-17b-16e-instruct` | Gemini 무료 할당량이 마르면 30점 채점 전체가 멈춘다. Cloudflare는 이미 배포 인프라로 쓰고 있어 **같은 계정으로 추가 가입 없이** 바로 대체 경로를 열 수 있고, 무료 티어가 있다 | Gemini 할당량 소진 시 30점 채점을 계속 살려 둔다 |
| 3 | Mistral | `mistral-small-latest` | 유럽계 제공자를 하나 넣어 특정 리전 장애·정책 변경에 세 곳이 동시에 막히는 상황을 줄인다. 무료/저가 티어로 학생 프로젝트 예산에 맞는다 | 1·2순위가 둘 다 막혔을 때 30점 채점을 이어간다 |
| 4 | Groq | `qwen/qwen3.6-27b` | 추론 속도가 빨라 앞선 셋이 전부 막힌 뒤에도 사용자가 오래 기다리지 않게 한다. 무료 티어 존재 | 마지막 보루. 여기까지 막히면 30점은 "사람 확인 필요"로 표시 |

**왜 멀티모달이어야 했는가** — "정면도를 잘 골랐나", "뷰가 균형 있게 놓였나"는 도면을
**눈으로 봐야** 판단할 수 있고 텍스트만 주고받는 모델로는 채점이 안 된다. 그래서 네
경로 모두 이미지 입력이 되는 모델만 골랐다.

**왜 무료 티어가 중요한가** — CADLens는 학생 8주 프로젝트이고 서버 비용을 팀이 직접
낸다. 유료 API만 쓰면 검사 횟수가 늘수록 비용이 늘어 계속 켜 둘 수 없다.

**왜 대체 제공자를 셋이나 넣었는가** — 제공자 하나에만 의존하면 그 한 곳의 무료
할당량이 마르는 순간 30점 채점(배점이 가장 큰 항목)이 통째로 멈춘다. 넷 중 하나만
살아 있어도 채점이 이어지게 만들었다.

**공통 지시문** — 네 경로 모두 같은 시스템 프롬프트와 같은 JSON 스키마를 쓰고,
"확실하지 않으면 감점하지 말고 참고로만 남겨라"라는 지시가 포함돼 있다. 응답이
스키마를 벗어나면 그 결과는 버리고 "사람 확인 필요"로 처리한다. 자세한 것은
[`docs/policy.md`](policy.md) "AI 생성물 표기" 절.

## 개발에 쓴 AI (프로덕트 안이 아님)

| 도구 | 무엇에 썼나 |
|---|---|
| Claude Code (Claude Opus 5 / Sonnet 5 / Sonnet 4.8) | 코드 초안, 코드 정리, 문서·번역 초안, 이 저장소의 계획·기록 작성 |
| GPT-5.6 Sol | 코드 초안 보조 |
| Gemini | 문서·번역 초안 보조 |

**사람이 한 것** — 뭘 만들지 정하기, 검사 항목을 고르고 KS 규격과 대조하기, 배점 정하기,
실제 도면으로 돌려보며 오류 찾기, 기준 도면 만들기, 마지막에 읽고 고칠지 결정하기.
AI가 만든 코드·문서는 **전부 사람이 확인한 뒤에만** 저장소에 들어갔다.

**개발 도구 AI와 프로덕트 AI를 섞지 않는 이유** — 심사에서 보는 "프로젝트의 AI 사용"은
사용자가 쓰는 제품 안에 들어간 AI(투상도 30점)이지, 저희가 코드를 짤 때 쓴 보조 도구가
아니다. 둘을 한 표에 넣으면 실제 제품 로직과 개발 편의 도구가 구분이 안 된다.

# 검사 정확도

CADLens가 "무엇을 얼마나 잡는지"를 숫자로 남기기 위한 문서입니다.
`bench.py`가 정답이 붙은 기준 도면을 실제 분석 경로(파일 → 사실 추출 → 채점)로
그대로 통과시키고, 나온 지적을 정답과 비교합니다.

```
python bench.py                       # 합성 기준 도면으로 측정
python bench.py labels.json           # 직접 라벨링한 실제 도면으로 측정
python bench.py --check               # 기준 미달이면 종료 코드 1 (CI에서 사용)
```

## 측정 방법

- **검출률(recall)**: 도면에 실제로 있는 결함 중 CADLens가 잡아낸 비율.
  낮으면 수험생이 놓친 것을 그대로 놓칩니다.
- **정확도(precision)**: CADLens가 지적한 것 중 실제 결함인 비율.
  낮으면 멀쩡한 도면을 틀렸다고 해서 수험생을 헷갈리게 합니다.
- **완전 일치**: 한 도면의 지적 목록이 정답과 정확히 같은 경우. 부분 정답을
  후하게 쳐주지 않기 위해 함께 기록합니다.

AI 판정(투상도 배열 30점)은 실행할 때마다 결과가 달라질 수 있으므로 측정에서
제외하고, 규칙 기반 검사만 측정합니다.

## 이 숫자의 한계

**이 100%를 "실기 도면에서 100% 맞힌다"로 읽으면 안 됩니다.**

기준 도면은 결함을 하나씩 심어 만든 **합성 도면**이고, 만든 사람과 검사 규칙을
만든 사람이 같습니다. 실제 수험생 도면보다 단순하므로 현장 정확도와는 다릅니다.
이 표가 보장하는 것은 다음 두 가지뿐입니다.

1. 18가지 상황에서 잡아야 할 것을 잡는다 (기능 회귀 시험).
2. 결함이 없는 도면에 헛지적을 하지 않는다.

### 아직 남아 있는 약점

측정으로 드러났거나, 원리상 틀릴 수 있다고 알고 있는 부분입니다.

| 약점 | 어떻게 틀릴 수 있나 | 현재 대응 |
|---|---|---|
| 표면거칠기 기호를 문자로 판별 | 기호를 선으로만 그리고 문자를 안 넣으면 못 봄 → 실격 오탐 | `√`·Ra 값·소문자 다듬질 기호를 인식. 대문자 X/Y/Z는 축 표시로 보고 제외 |
| 기하공차를 `TOLERANCE` 엔티티와 GDT 문자열로 판별 | 공차 기입틀을 선과 문자로 직접 그리면 못 봄 → 실격 오탐 | 향후 기입틀 도형 인식 필요 |
| 중심선을 레이어·선종류 이름으로 판별 | 이름이 CENTER/중심/DASHDOT 계열이 아니면 못 봄 | 선종류 패턴(점·쇄선 간격) 인식은 미구현 |
| 윤곽선을 닫힌 사각형으로 판별 | 선 4개로 그린 윤곽선은 못 봄 | 표제란 문자(품명·재질·척도)로 보완 |
| 투상도 배치·개수 | 순수 DXF는 뷰 경계를 알 수 없음 | 판별 불가일 때 검사를 건너뜀. 배치는 AI 판정으로 별도 처리 |
| 실제 수험생 도면 표본 | 라벨이 붙은 실제 도면이 아직 없음 | 아래 형식으로 넣으면 바로 측정됨 |

실제 도면으로 측정하려면 도면 파일과 정답 라벨을 JSON으로 두고 돌리면 됩니다.

```json
{
  "my_drawing_1.dxf": ["EX_DIM_MISSING", "EX_NO_FIT"],
  "my_drawing_2.dxf": []
}
```

## 측정으로 잡은 문제 (2026-08-05)

이 벤치마크를 붙이자마자 DXF 경로에서 구조적 오탐이 드러났고, 다음을 고쳤습니다.

| 문제 | 원인 | 조치 |
|---|---|---|
| 모든 DXF가 "표면거칠기 기호 없음"으로 실격 | DXF에서 거칠기 기호를 추출하지 않고 개수를 항상 0으로 둠 | 문자에서 `√`, `Ra/Rz/Ry` 값, 다듬질 기호(w/x/y/z)를 인식 |
| 모든 DXF가 "기하공차 없음"으로 실격 | 기하공차를 추출하지 않음 | `TOLERANCE` 엔티티와 GDT 문자열에서 공차값·데이텀 파싱 |
| 모든 DXF가 "중심선 없음" | 중심선 개수를 세지 않음 | 레이어·선종류가 CENTER/중심인 요소를 집계 |
| 모든 DXF가 "투상도 0개" | 투상도는 Inventor 블록 이름으로만 판별 | 판별 불가일 때는 "없음"이 아니라 검사 생략 |
| 모든 DXF가 "표제란 없음" | 표제란을 블록 속성으로만 인식 | 윤곽선(닫힌 사각형)과 표제란 문자(품명·재질·척도 등)로도 인식 |
| 문자가 하나라도 있으면 "주서 있음" | 도면의 모든 문자를 주서로 취급 | 주서다운 문자(여러 줄·주서 키워드·일정 길이)만 주서로 취급 |
| 축 표시 문자 `X`/`Y`/`Z`를 다듬질 기호로 오인 | 다듬질 문자 판정에 대소문자를 구분하지 않음 | 기호(`√`) 없이는 소문자만 인정. 실격 도면을 통과시키던 오류라 위험도가 가장 컸음 |
| 주서 문구가 거칠기 기호로 분류되어 주서에서 빠짐 | 문자 분류 순서가 주서보다 기호가 먼저였음 | 주서다운 문자를 먼저 주서로 판정 |

## AI 점수 편차 (2026-08-22)

투상도 30점은 AI가 매기므로 같은 도면이라도 실행할 때마다 점수가 달라집니다.
"달라진다"는 건 알고 있었지만 몇 점이 달라지는지는 재 본 적이 없어서, 먼저
재는 도구를 만들고 숫자를 남깁니다.

```
python variance.py samples/sample_plate.dxf -n 5
```

같은 도면을 5회 채점해 점수 분포와 지적 등장 횟수를 뽑습니다. `check.py` 경로는
같은 그림이면 캐시된 답을 돌려주므로 편차가 0으로 보입니다. 그래서 `variance.py`는
캐시를 건너뛰고 매번 새로 묻습니다.

| 도면 | 5회 점수 | 폭 | 표준편차 |
|---|---|---|---|
| `sample_plate.dxf` | 18, 18, 20, 20, 20 | 2점 | 1.10점 |
| `sample_autocad.dxf` | 18, 18, 18, 18, 18 | 0점 | 0.00점 |
| `sample_075em07z.dwg` | 0, 18, 18, 18, 18 | **18점** | 8.05점 |

- **무엇을 지적하는지는 흔들리지 않았습니다.** 15회 모두 "투상도 누락"을 지적했고
  다른 지적이 끼어든 경우는 없었습니다.
- **흔들리는 건 감점 폭입니다.** 같은 지적에 12점을 깎기도 하고 30점을 다 깎기도
  합니다(0점). 프롬프트가 "형상 표현이 불가능할 정도의 투상도 누락: 8~12점"이라고
  범위를 줬는데 그 범위를 벗어난 판정이 5회 중 1회 나왔습니다.
- **지적 제목은 매번 다르게 적힙니다.** "투상도 전체 누락", "투상도 완전 누락",
  "투상도 전체 누락 및 형상 표현 불가"가 같은 판정에 대해 섞여 나옵니다. 뜻은 같지만
  화면에 보이는 문구가 매번 달라지므로 수험생에게는 다른 지적처럼 보입니다.

### 이 측정에서 더 큰 문제가 드러났습니다

`sample_075em07z.dwg`는 선이 6,373개 들어 있는 실제 도면인데 AI는 5회 모두
**"투상도가 하나도 없다"** 고 답했습니다. AI에게 보내는 그림을 직접 저장해 보니
**201바이트짜리 빈 그림**이었습니다. AI는 도면이 아니라 백지를 채점하고 있었습니다.

원인은 도면 단위입니다. 이 파일의 도면 범위(`$EXTMIN`~`$EXTMAX`)는 약 0.12 × 0.12로,
`ai_review.render_png`가 이 값을 그대로 밀리미터로 보고 페이지를 만듭니다. 여백만
사방 5mm이라 그림이 들어갈 자리가 사실상 없어집니다. A3(420 × 297)로 그려진 도면은
멀쩡히 나오지만, 단위가 미터나 인치인 도면은 백지가 됩니다.

즉 위 표의 18점 편차는 AI가 오락가락한 게 아니라, **백지를 보고 몇 점을 깎을지
고민한 결과**입니다. 편차를 줄이기 전에 이 렌더링부터 고쳐야 합니다.

### 백지 렌더를 고친 뒤 (2026-08-22 밤)

`ai_review.render_png`가 도면 단위(`$INSUNITS`)를 밀리미터로 환산해서 그리도록 고쳤습니다.
단위 판별은 이미 있던 `dwg.detect_mm_per_unit`을 그대로 씁니다.

| 도면 | 고치기 전 그림 | 고친 뒤 그림 |
|---|---|---|
| `sample_075em07z.dwg` | 201바이트 (백지) | 283,550바이트 (도면이 보임) |
| `sample_autocad.dxf` | 201바이트 (백지) | 283,550바이트 |
| `sample_plate.dxf` | 5,696바이트 (정상) | 5,889바이트 (그대로 정상) |

**`sample_autocad.dxf`도 백지였습니다.** 이 도면이 다섯 번 모두 18점으로 편차 0을 보인 것은
채점이 안정적이어서가 아니라 매번 같은 백지를 봤기 때문이었습니다.

한 지적이 30점을 통째로 깎는 것도 막았습니다(`MAX_SINGLE_DEDUCT = 12`). 채점 지침이 정한
가장 큰 감점 폭이 8~12점인데 그보다 큰 감점 사유는 지침에 없습니다.

#### 다시 잰 결과 — 편차는 줄지 않았습니다

`python variance.py samples/sample_075em07z.dwg -n 5`

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 점수 | 0, 18, 18, 18, 18 | 0, 0, 5, 9, 18 |
| 폭 | 18점 | 18점 |
| 표준편차 | 8.05점 | 7.50점 |
| 지적 수 | 매번 1건 | 1~3건 |

**줄지 않았습니다.** 오히려 점수 중앙값이 18점에서 5점으로 내려갔습니다. 백지일 때는 지적이
"투상도 전체 누락" 하나로 일정했는데, 진짜 그림을 보게 되자 지적 개수부터 흔들립니다.
**편차의 원인은 백지가 아니라 프롬프트와 모델 쪽이었습니다.** 백지 렌더는 그것대로 반드시
고쳐야 할 버그였지만, 편차 문제는 따로 남아 있습니다.

한 가지 더 — 이 표본은 기계 부품 도면이 아니라 무늬가 반복되는 도면이었습니다. 그림을 열어
보고 알았습니다. 그러니 "투상도가 없다"는 판정 자체는 틀리지 않았을 수 있습니다.
**편차 측정을 실제 수험생 도면으로 다시 해야 합니다.** 표본이 잘못되면 측정도 잘못됩니다.

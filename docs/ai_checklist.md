# AI 윤리 체크리스트

W3(09-01~09-07) 산출물입니다. [AI 사용 기록](ai_usage.md)이 **무슨 모델을 왜 골랐나**를
적은 문서라면, 이 문서는 **그 AI를 쓰면서 지켜야 할 것을 지켰나**를 한 칸씩 확인한 표입니다.

확인 못 한 칸은 비워 두지 않고 `🔺`·`❌`로 남깁니다. 전부 `✅`인 체크리스트는
확인한 적이 없다는 뜻이기 때문입니다.

| # | 항목 | 결과 | 근거 |
|---|---|---|---|
| 1 | 어떤 AI가 무엇을 하는지 사용자에게 공개했나 | ✅ | 90점 중 **투상도 30점만** AI. 화면의 AI 항목에 보라색 `AI` 표시, 총평 상자에 AI가 쓴 문장이라고 표기. [`policy.md`](policy.md) 「AI 생성물 표기」 |
| 2 | AI 결과와 규칙 코드 결과를 섞지 않고 구분했나 | ✅ | 규칙 60점 + 실격 판정 5가지는 `exam.py` 순수 코드, AI는 `ai_review.py`. `bench.py` 는 `use_ai=False` 로 규칙만 잰다 |
| 3 | AI 점수를 확정 점수로 보이지 않게 했나 | ✅ | 확정 점수로 표시하지 않는 것을 [MVP 범위표](mvp.md) 「안 만들 것」에 못 박았다. 확실하지 않으면 감점 대신 **"사람 확인 필요"** |
| 4 | AI가 이상하게 답하면 어떻게 되나 | ✅ | JSON 스키마를 벗어난 응답은 **버리고** "사람 확인 필요"로 넘긴다. 한 지적이 30점을 통째로 깎지 못하게 `MAX_SINGLE_DEDUCT = 12` (채점 지침의 최대 감점 폭 8~12점) |
| 5 | 사용자 도면을 AI 학습에 쓰나 | ✅ 안 씀 | 어떤 AI도 사용자 도면으로 학습시키지 않는다. [`policy.md`](policy.md) 「올린 도면」 |
| 6 | 밖으로 나가는 데이터를 사용자가 알 수 있나 | ✅ | 나가는 지점은 **하나**다 — 투상도 30점 채점 때 도면을 PNG 1장으로 바꿔 Gemini(막히면 Workers AI → Mistral → Groq)로 보낸다. 원본 DWG·DXF 는 안 나간다. [아키텍처](architecture.md) 「개인정보가 밖으로 나가는 지점은 하나뿐」 |
| 7 | 도면 안에 든 개인정보를 경고했나 | ✅ | **표제란에 이름이 있으면 그 이름이 그림에 함께 찍혀 나간다.** 결과 화면에도 그대로 뜬다. 이 사실을 [`policy.md`](policy.md) 에 적고 "올리기 전에 지우고 올리세요"를 넣었다 |
| 8 | 개인정보를 안 받는 구조인가 | ✅ | 회원가입·로그인·쿠키·외부 추적 코드 없음. 세는 것은 접속·검사·재검사 횟수뿐이고 방문자 값은 주 단위 해시 16자 |
| 9 | 미성년 이용자를 고려했나 | ✅ | 이용자 대부분이 미성년이라 **브라우저에 아무것도 안 남기는 쪽**을 골랐고, 채팅·댓글·프로필 같은 사용자끼리 만날 곳을 [MVP 범위표](mvp.md)에서 아예 안 만들기로 잘랐다 |
| 10 | 같은 도면에 같은 점수가 나오나 (재현성) | 🔺 | **안 나온다.** 같은 도면 5회에 0·0·5·9·18점, 폭 18점 · 표준편차 7.50점. 원인은 프롬프트·모델 쪽으로 좁혔고 아직 열려 있다 — [P02](../plan/문제점/P02-AI점수편차.md) · [정확도](accuracy.md) |
| 11 | AI 가 만든 코드·문서를 사람이 확인했나 | ✅ | 개발에 쓴 AI 도구는 [AI 사용 기록](ai_usage.md)에 프로덕트 AI 와 **나눠서** 적었다. AI 초안은 전부 사람이 읽고 고친 뒤 커밋했다 |
| 12 | 성능 숫자를 부풀리지 않았나 | 🔺 | 공개한 100% 는 **합성 도면 100장** 숫자이고, 도면을 만든 사람과 규칙을 만든 사람이 같다. 이 한계를 [정확도](accuracy.md)·[데모 대본](demo_script.md) ③절·[P04](../plan/문제점/P04-표본도면.md)에 그대로 적었다 |
| 13 | 실제 도면 정확도를 쟀나 | ❌ | **못 쟀다.** `실제도면/labels.json` 이 비어 있어 `bench.py` 를 못 돌린다. 사람이 눈으로 라벨을 붙여야 한다. 실기 도면 표본은 2장뿐 — [P04](../plan/문제점/P04-표본도면.md) |
| 14 | API 키가 코드에 박혀 있지 않은가 | ✅ | 현재 코드와 커밋 히스토리 전체에서 0건. 자세한 명령과 결과는 [보안 점검표](security_check.md) |
| 15 | 올린 도면이 실제로 지워지는가 | 🔺 | 로직은 검증했고(1시간·최근 20건, 10분마다 주기 실행, `test_prune.py` 통과) **배포 서버 실측이 남았다** — [P15](../plan/문제점/P15-업로드정리주기.md) |

**✅ 11 · 🔺 3 · ❌ 1**

## 아직 못 지킨 것 세 가지

1. **같은 도면에 같은 점수가 안 나온다** ([P02](../plan/문제점/P02-AI점수편차.md)) — AI 30점의
   폭이 18점이다. 시연에서는 같은 도면을 두 번째 검사해 캐시된 결과를 쓴다.
2. **실제 도면 정확도를 아직 못 쟀다** ([P04](../plan/문제점/P04-표본도면.md)) — 합성 도면
   숫자만 있다. 09-06 에 실기 도면 9장 중 9장이 오작으로 잘못 찍히던 것을 찾은 것도
   합성 도면으로는 안 보였기 때문이다 ([P17](../plan/문제점/P17-GDT글꼴기하공차.md)).
3. **배포 서버에서 1시간 뒤 삭제를 눈으로 못 봤다** ([P15](../plan/문제점/P15-업로드정리주기.md)).

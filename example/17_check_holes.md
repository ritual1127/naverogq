# 일반기계기사 — 검사함수 분석 — check_holes

## 함수: `rules.py::check_holes`

| 항목 | 내용 |
|---|---|
| 검사 코드 | `HOLE_TOO_SMALL / HOLE_TOO_DEEP` |
| 기능 | 홀 직경이 기준(3.0mm) 미만이거나 깊이/직경 비가 10을 넘는지 검사한다. |

## 이 종목에서의 적용 가능성

3D 모델의 형상 피처 정보가 필요하다. 2D 도면만으로는 판정할 수 없다.

## 결론

이 종목의 실기 제출물 구성(`04_실기_과제구성.md` 참조)에 따라 활성/비활성 여부가
갈린다. 2D 도면만 제출한다면 3D 전용 함수는 항상 빈 결과를 내며, 이는 오류가
아니라 정상 동작이다. 불필요하게 끄지 않아도 된다 — 대상이 없으면 자연히
아무 것도 잡히지 않는다.

## 함수가 소비하는 입력 데이터

`check_holes`은 `facts` 딕셔너리의 특정 키를 읽어 판정한다. 이 키가 비어 있으면
(예: 3D 모델이 없어 `facts.get("holes", [])`가 빈 리스트) 함수는 예외 없이
빈 결과를 반환하도록 `rules.py` 전체가 설계되어 있다(`.get(key, [])` 패턴).
이 종목에 맞게 검사기를 켜고 끄는 별도 스위치를 만들 필요가 없는 이유가 이
방어적 설계 때문이다.

## 오탐 가능성 점검

이 함수가 이 종목에서 오탐(실제로는 문제가 없는데 지적하는 경우)을 낼 가능성은
주로 입력 데이터 구조가 종목별 CAD 작성 관행과 다를 때 생긴다. 예를 들어
`HOLE_TOO_SMALL / HOLE_TOO_DEEP`가 특정 레이어명이나 블록명에 의존한다면, 이 종목의 표준 도면 양식이
같은 명명 규칙을 쓰는지 먼저 확인해야 한다. 확인 없이 배포하면, 이 종목
특유의 정상적인 표기를 오류로 잘못 판정할 수 있다.

# 검증 방법론 (공통)

5개 종목 전체에 적용하는 검증 절차입니다. 종목별 세부 확인 항목은 각 폴더의
`44_테스트계획.md`, `46_체크리스트.md`를 보십시오.

## 3단계 검증

1. **요구사항 검증** — Q-Net 공개문제 3개 회차를 대조해 도면 크기·투상법·척도·
   오작 조건이 일관되는지 확인한다. 회차마다 다르면 가장 보수적인 값을 채택한다.
2. **로직 검증** — `test_rules.py` 패턴으로 종목별 신규 검사(재질 사전 확장 등)에
   단위 테스트를 추가한다. 기존 기능사 테스트가 깨지지 않는지 회귀 확인한다.
3. **실물 검증** — 실제 합격/불합격 도면을 확보해 검사 결과가 실제 판정과
   일치하는지 확인한다. 이 단계 없이는 배포하지 않는다.

## 왜 이 순서인가

요구사항이 틀리면 로직도 실물 검증도 의미가 없습니다. 로직이 틀리면 실물 검증에서
반드시 드러나야 합니다. 순서를 건너뛰고 실물 검증부터 하면, 우연히 맞은 것인지
로직이 맞아서 맞은 것인지 구분할 수 없습니다.

## 실패 시 처리

검증 3단계 중 하나라도 통과하지 못하면 해당 종목은 도입을 보류합니다.
"일단 배포하고 나중에 고친다"는 채택하지 않습니다 — 틀린 지적은 검사기가
없는 것보다 나쁩니다([`99_도입_로드맵.md`](99_도입_로드맵.md) 중단 조건 참조).

# 도입 로드맵

검토 결과를 실제 작업 순서로 옮긴 문서입니다.
판단 근거는 [`00_종합비교표.md`](00_종합비교표.md)에 있습니다.

## 전제

이 로드맵은 **요구사항이 확정된 뒤에만** 유효합니다.
Q-Net 공개문제를 확보하지 못한 종목은 코드를 건드리지 않습니다.
확인되지 않은 기준으로 검사 규칙을 만들면, 응시자에게 틀린 지적을 하게 됩니다.

## 0단계 — 구조 정리 (종목 무관, 선행)

현재 `exam.py`는 전산응용기계제도기능사 기준값을 모듈 상수로 박아 두고 있습니다.

```python
REQUIRED_SHEET = ("A3", 420.0, 297.0)
REQUIRED_THIRD_ANGLE = True
MIN_SURFACE_SYMBOLS = 3
MIN_FCF = 1
```

종목이 하나일 때는 문제없지만, 두 번째 종목이 들어오는 순간 막힙니다.

**할 일**

- [ ] 위 상수들을 종목별 딕셔너리(`SPECS`)로 분리
- [ ] `run()` 계열 함수가 종목 키를 인자로 받도록 수정
- [ ] 기존 기능사 동작이 그대로인지 `test_rules.py`로 확인
- [ ] 루브릭 배점도 종목별로 분리

**하지 말 것**

검사 함수 안에 `if 종목 == ...` 분기를 넣지 않습니다. 종목이 5개가 되면
분기가 규칙마다 퍼져서 손댈 수 없게 됩니다. **값만 분리하고 로직은 공유합니다.**

이 작업이 끝나면 이후 종목 추가는 대부분 "값 채우기"가 됩니다.

## 1단계 — 기계설계산업기사

재사용률이 가장 높고, 치공구설계산업기사 통합으로 대상자도 가장 많습니다.

- [ ] 공개문제 3개 회차 확보
- [ ] 도면 크기·투상법·척도 확정 → `SPECS`에 입력
- [ ] 투상도 최소 개수, 기호 최소 개수 기준 조정
- [ ] 표제란 필수 항목 목록 재작성
- [ ] 실제 도면으로 검사 결과 검증
- [ ] 점수 없이 "항목 충족 여부"만 출력하는 모드로 공개

3D 모델 채점은 이 단계에서 하지 않습니다. `inventor.py` 연계는 2D가 안정된 뒤입니다.

## 2단계 — 일반기계기사 (작업형 한정)

개발 부담이 거의 없습니다. 1단계 결과물에 설정만 추가하면 됩니다.

- [ ] 작업형 요구사항 확정 → `SPECS`에 입력
- [ ] **"실기 작업형만 검사합니다. 필답형은 대상이 아닙니다."** 안내 문구 추가
- [ ] 검증 후 공개

안내 문구를 빼면 사용자가 실기 전체를 검사받은 것으로 오해합니다.
이 종목에서는 문구가 기능의 일부입니다.

## 3단계 — 사출금형산업기사

공통 규칙만으로 먼저 엽니다.

- [ ] 공개문제 확보, 요구사항 확정
- [ ] 금형강 재질명 사전을 `rules.py`에 추가
- [ ] 부품란·풍선번호 일치 검사 추가
- [ ] 공통 규칙만으로 공개 (금형 전용 검사 없이)

이후 별도 과제로:

- [ ] 빼기구배 표기 검사
- [ ] 파팅라인 표시 검사
- [ ] 냉각회로 간섭 검사

이 셋은 도면 지오메트리만으로 판정하기 어렵습니다. 착수 전에 판정 가능한지부터
확인합니다. 판정이 불가능하면 만들지 않습니다.

## 4단계 — 프레스금형산업기사

구조 변경이 필요해 마지막입니다.

- [ ] 공개문제 확보, 요구사항 확정
- [ ] 공구강 재질명 사전 추가
- [ ] 공통 규칙만으로 공개
- [ ] 다이-펀치 클리어런스 검사 — **여러 부품도를 함께 읽는 구조**가 선행 필요
- [ ] 스트립 레이아웃 검사 — 판정 가능성 조사부터

현재 `rules.py`는 파일 하나를 독립적으로 검사합니다. 클리어런스는 다이와 펀치의
치수를 서로 비교해야 하므로, 검사 단위가 "파일"에서 "제출물 묶음"으로 바뀝니다.
작지 않은 변경이라 앞 단계가 안정된 뒤에 착수합니다.

## 하지 않기로 한 것

| 항목 | 사유 |
|---|---|
| 치공구설계산업기사 별도 지원 | 2022년 기계설계산업기사로 통합됨 |
| 필답형 채점 | 도면 파일이 없어 검사 불가 |
| 점수 표시 (초기) | 공식 배점 비공개, 근거 없는 점수는 오해를 만듦 |
| 미확인 조건의 오작 판정 | 멀쩡한 도면을 고치게 만듦 |

## 중단 조건

아래에 해당하면 그 종목은 도입하지 않습니다.

- 공개문제를 확보할 수 없다
- 오작 조건을 공개문제 원문에서 확인할 수 없다
- 검증용 실제 도면을 구할 수 없다

"일단 붙여 놓고 나중에 고친다"는 하지 않습니다. 검사기가 틀린 지적을 하면
사용자는 맞는 도면을 틀리게 고칩니다. 검사기가 없는 것보다 나쁩니다.

사용자에게 틀린 지적을 하게 됩니다.

## 구조 변경 제안

종목이 늘어나므로 `exam.py`의 종목 종속 상수를 분리하는 편이 낫습니다.

```python
# exam.py — 현재
REQUIRED_SHEET = ("A3", 420.0, 297.0)
MIN_SURFACE_SYMBOLS = 3

# 제안
SPECS = {
    "craftsman_cad": dict(sheet=("A3", 420.0, 297.0), min_surface=3, min_fcf=1),
    "프레스금형산업기사": dict(sheet=(...), min_surface=..., min_fcf=...),
}
```

검사 함수는 그대로 두고 상수만 딕셔너리로 뺍니다. 종목 추가가 값 추가로 끝납니다.
로직 분기를 종목별로 만들면 유지보수가 불가능해지므로 피합니다.

## 각 신규 개발 항목의 착수 조건

위 항목들은 착수 순서가 있습니다. 요구사항이 확정되지 않은 항목부터 손대면
헛일이 될 수 있으므로, 각 항목 앞에 "이걸 먼저 확인해야 시작할 수 있다"는
조건을 명시적으로 답니다.

| 항목 | 착수 전 확인 사항 |
|---|---|
| 스트립 레이아웃 검사 | 요구사항 확정 여부, 관련 테스트 존재 여부 |
| 클리어런스 검사 | 요구사항 확정 여부, 관련 테스트 존재 여부 |
| 공구강 재질 사전 | 요구사항 확정 여부, 관련 테스트 존재 여부 |

## 신규 개발 규모를 과소평가하지 않는 법

"소"로 분류된 항목도 실제로는 회귀 테스트 작성, 기존 기능사 동작 보존 확인,
문서 갱신까지 포함하면 순수 코드 변경량보다 시간이 더 걸립니다. 이 문서의
작업량 분류(소/중/대)는 코드 diff 크기 기준이며, 검증·테스트 시간은 별도로
`44_테스트계획.md`에서 다룹니다.

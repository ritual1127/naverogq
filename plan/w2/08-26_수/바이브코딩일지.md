# 08-26 바이브 코딩 일지

> 오늘 AI에게 무엇을 시켰고, 무엇이 나왔고, 무엇을 내가 판단했는지 남긴다.
> 코드는 git에 남지만 **왜 그렇게 시켰는지는 여기 아니면 안 남는다.**

오늘 계획은 인터뷰 두 건이었다. 셋 다 사람만 할 수 있는 일이라 시킬 것이 없었고,
실제로 대신 하지 않았다. 21:00까지 저장소에 들어온 기록이 없어 셋 다 `⬜`로 뒀다.
그런데 **준비물을 확인하다가 하루가 통째로 다른 방향으로 갔다.**

## 1부 — 폴더가 있는 것과 쓸 수 있는 것은 다르다

어제 만들어 둔 [`실제도면/`](../../../실제도면/README.md)이 오늘 준비물이다. 있는지만 보고
넘어갈 수도 있었는데 **실제로 한 번 돌려 보게 시켰다.** 아직 비어 있는 `labels.json`으로
측정을 돌린 것뿐이다.

```
$ python bench.py 실제도면/labels.json
- 기준 도면 0장 중 완전 일치 0장
- 검출률(recall) 100.0% — 실제 결함 0건 중 0건 검출
- 정확도(precision) 100.0% — 지적 0건 중 0건이 실제 결함
```

**도면이 한 장도 없는데 100%가 나왔고 종료 코드가 0이었다.** `--check`도 통과한다.

원인은 두 줄이었다.

```python
recall = tp / (tp + fn) if tp + fn else 1.0
precision = tp / (tp + fp) if tp + fp else 1.0
```

0으로 나누는 것을 막으려고 분모가 0이면 1.0을 넣어 둔 것이다. 합성 도면 18장만 쓰는 동안에는
분모가 0이 될 일이 없어서 몇 주 동안 안 보였다. 내일부터 실제 도면을 받기 시작하면
**"아직 아무것도 없다"와 "다 맞혔다"가 같은 숫자로 나온다.** 발표에서 제일 나쁜 종류의 숫자다.

여기서 판단한 것은 **어디까지 고칠지**였다. 0장이면 리포트를 아예 안 찍고 종료 코드 1,
못 연 도면이 있으면 `--check` 없이도 종료 코드 1, 요약에 분석 실패 장수를 적는다.
계산식 자체(분모 0이면 1.0)는 그대로 뒀다. 호출하는 쪽에서 0장을 막았으니 그 기본값이 밖으로
나올 일이 없어졌다. [P09](../../문제점/P09-빈측정100.md)로 남겼다.

**기본값이 거짓말이 될 수 있다.** 0으로 나누기를 막는 값은 "계산할 수 없음"이지 "완벽함"이
아닌데, 코드에서는 둘이 같은 `1.0`이다.

## 2부 — 인터뷰를 웹으로도 받기로 했다

계획에 없던 것이다. 이유는 하나다. **약속이 안 잡히면 한 주가 그냥 간다.** 어제 대상표에
세 명까지 찼고 두 명과 약속 시간이 아직 비어 있다. 못 만나는 사람에게 보낼 자리를 만들었다.
[`인터뷰폼/`](../../../인터뷰폼/README.md) — https://cadlens-interview.pages.dev

**요구가 다섯 번 바뀌었고 그때마다 다시 시켰다.** 그 과정이 오늘 기록할 값어치가 있다.

1. **처음엔 대면 질문지를 그대로 웹에 옮겼다.** 서술형 다섯 개. 만들고 보니 별로였다.
   대면에서는 3초 침묵과 꼬리 질문으로 캐낼 수 있지만, 글로는 "그냥 확인해요" 한 줄이 끝이다.
2. **객관식 80%로 바꿨다.** 적기 귀찮으면 아무도 안 채운다. 지금은 고르는 질문 26개 +
   적는 칸 4개다.
3. **드롭다운을 전부 없앴다.** 어떤 건 `<select>`, 어떤 건 알약 모양 버튼이라 통일감이 없었다.
   구글폼처럼 동그라미·네모 한 줄짜리로 통일했다.
4. **고르는 칸을 전부 필수로 만들었다.** 여기서 한 번 막혔다 — 필수로만 만들면 해당 없는
   사람이 아무거나 고른다. `빠뜨린 적 없음` · `잘 모르겠어` · `딱히 없어`를 넣고 나서야
   필수를 걸었다. **없는 것을 있다고 고르게 하면 그 답은 쓸모가 없다.**
5. **링크 미리보기를 만들었다.** 카톡에 붙였을 때 주소만 뜨면 아무도 안 누른다.
   1200×630 그림을 그려 넣었다.

선택지는 지어내지 않았다. **실기 오작·미완성 기준**(도면 크기·각법·척도 불일치, 끼워맞춤공차·
기하공차·표면거칠기 기호 전체 누락, 조립 상태 제도 / 출력 10분 초과, 투상도 누락)과
`exam.py`의 검사 24개에서 뽑았다. 돈이나 시간을 써 봤는지 묻는 질문은 강의가 반드시 넣으라고
한 것이라 문장을 바꾸지 않았다.

### 통계는 KV로 시작했다가 D1로 갈아엎었다

처음엔 KV에 답 하나씩 넣고 통계 화면에서 전부 읽어 세는 방식이었다. 1000명이 답해도 견디게
하라는 요구가 붙으면서 그 구조로는 안 된다는 게 분명해졌다. **1000건이면 1000번 읽어야 한다.**

D1로 옮기면서 구조를 바꿨다. 답 하나가 `answers` 한 줄이고, **고른 것은 `picks` 로 펼쳐서**
넣는다. 통계는 답이 몇 건이든 `GROUP BY` 한 번이다.

**말로만 "견딘다"고 적지 않으려고 실제로 넣고 쟀다.** 답 1000건, `picks` 31,840줄,
`notes` 4,000줄.

| | |
|---|---|
| 통계 화면 | 207~739ms · 98KB |
| 복사용 글 | 133ms · 12KB |
| 마지막 쪽 | `981–1000 / 1000` 정상 |

재고 나서 전부 지웠다. 숫자를 남기려고 데이터를 남겨 두면 진짜 답이 들어왔을 때 섞인다.

## 3부 — 검수가 내가 고친 데서 거짓말을 찾았다

다 만들고 검수를 돌렸다. 9건이 나왔고 8건을 고쳤다. 그중 하나가 제일 뼈아프다.

**1부에서 P09를 고치면서 요약에 이렇게 적었다** — "분석 실패 n장 — 아래 숫자는 이 장들을
뺀 것이다". 그런데 코드는 빼지 않고 있었다. 못 연 도면은 검출 결과가 빈 집합이라 기대 코드가
전부 "놓침"으로 잡힌다. 10장 중 한 장의 파일 이름을 틀리면 나머지 9장을 완벽하게 맞혀도
검출률이 90%대로 떨어진다. **거짓말을 고치다가 새 거짓말을 한 줄 적은 것이다.**

문서에도 그대로 번져 있었다. P09의 조치 항목이 같은 문장으로 적혀 있었다. 코드와 기록이
동시에 틀렸으니, 검수가 없었으면 이건 안 보였을 것이다. 못 연 장을 계산에서 빼고, 분석된 장이
0이면 퍼센트를 아예 찍지 않게 고쳤다. P09 문서에는 지우지 않고 **처음에 무엇을 잘못 적었는지를
기록 절에 남겼다.**

나머지 중 기억할 것 둘.

- **열쇠 없이 부르는 POST는 남이 숫자를 만들 수 있다.** 같은 값을 60번 담아 보내면 표에
  "60명 6000%"가 찍혔다. 중복을 없앴다. 직접 60번 담아 쏴 보고 `1명 100%`를 확인했다.
- **"해당 없음"과 다른 항목을 같이 고를 수 있었다.** `아무것도 안 씀`과 `인강 삼`을 같이
  고르면 강한 신호에 들어간다. 강한 신호는 **문제를 다시 고를지 정하는 숫자**라 어긋나면 안 된다.
  해당 없음을 고르면 나머지를 버리게 했다.

**한 건은 안 고쳤다.** 공개 POST에 선택지 허용 목록이 없다. 목록이 지금 폼 HTML에만 있어서
서버에도 두면 두 곳이 갈라진다. 안 고친 이유를 커밋 메시지에 적었다. 고쳤다고 적는 것보다
안 고쳤다고 적는 게 낫다.

## 오늘 배운 것 세 줄

1. **준비물은 있는지가 아니라 쓸 수 있는지를 본다.** 폴더는 어제 만들어 뒀지만, 한 번 돌려
   보고서야 0장에 100%가 나오는 걸 알았다.
2. **기본값이 거짓말이 될 수 있다.** 0으로 나누기를 막는 1.0은 "잴 수 없음"인데 화면에는
   "완벽함"으로 나온다.
3. **고친 것도 검수한다.** 오늘 제일 큰 지적은 내가 오늘 고친 코드에서 나왔다. 고치는 순간이
   가장 자신 있고, 가장 안 보인다.

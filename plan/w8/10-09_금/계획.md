## 할 일

### 1. 서버 깨우기를 믿을 수 있게 — **박지완**  ·  예상 1시간

- GitHub 예약 실행(`keepalive.yml`, 5분마다)이 실제로는 **하루 2 ~ 6번** 돌았다. 무료 서버는 15분 동안 요청이 없으면
  잠들고, 잠들면 첫 사람이 깨어나기를 기다린다([P31](../../문제점/P31-서버깨우기.md)). 실제로 얼마나 자주 잠드는지는 모른다 —
  **고치기 전에** Render 대시보드 Logs 에서 서버가 새로 켜진 기록이 어제 하루 몇 번인지 세어 메모에 적는다(고친 뒤와 견준다).
- **이미 쓰는 Cloudflare 계정**(D1 · Workers AI)의 Workers **Cron Trigger** 로 5분마다
  `https://naverogq.onrender.com/api/health` 를 부른다. 시간대는 지금과 같게 — 한국 시간 0 ~ 3시는 쉰다
  (`*/5 0-14,18-23 * * *`, UTC).
- `fetch` 한 번 하는 Worker 하나다. 저장소에 `keepalive/` 로 두고 배포 명령을 README 에 한 줄.
- GitHub 예약 실행은 지우지 않는다 — 드물게 돌아도, 실패하면 메일이 오는 감시로 남긴다.
- "5분마다 깨운다"고 적힌 문서를 실제대로 고친다 — [`docs/화면_기능명세.md`](../../../docs/화면_기능명세.md) ·
  [W8 KPI 리포트](../W8_KPI리포트.md) ⑤.

**이렇게 되면 끝** — Cloudflare 대시보드의 Cron 실행 기록이 5분 간격으로 찍힌다. P31 에 조치를 적는다

**흔한 실수** — 깨우는 주소를 첫 화면(`/`)으로 하는 것. 첫 화면은 방문으로 세인다(`main.py` 의 `index`). `/api/health` 는 안 센다

### 2. 다시 들어온 사람에게 첫 화면에서 지난 검사를 — **박지완**  ·  예상 2 ~ 3시간

- [점검표 고칠 차례 ①](../../../docs/workshop_check.md#고칠-차례) · W6 FIX 04 "다시 올 이유 — 저장된 기록 · 이어하기".
- 브라우저는 이미 최근 20건을 기억한다(`cadcheck.history` — 파일 이름 · 점수 · 실격 여부 · 시각). 같은 도면을 다시 올리면
  지난 결과와 비교해 준다. **그런데 다시 들어왔을 때 첫 화면에는 그 기록이 안 보인다.**
- 올리기 상자 바로 아래에 최근 3건 — 파일 이름 · 점수 · 언제 — 과 "고쳐서 다시 올리면 지난번과 비교해 드려요" 한 줄.
  네 언어.
- **서버와 저장 항목은 그대로다.** 이미 브라우저에 있는 것을 보여 주기만 한다 — 개인정보 방침을 바꿀 일이 없다.
- 기록이 없으면(처음 온 사람) 아무것도 안 보인다.
- **공용 PC 를 생각한다.** 실습실 컴퓨터는 여러 학생이 같이 쓴다 — 목록 옆에 `이 기기에서 지우기`.

**이렇게 되면 끝** — 로컬 서버에서 예제를 한 번 검사하고 새로고침하면 첫 화면에 그 검사가 보이고, 시크릿 창에서는
아무것도 안 보이고, `지우기`를 누르면 사라진다. 휴대폰 폭 · 어두운 화면에서도.
`python -m pytest -q test_rules.py test_events.py test_prune.py` 통과

**흔한 실수** — 실습실 PC 에서 다음 학생에게 앞 학생의 파일 이름이 보인다는 것을 잊는 것

### 3. 15장 목표 셋 정하기 — **전원**  ·  예상 20분

- 10분판 15장 "본선 목표"는 발표에서 하는 **약속**이다. 본선에서 다시 묻는다
  ([W8 준비](../W8_준비.md#10분-발표--2차-제출-영상--본선-10-06) "녹화 전에 할 것").
- 지금 초안 — "실기 준비반에 직접" · "학생 3명 이상 · 완성 도면 30장" · "Inventor 치수 문제(P28) 본선 전에".
- 네 명이 지킬 수 있는지 보고 정한다. 바꾸면 `presenter/talk10.js` 15장의 카드와 대사 둘 다(박지완).

**이렇게 되면 끝** — 네 명이 단톡에서 "이 셋"이라고 했다

**흔한 실수** — 녹화를 다 하고 나서 목표를 바꾸는 것. 다시 찍어야 한다

### 4. 10분 발표 영상 녹화 — **안대열** (읽는 사람 넷)  ·  예상 2 ~ 3시간

- 2차 제출물 ③. [W8 준비](../W8_준비.md#10분-발표--2차-제출-영상--본선-10-06)의 "녹화 전에 할 것"을 먼저 한다 —
  12장 맨 오른쪽 막대를 녹화 직전 `/api/stats` `weeks` 맨 위 `recheckers` 로 다시 보기 · 10-08 실측으로 10분 이내인지.
- 4장 영상은 목소리가 든다 — 녹화 프로그램이 **탭 소리**를 잡는지 10초만 먼저 찍어 들어 본다.
  5 ~ 7장 영상은 소리가 없다 — 박지완이 영상 위에 그 장 대사를 말한다.
- 한 번에 안 되면 구간별(문제 · 데모 · 숫자 · 배운 것 · 다음)로 찍어 붙인다.

**이렇게 되면 끝** — 10분 이내 영상 파일이 있고, 처음부터 끝까지 소리가 들린다

**흔한 실수** — 소리를 확인 안 하는 것. 화면보다 소리가 치명적이다 — 데모데이 ② 에서는 마이크가 안 돼 순서가
밀렸다([P29](../../문제점/P29-데모데이마이크.md))

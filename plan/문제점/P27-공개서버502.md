## 증상

2026-10-03 에 W8 KPI 리포트용 숫자를 읽으려고 바깥(팀 컴퓨터가 아닌 곳)에서 공개 서버를 불렀다.

| 순서 | 요청 | 결과 |
|---|---|---|
| 1 | `GET /api/stats` | 200 — 지표 JSON 이 정상으로 왔다 |
| 2 | `GET /api/health` (1과 동시에) | 60초 안에 응답 없음 |
| 3 | `GET /api/health` | **502 Bad Gateway** |
| 4 | `GET /` | **502 Bad Gateway** |

같은 날 23:32 에 Render 가 메일을 보냈다 — *"Web Service naverogq exceeded its memory limit,
which triggered an automatic restart. While restarting, the instance was temporarily unavailable."*
무료 플랜의 메모리는 512MB 다.

## 원인

**검사가 동시에 몇 개 돌든 막는 것이 없었다.** 속도 제한(한 사람 10분에 40번)은 있었지만
동시에 도는 수에는 상한이 없었다. 검사 하나는 도면 기록 · 미리보기 · AI 에게 보낼 그림 · 수정 예시
래스터를 잠깐 들고 있고, 여럿이 겹치면 그만큼 쌓인다. 끝난 뒤에도 프로세스가 메모리를 다 돌려주지
않아 겹칠 때마다 계단처럼 올라갔다.

배포 서버와 같은 조건(리눅스 · Python 3.13 · DejaVu+나눔 글꼴 · LibreDWG 0.14)을 WSL 에 꾸려
실서버(`uvicorn`)를 띄우고 서버 프로세스의 RSS 를 0.1초마다 쟀다. AI 는 켠 채로 두고 네트워크만
가짜로 바꿨다(클라이언트 생성 · 그림 · 뒤에서 도는 답변/번역은 실제와 같다).

| 단계 | 정점 | 끝난 뒤 |
|---|---|---|
| 서버가 뜸 | 170 MB | 170 MB |
| 워밍업 (예제 3장) | 215 MB | 215 MB |
| 학생 도면 1장 | 245 MB | 244 MB |
| 동시에 3장 | 275 MB | 266 MB |
| 동시에 6장 | 393 MB | 342 MB |
| 동시에 6장 한 번 더 | **491 MB** | 371 MB |

혼자 도는 검사 하나는 한도 안이다. **겹칠 때 넘는다.** 데이터 크기 문제가 아니다 — 결과 응답은
0.2~0.4MB, 예제 결과 캐시는 많아야 16개다.

원인이 아닌 것으로 확인한 것

- **DWG 변환** — 워밍업이 예제 DWG 를 LibreDWG 로 바꾸는데, `dwg2dxf` 정점이 12.7MB · 0.03초였다.
- **글꼴** — 윈도우 PC 에서는 도면 글꼴(Gulim · tahoma)이 없으면 ezdxf 가 22MB 짜리 Arial Unicode 로
  대신 그려 검사 하나가 390MB 까지 갔다. 배포 서버(리눅스)에서는 DejaVuSans(0.7MB)로 대신 그려 해당이 없다.

## 조치

`main._result` 에 순번을 걸었다(`CHECK_SLOT`). 업로드 · 예제 · 워밍업이 모두 이 함수를 지나므로
한 곳에서 막힌다. 검사는 한 번에 하나만 돌고, 다른 검사는 기다린다. 60초를 기다려도 차례가 안
오면 503 과 함께 "잠시 뒤에 다시 올려 주세요"를 돌려준다(기다리는 요청이 스레드를 다 차지해
`/api/health` 까지 막히지 않게). 예제 결과가 캐시에 있으면 순번을 거치지 않고 바로 나간다.
CPU 가 0.1 이라 동시에 돌려도 빨라지지 않았으므로 한 명이 쓸 때 느려지는 것은 없다.

## 확인

```
python -m pytest -q   → 83 passed
```

`test_events.py::test_checks_run_one_at_a_time` — 검사 셋을 동시에 넣으면 고치기 전에는 3개가 겹쳤고
(`assert 3 == 1`), 고친 뒤에는 1개다.

같은 재현을 고친 코드로 다시 돌렸다.

| 단계 | 고치기 전 정점 | 고친 뒤 정점 | 고친 뒤 끝난 뒤 |
|---|---|---|---|
| 동시에 6장 | 393 MB | 310 MB | 271 MB |
| 동시에 6장 한 번 더 | **491 MB** | **313 MB** | 269 MB |

한도 512MB 에 약 200MB 가 남는다. 두 번째 몰림에서 더 오르지 않는다.

**남은 것** — 배포 서버에서 무엇이 겹쳤는지는 모른다. 그날 사람이 한 검사는 0건이었으므로
공개 지표에서 빼는 프로그램 요청일 수 있는데, 원자료 조회(wrangler)가 인증 만료로 막혀 확인하지
못했다. 배포 뒤 며칠 동안 Render 메모리 초과 메일이 다시 오는지 보고, 오지 않으면 해결로 닫는다.

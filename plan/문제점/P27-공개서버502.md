| | |
|---|---|
| 상태 | 🔴 **열림** — 한 번 관측했고 원인은 모른다 |

| 무엇에 영향을 주나 | 2차 제출물 ① 프로덕트 URL — 심사위원이 직접 접속한다 · 발표 영상 촬영 |
| 맡은 사람 | 박지완 |

## 증상

2026-10-03 에 W8 KPI 리포트용 숫자를 읽으려고 바깥(팀 컴퓨터가 아닌 곳)에서 공개 서버를 불렀다.

| 순서 | 요청 | 결과 |
|---|---|---|
| 1 | `GET /api/stats` | 200 — 지표 JSON 이 정상으로 왔다 |
| 2 | `GET /api/health` (1과 동시에) | 60초 안에 응답 없음 |
| 3 | `GET /api/health` | **502 Bad Gateway** |
| 4 | `GET /` | **502 Bad Gateway** |

그 뒤로는 다시 불러 보지 못했다. 몇 분 동안 이어졌는지, 저절로 돌아왔는지 모른다.

## 원인

**모른다.** 추측은 여기 적지 않는다. 볼 곳만 적는다.

- Render 대시보드 → 이 서비스의 **Events**(재시작 · 배포 · 실패 기록)와 **Logs** — 2026-10-03 그 시각 전후
- GitHub Actions → **Keep Render service awake** 실행 기록. 5분마다 `curl --fail` 로 `/api/health` 를 부르므로,
  502 가 이어졌다면 그 시각 실행이 실패로 남는다([`keepalive.yml`](../../.github/workflows/keepalive.yml))

## 조치

없음 — 원인을 본 뒤 정한다.

## 확인 (할 것)

- 위 두 곳에서 그 시각 기록을 본다
- 시크릿 창과 팀원이 아닌 사람의 휴대폰(다른 통신망)에서 `/` 를 열고 예제 검사를 끝까지 해 본다
- 발표 영상 촬영 직전에도 같은 확인을 한다

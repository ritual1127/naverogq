## 증상

08-26 준비물 점검으로 어제 만든 `실제도면/` 폴더가 실제로 쓸 수 있는지 보려고
아직 비어 있는 라벨 파일로 측정을 돌렸다.

```
$ python bench.py 실제도면/labels.json
| 시험 도면 | 잡아야 할 지적 | 결과 |
|---|---|---|

- 기준 도면 0장 중 완전 일치 0장
- 검출률(recall) 100.0% — 실제 결함 0건 중 0건 검출
- 정확도(precision) 100.0% — 지적 0건 중 0건이 실제 결함
```

**도면이 한 장도 없는데 100% / 100% 가 나오고 종료 코드도 0이었다.**
`--check` 를 붙여도 통과한다.

라벨에 이름만 적고 도면 파일이 없을 때도 마찬가지였다. 그 장은 표에
`분석 실패` 로 찍히지만 요약 숫자는 그 장을 조용히 빼고 계산하고, 역시 0으로 끝난다.

## 원인

`run()` 의 마지막 두 줄이다.

```python
recall = tp / (tp + fn) if tp + fn else 1.0
precision = tp / (tp + fp) if tp + fp else 1.0
```

0으로 나누는 것을 막으려고 분모가 0이면 1.0 을 넣었다. 합성 도면 18장으로만 돌리던
동안에는 분모가 0이 될 일이 없어서 드러나지 않았다. 실제 도면을 받기 시작하면
**"아직 아무것도 없다"와 "다 맞혔다"가 같은 숫자로 나온다.**

## 조치

`bench.py` 세 군데.

1. 라벨에 도면이 한 장도 없으면 리포트를 찍지 않고 종료 코드 1로 끝낸다.
   0장으로는 잴 수 있는 것이 없다.
2. 요약에 **분석 실패 장수**를 한 줄로 적고, 못 연 장은 검출률·정확도 계산에서 **실제로 뺀다**.
   (처음에는 "뺀 것이다"라고 적어 놓고 빼지 않아 파일 이름을 틀린 것이 검출률이 낮은 것처럼
   보였다. 08-26 검수에서 찾아 고쳤다.) 분석된 도면이 0장이면 퍼센트를 아예 찍지 않는다.
3. 열지 못한 도면이 한 장이라도 있으면 `--check` 없이도 종료 코드 1로 끝낸다.
   파일 이름이 틀렸거나 파일이 없는 상태에서 나온 정확도는 쓰면 안 된다.

## 확인

| 무엇 | 결과 |
|---|---|
| `python bench.py 실제도면/labels.json` (0장) | `FAIL: … 도면이 한 장도 없다` · 종료 코드 1 |
| 없는 파일 이름 한 장짜리 라벨 | 표에 `분석 실패`, 요약에 `기준 도면 1장 중 분석 0장` · `분석 실패 1장` · `분석된 도면이 0장이라 검출률·정확도를 잴 수 없다`, 종료 코드 1 |
| `python bench.py --check` (합성 18장) | 18장 중 분석 18장 · 완전 일치 18장 · 100% / 100% · 종료 코드 0 (그대로) |
| `python -m pytest test_rules.py -q` | 17개 통과 |

내일(08-27) 김승준이 받은 도면에 라벨을 붙이고 이 명령을 돌린다. 파일 이름을
잘못 적으면 이제 100% 대신 실패가 뜬다.

## 기록

- 2026-08-26 — 0장 100% 를 막고 분석 실패 표시를 넣었다.
- 2026-08-26 (검수) — 실패한 장을 **뺀다고 적어 놓고 빼지 않던 것**을 찾았다. 10장 중 한 장의
  파일 이름을 틀리면 그 장의 기대 코드가 전부 놓침으로 잡혀 검출률이 90%대로 떨어졌다.
  못 연 장을 tp·fn·fp 와 완전 일치에서 빼고, 분석된 장이 0이면 퍼센트를 찍지 않게 했다.
  합성 18장은 18/18 · 100%/100% · 종료 0 그대로, 테스트 17개 통과.

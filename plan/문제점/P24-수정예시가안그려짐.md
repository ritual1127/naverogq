## 증상

"중심선이랑 빠진 치수는 왜 안 그려 주냐"는 말을 듣고 실제 도면 6장으로 재 봤다.
**중심선 예시가 한 장도 안 그려졌다.**

| 도면 | 원 | 중심선 엔티티 | 그려 준 중심선 | 그려 준 치수 |
|---|---|---|---|---|
| 1본체.dxf | 83 | 32 | **0** | 2 |
| 3축.dxf | 21 | 14 | **0** | 0 |
| A01.dxf | 61 | 24 | **0** | 0 |
| A02.dxf | 35 | 13 | **0** | 0 |
| A03.dxf | 50 | 18 | **0** | 0 |
| A05.dxf | 42 | 21 | **0** | 0 |

## 원인

**중심선을 도면 단위로만 봤다.** 판정이 이랬다.

```python
def lacks_center_lines(sheet):
    counts = sheet.get("counts") or {}
    return not counts.get("Centerlines", 0) and not counts.get("Centermarks", 0)
```

중심선이 **하나라도** 있으면 "있는 도면"이다. 그래서

1. `EX_NO_CENTERLINE` 지적이 안 뜨고,
2. `main._fix_plan` 이 이 값으로 중심선 예시를 만들지 말지 정하므로 계산 자체를 안 하고,
3. 계산했어도 `main._fix_layer` 가 지적 코드로 한 번 더 막는다.

실제 도면은 큰 원에는 중심선을 긋고 **작은 구멍에서 빠뜨리는** 쪽이 훨씬 흔하다.
위 6장은 전부 중심선이 13~32개 있었으므로 전부 "있는 도면"으로 통과했다.
1본체.dxf 를 원 단위로 다시 세어 보니 **구멍 9개 중 5개에 중심선이 없었다.**

치수 쪽은 사정이 다르다. 6장 중 5장이 `미치수군 0` 인데, 이건 규칙이 맞다 —
같은 지름은 한 번만 적으면 되고(KS B 0001), 나사 구멍은 호칭으로 적으므로 지름 치수를
안 적는 게 정상이다. **실제로 빠진 경우에는 그린다**(1본체.dxf 에서 5개 구멍에 2개 지시선).

## 고친 것

**중심선을 원마다 본다.** `dwg.py` 가 중심선 엔티티의 좌표(`center_segs`)를 모아 두고,
구멍 원마다 중심을 지나는 중심선이 있는지(`_has_center_line`) 표시한다. 판정은
"선이 원 중심에서 반지름의 22% 안으로 지나가나"이고, 애매하면 **있다고 본다** —
이미 그어 둔 원 위에 초록색을 덧그리는 쪽이 사용자에게 더 나쁘다.

| | 전 | 후 |
|---|---|---|
| 판정 단위 | 도면 한 장 | **원 하나하나** |
| 지적 문구 | "중심선·중심마크 없음" | "구멍 5곳에 중심선 없음" |
| 그리는 대상 | 중심선이 0개인 도면의 모든 원 | **중심선이 없는 원만** |
| 화면 설명 | — | "이미 중심선이 있는 원 4개에는 그리지 않았어요" |

고치는 중에 **오탐이 하나 나왔다.** 문자 없는 거칠기 기호(∇)에 붙은 작은 원이 구멍으로
세어져 "중심선 없음"이 떴다. 기호에 붙은 원을 거르는 `_is_inscribed` 가 치수 검사에만
걸려 있고 중심선 쪽에는 없었다. 같은 필터를 중심선 쪽에도 걸었다.

## 남은 것

- **원이 아닌 형상의 중심선**(대칭인 사각 형상의 중심선)은 아직 안 그린다.
- **길이·폭 치수**는 여전히 안 그린다. 어디를 기준으로 재는지가 설계 판단이라,
  숫자를 지어내느니 안 그리는 쪽을 골랐다. 지름 치수는 원에서 바로 읽히므로 그린다.

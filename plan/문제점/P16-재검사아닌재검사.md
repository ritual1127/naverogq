## 증상

오늘 계측 이벤트를 붙이려고 `stats.py` 를 열어 보니 [P07](P07-지표0.md) 에서
이미 붙여 둔 `recheckers` 가 이렇게 세어지고 있었다.

```sql
SELECT COUNT(*) FROM (SELECT visitor, SUM(n) s FROM hits
  WHERE day>=? AND kind IN ('check','sample') GROUP BY visitor HAVING s >= 2)
```

**한 주에 검사를 두 번 한 사람**이다. 재검사가 아니다. 예제 도면을 두 번 눌러도,
서로 다른 도면 두 장을 올려도, 같은 IP 를 쓰는 학교 컴퓨터에서 두 사람이 한 번씩
올려도 이 숫자가 올라간다. 화면에는 "고쳐서 다시 올렸다는 뜻이라 저희가 제일
중요하게 보는 숫자"라고 적혀 있었다. **공개된 숫자가 설명과 다른 것을 세고 있었다.**

## 원인

08-30 에 계측을 붙일 때 서버가 알 수 있는 것만으로 재검사를 흉내 냈다.
같은 파일을 고쳐서 다시 올렸는지는 **파일 이름을 저장해야** 알 수 있는데,
[공개 고지](../../docs/policy.md)에서 파일 이름을 안 남기기로 했으므로
서버 쪽 데이터만으로는 판별할 방법이 없다. 그래서 '2회 이상'으로 대신했고
그 사실이 어디에도 안 적혀 있었다.

## 조치

판별을 **브라우저 쪽으로 옮겼다.** 화면에는 이미 `cadcheck.history` 로
같은 파일 이름의 지난 결과를 들고 있다가 '재검사 비교' 상자를 띄우는 기능이 있다.
그 상자가 실제로 떴을 때만 `POST /api/event {"kind":"recheck"}` 를 보낸다.
보내는 것은 종류 이름 하나뿐이고 파일 이름·점수·도면 내용은 안 보낸다.

- `week.rechecks` — 진짜 재검사 횟수. 새로 셈
- `week.recheckers` — 예전의 '2회 이상' 값. **지우지 않고 남겼다.** 지우면 그 주 숫자가
  통째로 끊긴다
- `total.done` — 검사 완료 수. 시작(`check`)과 나눠 세니 중간에 터진 검사가 보인다

## 확인

```
python -m pytest test_events.py -q
→ 3 passed
```

`test_events.py` 가 `/api/event` 로 보낸 재검사 1건이 `week.rechecks` 에 잡히는지,
모르는 종류(`vote`)는 400 으로 막히는지, 예제 검사 한 번에 `samples` 와 `done` 이
같이 1 오르는지를 본다.

**아직 부분 해결이다.** 두 가지가 남았다.

1. 브라우저 기록을 지우거나 다른 기기에서 올리면 재검사로 안 세어진다. **실제보다 적게 나온다.**
   서버가 파일 이름을 안 갖는 한 이건 못 없앤다.
2. 화면 카드는 여전히 `recheckers`(2회 이상)를 큰 숫자로 보여 준다. 진짜 재검사 수가
   충분히 쌓이기 전에 바꾸면 0 만 보인다. 숫자가 쌓인 뒤 09-12 에 바꿀지 정한다.

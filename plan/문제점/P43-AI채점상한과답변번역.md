## 증상

10-20 밤(배포 전) 공개 서버에서 팀이 만든 예제 도면(`samples/sample_plate.dxf` 첫 줄에 DXF 주석을 넣어 캐시를 피함)을
curl 로 검사했다. UA 에 curl 이 들어가 사이트 통계에는 안 센다.

- 30점(Llama 4 Scout)은 12.4초에 왔다. 첫 응답(8초)보다 늦어 화면이 뒤에 채우는 경로였다.
- 질문 답변 · 번역은 76.8초 뒤 "더 없음"으로 끝났는데, AI 지적에 답변이 한 언어도 없었다.

## 원인

1. **채점 상한 20초.** `check.py` 가 `ai_review.judge` 를 기본값(`ASK_SEC = 20`)으로 부른다. 그날 낮 실측은
   [`ai_bench.py`](../../ai_bench.py) 에서 40초까지 기다려 쟀고, 20번 중 2번이 20초를 넘었다(20.1 · 26.2초).
   공개 서버라면 그 두 번은 시간 초과로 끊겨 30점이 비었다. 운영진 회신 · 문서의 "실패 0/20" 은 40초 기준이었다.
2. **답변 · 번역을 호출 하나로.** 한국어 답과 영어 · 일본어 · 중국어 번역을 한 번에 받았다(출력 510 토큰).
   Workers AI 의 Llama 4 Scout 는 초당 20 토큰 안팎이라 48 ~ 64초가 걸렸고, 한 언어라도 항목 수가 어긋나면
   네 언어를 다 버렸다 — 예제 3장을 만들 때 4번 중 1번, 이날 공개 서버 확인 1번 중 1번.
3. 언어별로 나눠 로컬에서 다시 재 보니 한 언어(중국어)가 120초 동안 답이 없었다. 출력 상한 3000 토큰이
   같은 말 되풀이를 끝까지 허락해서다(3000 토큰 ÷ 초당 20 토큰 ≈ 150초).

## 조치

`b8317a4` (23:20 푸시, 23:21 반영)

- `ASK_SEC` 20 → 45초, `BUDGET_SEC` 45 → 60초. 화면은 8초 뒤 결과를 먼저 보이고 180초까지 받아 가므로(`home.js`)
  길게 기다려도 검사가 멈추지 않는다.
- 답변 · 번역을 언어마다 따로, 동시에 부른다. 어긋난 언어만 버리고, 같은 도면을 다시 열면 빠진 언어만 다시 부른다
  (`_needs_extras`). 출력 상한을 지적 수에 맞추고(300 + 450 × 지적 수), 한 언어를 55초(`PART_SEC`)까지 기다린 뒤
  한 번 더 부른다.
- `/api/health` 에 `ai_recent` — 이 서버 프로세스가 뜬 뒤 채점 성공 · 실패 수, 중앙값 · 최대 초, 답변 · 번역 성공 몫,
  마지막 실패 종류. 서버 로그를 못 보는 사람도 지금 AI 채점이 되는지 볼 수 있다. 실패 이유에는 계정 번호가 든
  주소를 싣지 않는다.
- 시험 3개를 더해 93개 통과(언어별로 살리기 · 상한 · 최근 요약).

- 반영 뒤 `/api/health` 의 `ai_recent`: 채점 3 · 실패 0 · 중앙값 5.5초 · 최대 6.4초 · 답변 · 번역 12/12.
- 운영진 회신에 적은 "채점 실패 0%"는 이제 공개 서버의 상한(45초)이 측정 조건(40초)보다 길어 같은 조건이다.
- 첫 확인 때 배포 직후 첫 응답이 34초 걸리고 응답 하나가 JSON 이 아니었다 — 배포 직후 한 번뿐이었다([P40](P40-배포직후첫응답느림.md)).

## 남은 것

- 같은 도면이라도 Workers AI 응답 시간이 4 ~ 26초로 흔들린다. 45초를 넘는 경우는 아직 못 봤다.
- 예비 채점기가 없어 Cloudflare 가 막히면 30점이 빈다([P35](P35-제미나이18세조항.md) 남은 것).

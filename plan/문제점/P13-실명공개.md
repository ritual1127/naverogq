## 증상

08-30 계획의 3번 항목이 "인터뷰 기록에 실명이 들어가지 않게 한 번 더 확인한다" 였다.
제출 대상인 [`docs/interviews.md`](../../docs/interviews.md) 는 본문을 `박\*후` · `박\*호` 처럼
가려 뒀는데, **링크 하나가 실명이 든 파일 이름을 그대로 달고 있었다.**

```
plan/w2/08-25_화/질문지_박OO_박OO_손선생님.md
```

이 파일 이름이 `docs/interviews.md` 196번째 줄을 포함해 저장소 **7개 문서**에서 링크로 쓰이고 있었다.
본문에도 실명이 남아 있었다 — 질문지 안에 8곳, [인터뷰 대상표](../w2/08-25_화/인터뷰대상표.md) 2곳,
그리고 [08-29 계획](../w2/08-29_토/계획.md) 메모에는 `박\*후(=실명) · 박\*호(=실명)` 처럼
**가린 이름과 실명을 나란히 적어 둔 줄**까지 있었다. 가림 자체가 무의미해지는 줄이다.

저장소는 https://github.com/ritual1127/naverogq 로 **공개**돼 있다.
가린 것은 문서 본문뿐이었고 파일 이름과 대상표는 그대로였다.

## 원인

08-25 에 질문지를 사람별로 나누면서 **파일 이름에 실명을 넣었다.**
그때는 인터뷰 준비 문서라 제출물이 아니었고, 08-29 에 인터뷰를 정리할 때는
본문 가림에만 신경 썼다. 가려야 할 것이 본문만이 아니라 **파일 이름과 대상표와
매핑 줄**이라는 걸 아무도 짚지 않았다.

## 조치

- `질문지_박OO_박OO_손선생님.md` → **`질문지_대면3인.md`** 로 `git mv`
- 저장소 `.md` 전체에서 실명 두 개를 `박\*호` · `박\*후` 로 바꿈 — **11개 파일**
- `박\*후(=실명) · 박\*호(=실명)` 매핑 줄에서 괄호를 지움
- 링크 7개는 새 파일 이름으로 따라 바뀌었다

## 확인

```
git grep -c -F -f <저장소 밖에 둔 실명 파일>   →  0건
```

실명은 저장소 밖 파일에만 둔다. 확인 명령에 이름 조각을 적으면 그 명령이 가림을 다시 푼다(10-10 에 찾음 — 기록 절).

**아직 남은 것** — 08-25 ~ 08-29 커밋에는 실명과 옛 파일 이름이 그대로 있다.
히스토리를 다시 쓰는 것(`filter-branch` 등)은 협업 중인 저장소를 흔들기 때문에
**저장소 주인이 결정할 때만 한다.** 그때까지 이 문제는 열어 둔다.

## 정할 때 볼 것 — 10-10 에 센 것

정하는 것은 [10-11](../w8/10-11_일/계획.md) 박지완이다. 여기에는 센 것만 둔다.

- 이름이나 이름 조각이 들어가거나 빠진 커밋은 13개다(08-25 ~ 09-02, `git log -G`). 10-10 에 확인 줄을 고친 커밋까지 14개.
- 기록을 다시 쓰면 08-25 의 첫 커밋부터 **166개 커밋의 해시가 바뀐다**(10-10 새벽 기준). 문서가 해시를 적어 둔 곳이
  3개(`a666ea3` · `05d7094` · `5e72849`)라 새 해시로 고쳐야 한다. 팀원 셋은 저장소를 다시 받아야 한다.
- [GitHub 문서 "저장소에서 민감한 데이터 제거"](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository) —
  강제 푸시만으로는 안 지워진다. 옛 커밋은 해시 주소로 계속 열리고(캐시), 남이 받아 간 클론 · 포크에 남는다.
  GitHub 쪽에서 완전히 지우려면 지원팀에 요청한다(캐시 삭제 · 가비지 컬렉션). 포크가 있으면 지원팀도 못 지운다.
- 이 저장소는 포크 0 · PR 0 이다(10-10 확인).

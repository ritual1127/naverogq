# P13 · 인터뷰 대상자 실명이 공개 저장소에 그대로 올라가 있었다

| 맡은 사람 | 박지완 |

## 증상

08-30 계획의 3번 항목이 "인터뷰 기록에 실명이 들어가지 않게 한 번 더 확인한다" 였다.
제출 대상인 [`docs/interviews.md`](../../docs/interviews.md) 는 본문을 `박\*후` · `박\*호` 처럼
가려 뒀는데, **링크 하나가 실명이 든 파일 이름을 그대로 달고 있었다.**

```
plan/w2/08-25_화/질문지_박주호_박신후_손선생님.md
```

이 파일 이름이 `docs/interviews.md` 196번째 줄을 포함해 저장소 **7개 문서**에서 링크로 쓰이고 있었다.
본문에도 실명이 남아 있었다 — 질문지 안에 8곳, [인터뷰 대상표](../w2/08-25_화/인터뷰대상표.md) 2곳,
그리고 [08-29 계획](../w2/08-29_토/계획.md) 메모에는 `박\*후(=박신후) · 박\*호(=박주호)` 처럼
**가린 이름과 실명을 나란히 적어 둔 줄**까지 있었다. 가림 자체가 무의미해지는 줄이다.

저장소는 https://github.com/ritual1127/naverogq 로 **공개**돼 있다.
가린 것은 문서 본문뿐이었고 파일 이름과 대상표는 그대로였다.

## 원인

08-25 에 질문지를 사람별로 나누면서 **파일 이름에 실명을 넣었다.**
그때는 인터뷰 준비 문서라 제출물이 아니었고, 08-29 에 인터뷰를 정리할 때는
본문 가림에만 신경 썼다. 가려야 할 것이 본문만이 아니라 **파일 이름과 대상표와
매핑 줄**이라는 걸 아무도 짚지 않았다.

## 조치

- `질문지_박주호_박신후_손선생님.md` → **`질문지_대면3인.md`** 로 `git mv`
- 저장소 `.md` 전체에서 실명 두 개를 `박\*호` · `박\*후` 로 바꿈 — **11개 파일**
- `박\*후(=박신후) · 박\*호(=박주호)` 매핑 줄에서 괄호를 지움
- 링크 7개는 새 파일 이름으로 따라 바뀌었다

## 확인

```
grep -rn "박주호\|박신후" --include=*.md .   →  0건
```

**아직 남은 것** — 08-25 ~ 08-29 커밋에는 실명과 옛 파일 이름이 그대로 있다.
히스토리를 다시 쓰는 것(`filter-branch` 등)은 협업 중인 저장소를 흔들기 때문에
**저장소 주인이 결정할 때만 한다.** 그때까지 이 문제는 열어 둔다.

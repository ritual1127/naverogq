## 증상

북극성 지표는 **주간 재검사 사용자 수**인데 지금 값이 0명이다. 사람이 안 써서가 아니라
**세는 기능 자체가 없다.** `docs/impact.md`에도 "아직 사용자가 몇 명인지 세지 않고 있습니다"라고
적어 두었다.

## 왜 급한가

- W5(09-15 ~ 21) 산출물에 "사용자 기록 — 몇 명이 써 봤고 몇 명이 핵심 행동을 끝냈나"가 있다.
- W6(09-22 ~ 28) 산출물이 통째로 지표다 — 계측 이벤트 · 퍼널 · 리텐션 커브 · 북극성 지표 현황.
- 계측을 09-05에 붙이기로 계획했는데 **그날 못 붙이면 W5 · W6에 낼 숫자가 없다.**

## 조건

이용자 대부분이 미성년 수험생이다. 개인을 알아볼 수 있는 것은 남기지 않는다.
무엇을 세고 무엇을 안 세는지 `docs/policy.md`에 적기 전에는 배포하지 않는다.

## 기록

- 2026-08-22 — 팀 목표 1장을 쓰면서 현재 값이 0이라는 걸 확인.
- 2026-08-30 — **세는 기능을 붙였다.** `stats.py` + `/api/stats` + 화면 아래 "사용 현황".
  접속은 **IP 당 하루 한 명**으로 세고, 검사는 올린 횟수만큼 센다. **주간 재검사 사용자 수**
  (한 주에 두 번 이상 검사한 사람)가 북극성 지표 그대로다.
  IP 는 저장하지 않고 `서버만 아는 임의 값 + 그 주 + IP` 를 해시한 16자만 남긴다.
  주가 바뀌면 값이 달라져 주를 넘겨 이어 볼 수 없다. 무엇을 세는지는 배포 전에
  [`docs/policy.md`](../../docs/policy.md) 와 화면 아래 고지, `README.md` 에 먼저 적었다
  (P07 의 조건이 그것이었다). 시험 1개 추가 — 전체 19개 통과.
  **아직 열려 있는 이유** — 배포 서버에서 실제로 쌓이는 걸 아직 못 봤다.
- 2026-08-30 밤 — **저장을 D1 로 옮겼다.** `CLOUDFLARE_ACCOUNT_ID` · `CADLENS_D1_STATS` ·
  `CLOUDFLARE_API_TOKEN` 셋이 다 있으면 D1 에 쓰고, 하나라도 없으면 지금처럼 서버 안
  sqlite 로 센다(로컬과 시험은 그대로 sqlite). 표는 인터뷰 폼이 쓰던 D1 안에 `hits` 로
  따로 뒀다 — 새 데이터베이스를 만드는 것보다 관리할 게 하나 적다.
  D1 쓰기는 딴 실로 보내 화면을 안 붙잡고, 조회는 30초 캐시다. D1 이 죽어도 검사는 돈다.
  실제 D1 에 넣고 빼서 확인했다 — 접속 2 · 검사 2 · 재검사 1 로 sqlite 와 같은 숫자가
  나왔고, 확인용으로 넣은 줄은 지웠다(`SELECT COUNT(*) FROM hits` → 0).
  **남은 것은 사람 몫** — Render 대시보드에서 `CLOUDFLARE_API_TOKEN` 에 D1 쓰기 권한이
  있는지 보고, `CADLENS_D1_STATS` 값이 들어갔는지 확인해야 한다. 그전까지는 sqlite 로 센다.
- 2026-08-30 밤 — **배포 서버에서 D1 로 쌓이는 것까지 확인해 닫는다.** Render 환경변수 셋이
  다 붙어 `/api/stats` 가 `"store":"d1"` 로 뜬다. 붙기 전에는 `CLOUDFLARE_API_TOKEN` 하나가
  비어 있었고, 그걸 찾으려고 `missing_env` 를 응답에 넣었다(이름만, 값은 안 내보낸다).
  배포된 서버로 접속 1회 · 예제 검사 1회를 보내고 D1 을 직접 조회해
  `visit` 2줄 · `sample` 1줄이 들어간 것을 봤다. `/api/stats` 도 접속 2 · 검사 1 로 같이 움직인다.
  **지표 값 자체는 아직 0에 가깝다** — 세는 기능이 없어서가 아니라 쓰는 사람이 없어서다.
  그건 W5·W6 에서 사람을 데려와야 오르는 숫자이고, 이 문제(셀 방법이 없다)는 여기서 끝난다.

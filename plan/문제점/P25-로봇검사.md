## 증상

W6 제출 전에 사용자 수를 믿을 수 있는지 D1 원자료(1462줄)를 한 값씩 봤다.
기록된 검사 1227번 중 **1147번이 사람이 아니었다.**

- 09-21~22 에 방문자 값 21개가 검사 1134번을 찍었다. 20개는 첫 화면을 한 번도 열지 않고
  검사 API 만 불렀고, 1개는 화면을 7번 열고 하루에 227번 검사했다.
- 09-18 에도 화면 없이 검사만 한 값이 4개(검사 12번) 있었다. 그날은 팀이 속도를 잰 날이다.
- W5 제출본에 북극성 지표를 **09-14 주 10명**으로 냈는데, 그중 3명이 위 09-18 값이었다.
  빼면 **7명**이다.

## 원인

`stats.py` 가 검사를 누가 했는지 가리지 않고 다 셌다. 09-23 에 User-Agent 로 로봇을 거르게
했지만, 그 전 기록에는 적용되지 않았고 브라우저인 척하는 스크립트는 거르지 못한다.
검사 API 를 스크립트가 바로 부르면 사람처럼 세어졌다.

## 조치

검사 화면은 `/` 하나뿐이라 사람은 검사 전에 방문이 찍힌다. 이것으로 가른다.

- `stats.py` 에 `people` 을 두고 세는 곳이 모두 그것을 읽게 했다. **그 주에 방문 없이 검사한
  값**과 **하루 100번 이상 검사한 값**(사람 최대는 30번)을 뺀다. 지난 기록에도 그대로
  적용된다 — 읽을 때 빼기 때문이다.
- 로컬 sqlite 경로가 D1 과 다른 SQL 을 따로 들고 있던 것을 합쳤다. 한쪽만 고쳐지면 로컬과
  공개 숫자가 달라진다.
- 09-21~23 에 방문만 찍힌 1191개 값은 코드로 뺄 수 없어(날짜를 찍어 빼야 한다)
  [`docs/metrics.md`](../../docs/metrics.md)에서만 뺐다.

## 확인

```
python -m pytest -q
→ 82 passed
```

`test_rules.py::test_scripts_are_not_counted_as_people` 가 사람 1명 · 화면 없이 검사한 값 1개 ·
하루 100번 검사한 값 1개를 넣고 사람 1명만 세어지는지 본다.

고친 SQL 을 실제 D1 에 SELECT 로만 돌려 원자료 분석과 같은 값이 나오는 것을 확인했다 —
09-14 주 검사 시작 7명 · 2회 이상 7명, 09-21 주 8명 · 1명, 사람 검사 80번.

**아직 부분 해결이다.** 셋이 남았다.

1. 방문만 한 값은 사람인지 가를 수 없다.
2. 화면을 연 IP와 올린 IP가 다르면(휴대폰 등) 사람도 규칙 ①에 걸린다. 걸린 값 중 검사가
   1~2번뿐인 10개가 그럴 수 있다. 모두 사람으로 쳐도 북극성은 09-14 주 8명 · 09-21 주
   2명이 최대다.
3. 팀이 브라우저로 쓴 것은 가를 수 없다.

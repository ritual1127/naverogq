## 증상

09-04(금) 보안 점검표(09-01에 당겨서 함) 4번 "업로드 도면이 실제로 1시간 뒤
지워지는가"를 확인하다가 두 가지를 찾았다.

1. `.gitignore`에 `.env`가 없었다. 지금 커밋된 `.env` 파일은 없지만(`git ls-files`
   0건), 로컬에서 만든 `.env`를 실수로 `git add`하면 그대로 새는 구조였다.
2. `main.py`의 `_prune_uploads()`(1시간 지난 작업 폴더 삭제)가 **크론이 아니라
   `_run()`, 즉 새 검사 요청이 들어올 때만 호출된다.** 트래픽이 뜸한 시간대엔
   1시간이 지난 폴더도 **다음 요청이 올 때까지** 디스크에 남는다.

## 원인

1번은 처음부터 `.gitignore` 목록에 빠져 있었다 — 만든 사람이 챙기지 않은 항목.
2번은 별도 백그라운드 스케줄러 없이 요청 처리 흐름 안에 정리 로직을 끼워 넣은
설계다. 검사 요청이 자주 오면 문제가 안 되지만, 방문이 뜸하면 "최대 1시간"이란
문구와 실제 동작이 어긋난다.

## 조치

- `.gitignore`에 `.env`, `.env.*` 추가 (2026-09-01)
- `_prune_uploads()` 로직 자체는 로컬 테스트로 맞게 짜여 있음을 확인함
  (1시간 지난 폴더는 지우고 새 폴더는 남김)
- **정리 주기를 09-02에 ①로 정해서 고쳤다.** 새 패키지(APScheduler 등)는 안 붙이고
  `main.py` lifespan에서 asyncio 작업 하나를 띄워 `PRUNE_EVERY_SEC = 10분`마다
  `_prune_uploads()`를 부른다. 화면 문구는 그대로 두고 문구가 참이 되게 코드를 맞췄다 —
  ②로 갔으면 5개 언어 10곳을 고치면서 약속만 약해졌을 것이다.

## 확인

```
python -c "..." 로 old(1시간2분 전)/new 폴더 만들고 _prune_uploads() 직접 호출
→ old 남음: False, new 남음: True
```

```
python -m pytest test_prune.py -q   →  1 passed
```

`test_prune.py`는 **요청을 한 번도 보내지 않고** lifespan만 띄운 상태에서
1시간 2분 지난 폴더가 지워지고 방금 만든 폴더는 남는지 본다. 고치기 전 코드로는
이 테스트가 실패한다(그때는 요청이 있어야만 정리가 돌았다).

**아직 못 한 것** — 배포 서버(Render)에 실제로 도면을 올리고 트래픽 없이 1시간 이상
기다려 정말 지워지는지 실측하는 것. Render 대시보드 접근 권한이 있는 사람 몫이다.
로컬에서 참인 것과 Render 무료 플랜에서 참인 것은 다를 수 있다 — **무료 플랜은
트래픽이 없으면 인스턴스를 재우기 때문에 주기 작업도 같이 멈출 수 있다.** 이건
실측으로만 알 수 있어 상태를 `부분 해결`로 둔다.

# P21 · 같은 도면을 다시 올려도 AI 캐시가 한 번도 안 맞았다

| | |
|---|---|

| 처음 본 날 | 2026-09-08 |
| 무엇에 영향을 주나 | AI 무료 할당량 · 검사 속도 · **재검사 비교의 점수** · 시연 |
| 맡은 사람 | 박지완 |
| 목록 | [문제점 전체](README.md) |

## 증상

같은 도면(`1본체.dxf`)을 API 로 두 번 올렸는데 두 번 다 10초 넘게 걸렸다.
캐시가 맞았다면 두 번째는 1초대여야 한다. 그리고 두 번의 AI 점수가 서로 달랐다.

## 원인

캐시 열쇠를 **AI에게 보낸 그림(PNG)의 해시**로 만들고 있었다. 그런데 같은 도면을 두 번
그리면 그림이 매번 조금씩 다르다.

```
render_png("1본체.dxf") 두 번
  길이   253,727 / 253,668 바이트   ← 다르다
  픽셀   2,400×1,238 중 1,664개(0.056%) 다름
  열쇠   a70f7a11… / 22181058…      ← 그래서 매번 새 열쇠
```

즉 **캐시는 만들어지기만 하고 한 번도 쓰이지 않았다.** 결과는 셋이다.

1. 검사할 때마다 AI를 새로 부른다 — 무료 할당량이 그만큼 빨리 마른다.
2. 같은 도면인데 점수가 매번 달라진다([P02](P02-AI점수편차.md)의 편차가 그대로 노출된다).
3. **재검사 비교**가 거짓말을 한다. 도면을 안 고치고 다시 올려도 점수가 움직인다.

README 에는 "같은 도면을 같은 모델로 다시 검사하면 저장해 둔 응답을 써서 API를 다시
부르지 않습니다"라고 적어 뒀다. 사실이 아니었다.

## 조치

캐시 열쇠를 **도면 파일 내용**으로 바꿨다(`_drawing_blob`). 같은 파일이면 같은 열쇠다.
그림이 아니라 입력을 기준으로 여니 렌더링이 조금 흔들려도 캐시가 맞는다.

## 확인

같은 도면을 API 로 두 번 올렸다.

| | 걸린 시간 | 자동 점수 | AI 항목 |
|---|---|---|---|
| 1회 | 7,246 ms | 86 | 30 |
| 2회 | **1,537 ms** | 86 | 30 |

시험 시간도 같이 줄었다 — `test_events.py::test_sample_counts_start_and_done`
17.80초 → 1.14초. 그 시험이 예제 도면을 실제로 채점하는데, 그동안 매번 AI를 새로
부르고 있었다는 뜻이다.

## 남은 것

- DWG 를 올리면 변환된 DXF 의 내용으로 열쇠를 만든다. LibreDWG 변환이 결정적이지
  않으면 DWG 는 여전히 캐시가 안 맞을 수 있다. 재 보지 않았다.
- 렌더링 자체가 왜 흔들리는지는 아직 모른다. 캐시는 이제 그것과 무관하지만,
  AI가 매번 조금 다른 그림을 본다는 사실은 그대로 남는다([P02](P02-AI점수편차.md)).

# P14 · 파서가 도면 요소 셋을 다른 것으로 봤다

| | |
|---|---|
| 상태 | ✅ **해결** — 2026-08-30 |
| 처음 본 날 | 2026-08-30 |
| 무엇에 영향을 주나 | `EX_DIM_MISSING` 오탐(모든 실제 도면) · `EX_NO_NOTES` · `EX_NO_TITLEBLOCK` 미탐 |
| 맡은 사람 | 박지완 |
| 목록 | [문제점 전체](README.md) |

## 증상

공개문제 형식에 맞춘 [합성 도면 100장](../../합성도면/README.md)을 새로 찍어
`bench.py` 를 돌렸더니 **완전 일치가 66/100** 이었다. 라벨을 잘못 적은 것을
걷어내고 남은 것이 셋인데, 셋 다 **우리 파서가 도면 요소를 다른 것으로 본 것**이었다.

| 도면에 있던 것 | 파서가 본 것 | 결과 |
|---|---|---|
| 제3각법 기호(원 두 개) | 치수 없는 구멍 | `EX_DIM_MISSING` **오탐** |
| `단면도 A-A (1:1)` 뷰 이름표 | 주서 | 주서가 없어도 `EX_NO_NOTES` **미탐** |
| 부품 외형 사각형 | 도면 윤곽선 | 표제란이 없어도 `EX_NO_TITLEBLOCK` **미탐** |

**셋 다 합성 도면만의 문제가 아니다.** 실기 도면에는 제3각법 기호가 반드시 있고,
단면도 이름표도 거의 항상 있으며, 부품 외형은 사각형인 경우가 많다.
기존 기준 도면 18장이 너무 단순해서(도면틀 하나 · 사각형 하나 · 뷰 이름표 없음)
넉 달 동안 안 드러났다.

## 원인

| | 왜 |
|---|---|
| 제3각법 기호 | 원을 걸러 내는 조건이 "치수와 붙어 있나 · 기호 문자 옆인가 · 선 격자 안인가"뿐이었다. 각법 기호는 어디에도 안 걸린다 |
| 뷰 이름표 | `_is_note()` 가 **12자 이상이면 주서**로 봤다. `단면도 A-A (1:1)` 은 13자다 |
| 윤곽선 | `_is_border()` 가 **축에 나란한 닫힌 사각형이면 전부** 윤곽선이었다. 크기를 안 봤다 |

## 조치

`dwg.py` 세 군데.

1. `제3각법`·`third angle` 문자 둘레 **45mm** 를 기호 자리로 보고 그 안의 원을 뺀다.
2. `_VIEW_LABEL_RE` 를 만들어 `정면도·평면도·단면도·상세도…` 로 시작하는 문자는
   길이와 상관없이 주서로 세지 않는다.
3. 윤곽선은 **그려진 것 전체 폭·높이의 60% 이상을 감싸는 사각형**만 인정한다.

## 확인

```
python bench.py 합성도면/labels.json
→ 완전 일치 100/100 · 검출률 100.0% · 정확도 100.0%
python -m pytest test_rules.py -q
→ 20 passed
```

시험을 하나 더 붙였다(`test_synthetic_sheet_is_clean_and_defects_are_caught`) —
기준 도면은 지적 0건이어야 하고, 결함을 하나 넣으면 그것이 잡혀야 한다.
셋 중 어느 하나가 되돌아가면 이 시험이 깨진다.

**이 100% 는 합성 도면 숫자다.** 우리가 심은 결함을 우리 규칙이 잡는다는 뜻이고
실제 수험생 도면 정확도가 아니다 — 그건 [P04](P04-표본도면.md) 다.

## 증상

시연에 쓸 도면을 고르려고 가지고 있는 도면 9장(실기 도면 2장 + 표본 7장)을
한 번에 검사했더니 **9장 전부 오작(실격)** 이었다.

```
1본체.dxf   42/60 실격=True  ['DQ_NO_GEOMETRIC_TOL']
3축.dxf     56/60 실격=True  ['DQ_NO_GEOMETRIC_TOL']
(나머지 7장) 실격=True  ['DQ_NO_SURFACE_SYMBOL', 'DQ_NO_GEOMETRIC_TOL']
```

`1본체.dxf` 와 `3축.dxf` 는 실기 도면이고 **기하공차가 눈으로 보인다.** 그런데
파서는 하나도 못 찾았다. 합성 도면 100장은 같은 날 완전 일치 100장이었다.

## 원인

도면 안의 문자를 다 뽑아 보니 이렇게 들어 있었다.

```
(168.6, 198.5) 'b'      스타일 '텍스트 스타일16'  글꼴 AIGDT___.TTF
(177.0, 199.2) '0.013'  스타일 '주 문자 (ISO)'    글꼴 tahoma.ttf
(189.8, 199.3) 'A'      스타일 '주 문자 (ISO)'
```

**기하공차 기호가 글자 `b` 로 저장돼 있다.** 실기 도면은 기호를 유니코드(⏥ ⌭ ⊥)로
넣지 않고 **GDT 전용 글꼴**(`AIGDT___.TTF` · `gdt.shx`)로 알파벳 한 글자를 찍어
모양을 만든다. 화면에는 기호로 보이지만 파일에 남는 문자는 그냥 알파벳이다.

`dwg.py` 의 `_GDT_TEXT_RE` 는 유니코드 기호와 `%%v` 만 찾고 있었다. 그래서 기하공차가
0개가 되고, 하나도 없으면 오작이므로 **실기 도면은 무조건 실격**이 됐다.

합성 도면에서 안 드러난 이유 — 합성 도면은 우리가 만들면서 기호를 유니코드로
넣었다. 도면을 만든 사람과 규칙을 만든 사람이 같아서 생긴 구멍이다([P04](P04-표본도면.md)).

## 조치

`dwg.py` — 글자가 아니라 **글꼴 이름**을 본다.

1. `_gdt_styles(doc)` — 글꼴 이름에 `gdt` 가 들어간 문자 스타일을 모은다
   (`gdt.shx` · `AIGDT___.TTF` · `amgdt.shx` 가 다 걸린다).
2. 그 스타일로 찍힌 짧은 문자는 좌표와 함께 따로 모은다.
3. `_gdt_frames()` — 기호 글자 기준으로 **같은 줄(±2.5mm) 오른쪽 45mm** 안의
   보통 문자를 훑어 공차값과 데이텀을 붙여 공차칸 하나로 만든다.
4. **값도 데이텀도 없으면 공차칸으로 세지 않는다.** 지름 기호(⌀)도 같은 글꼴로
   찍히기 때문이다. `1본체.dxf` 의 `o` 두 개가 그것이다.

데이텀 정규식도 고쳤다. `^[A-Z]$` 였는데 `3축.dxf` 는 공통 데이텀 `E-F` 를 쓴다.
그대로 두면 데이텀을 못 읽어 이번에는 `EX_FCF_NO_DATUM` 오탐이 났다(51/60).

## 확인

```
1본체.dxf  42/60 실격=False  기하공차 5칸  (전부 데이텀 A 또는 B)
3축.dxf    56/60 실격=False  기하공차 6칸  (전부 공통 데이텀 E-F)
python bench.py 합성도면/labels.json
→ 완전 일치 100/100 · 검출률 100.0% · 정확도 100.0%   (그대로)
python -m pytest -q
→ 30 passed
```

시험을 하나 붙였다 — `test_gdt_font_letters_are_read_as_geometric_tolerance`.
GDT 글꼴 `b` + `0.013` + `A` 는 공차칸 하나로 읽히고, 값도 데이텀도 없는 지름 기호
하나는 공차칸으로 세지 않는다.

**아직 실제 도면 정확도 숫자는 아니다.** 오작 오탐이 사라진 것뿐이고,
`실제도면/labels.json` 이 비어 있어 `bench.py` 는 못 돌린다 — [P04](P04-표본도면.md).

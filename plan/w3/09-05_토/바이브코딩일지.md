# 09-05 바이브 코딩 일지

> 오늘 AI에게 무엇을 시켰고, 무엇이 나왔고, 무엇을 내가 판단했는지 남긴다.
> 코드는 git에 남지만 **왜 그렇게 시켰는지는 여기 아니면 안 남는다.**

오늘 계획은 "이벤트 4가지 심기"였다. 방문 · 검사 시작 · 검사 완료 · 재검사.
그런데 코드를 열어 보니 **넷 중 둘은 이미 08-30에 붙어 있었다.** 남은 둘을 붙이는
일보다, 이미 붙어 있던 것이 **엉뚱한 걸 세고 있다는 걸 발견한 게** 오늘의 본론이 됐다.

## 1부 — 시키기 전에 있는 걸 먼저 읽혔다

계획에는 "저장은 파일 한 개(JSON Lines)면 충분하다. 데이터베이스를 새로 붙이지
않는다"고 적혀 있었다. 그대로 시켰으면 `events.jsonl` 같은 파일이 새로 생겼을 것이다.

먼저 `stats.py`를 읽게 했더니 sqlite와 Cloudflare D1을 같이 쓰는 `hits` 표가
이미 있었다.

```python
UPSERT = ("INSERT INTO hits(day, visitor, kind, n) VALUES(?,?,?,1) "
          "ON CONFLICT(day, visitor, kind) DO UPDATE SET n = n + 1")
```

`kind` 칸이 이미 종류를 받는 구조다. 여기에 `done`과 `recheck`라는 이름 두 개를
더 넣으면 끝이었다. **새 파일을 안 만드는 쪽으로 판단했다.** 계획이 틀렸다기보다
08-30에 앞당겨 한 일을 계획이 모르고 있었던 것이다.

JSON Lines였다면 D1에 안 쌓여서 Render가 다시 뜰 때마다 0부터 셌을 것이다.
그건 [P07](../../문제점/P07-지표0.md)에서 이미 한 번 겪고 고친 문제다.

## 2부 — 숫자가 이름과 다른 걸 세고 있었다

계획의 세 번째 항목이 "본인이 두 번 검사했을 때 재검사가 1 올라간다"였다.
그게 어떻게 세어지는지 SQL을 직접 열어 봤다.

```sql
SELECT COUNT(*) FROM (SELECT visitor, SUM(n) s FROM hits
  WHERE day>=? AND kind IN ('check','sample') GROUP BY visitor HAVING s >= 2)
```

**한 주에 검사를 두 번 한 사람**이다. 재검사가 아니다. 예제 도면을 두 번 눌러도,
서로 다른 도면 두 장을 올려도, 같은 IP를 쓰는 학교 컴퓨터에서 두 사람이 한 번씩
올려도 이 숫자가 올라간다.

화면에는 이렇게 적혀 있었다.

> 한 주에 도면을 두 번 이상 검사한 사람 수입니다. **고쳐서 다시 올렸다는 뜻이라**
> 저희가 제일 중요하게 보는 숫자입니다.

앞 문장은 맞고 뒷 문장은 틀렸다. 그리고 이 숫자는 `/api/stats`로 **아무나 볼 수 있게
공개돼 있다.** 로직이 안 터지니 계속 모르고 지나갈 수 있었고, W5·W6 산출물에 이대로
냈으면 부풀린 숫자를 낸 게 됐을 것이다. [P16](../../문제점/P16-재검사아닌재검사.md)으로
남겼다.

## 3부 — 서버가 못 하는 판별을 브라우저로 옮겼다

진짜 재검사를 서버가 알려면 **같은 파일 이름을 저장해야 한다.** 그런데
[공개 고지](../../../docs/policy.md)에서 파일 이름은 안 남기기로 했다. 이용자
대부분이 미성년 수험생이라 08-30에 그렇게 정했고, 그 결정을 뒤집을 이유가 없었다.

화면 쪽에는 이미 답이 있었다. `cadcheck.history`가 브라우저 안에 같은 파일 이름의
지난 결과를 들고 있다가 "재검사 비교" 상자를 띄운다.

```js
const diff=(prev&&prev.job!==d.job)?buildDiff(prev,now):null;
CMP.set(d.job,diff);histSave(now);
// 같은 파일을 고쳐서 다시 올린 것 = 재검사. 종류 이름만 보낸다(파일명은 안 보냄).
if(diff)fetch('/api/event',{method:'POST',...
```

**그 상자가 실제로 뜬 순간에만** 서버로 `recheck`라는 종류 이름 하나를 보낸다.
파일 이름도 점수도 도면 내용도 안 보낸다. 서버는 종류 이름을 검사해서 모르는 값은
400으로 막는다.

```python
EVENT_KINDS = {"recheck"}
```

이 화이트리스트는 안 시켰는데 붙은 게 아니라 **내가 요구했다.** 화면이 보내는 값을
그대로 `kind`에 넣으면 누구나 아무 종류 이름이나 만들어 통계에 넣을 수 있다.

**대신 잃은 게 있다.** 브라우저 기록을 지우거나 다른 기기에서 올리면 재검사로
안 세어진다. 즉 이 숫자는 **실제보다 적게** 나온다. 부풀려지는 것보다 적게 나오는
쪽이 낫다고 판단했고, 그 한계를 P16에 그대로 적었다.

기존 `recheckers`는 **지우지 않았다.** 지우면 그 주 숫자가 통째로 끊긴다.
화면 카드도 아직 기존 값을 크게 보여준다. 진짜 재검사 수가 쌓이기 전에 바꾸면
0만 보이기 때문이고, 바꿀지는 09-12에 정한다.

## 4부 — 시험을 안 붙였으면 오늘 한 일이 증명이 안 됐다

이벤트를 붙였다는 걸 어떻게 확인하나. 로컬에서 눌러 보는 걸로는 다음 주에
누가 코드를 고쳤을 때 깨지는 걸 못 잡는다. `test_events.py`를 하나 만들게 했다.

```python
def test_sample_counts_start_and_done():
    before = client.get("/api/stats").json()["total"]
    r = client.post("/api/analyze-sample", json={"name": "sample_plate.dxf"})
    assert r.status_code == 200, r.text
    after = client.get("/api/stats").json()["total"]
    assert after["samples"] == before["samples"] + 1
    assert after["done"] == before["done"] + 1
```

```
python -m pytest test_events.py -q      → 3 passed
python -m pytest test_rules.py test_prune.py -q → 26 passed
```

시험 db는 `CADLENS_STAT_DB` 환경변수로 임시 폴더에 만든다. 진짜 통계에 시험
숫자가 섞이면 안 된다.

**검사 완료(`done`)를 따로 센 이유**도 여기서 보인다. 시작(`check`)만 세면 중간에
터진 검사와 결과까지 나온 검사가 같은 수로 잡힌다. `_run()`이 예외를 던지면
`_done()`까지 안 가므로, 두 숫자의 차이가 곧 실패한 검사 수다.

## 5부 — 계획 밖에서 온 것: 운영진 공지

작업 중에 데모데이 공지가 왔다. 계획과 세 군데가 달랐다.

| | 계획에 적혀 있던 것 | 실제 |
|---|---|---|
| 영상 마감 | 09-09(수) 저녁 | **09-08(화) 밤 12시** |
| 내는 방법 | 영상 파일 제출 | **유튜브 주소** |
| 접속 링크 | `xwt-rzfy-pyz` | **`kvw-cpuj-bfx`** (8월 링크 폐기) |

여기서 링크만 고치고 넘어갈 수도 있었다. 그런데 **촬영일(09-08)과 마감이 같은 날
자정**이 됐다는 게 진짜 변화다. 여유가 0이 됐다. 09-09에 있던 제출을 09-08로 옮기고,
09-09는 "제출 확인"으로 바꿨다. 역할 분담 표의 안대열 줄도 같이 고쳤다.

계획 파일은 사후에 예쁘게 고치는 문서가 아니다. 그래서 **왜 바뀌었는지(09-05 공지)를
줄마다 같이 적었다.** 나중에 보면 우리가 늦은 건지 일정이 바뀐 건지 구분이 된다.

## 6부 — 대본은 읽어야 길이를 안다

영상 대본(`docs/demo_script.md`)을 쓰면서, 처음 나온 건 절별 표와 요약이었다.
그걸로는 촬영을 못 한다. **소리 내어 읽을 원고**가 필요했다.

한국어를 편하게 읽으면 1초에 4.5~5자다. 그 기준으로 절마다 글자 수를 세게 했다.

```
① 106자 · 22초    2-2 137자 · 29초    ③ 78자 + 95자
```

3분 중 나레이션이 실제로 말하는 건 2분 30초쯤이고, 나머지 30초는 화면만 도는
구간이다. **그 침묵이 어색한 게 아니라 화면을 보게 만드는 자리**라서 대본에
그렇게 적었다.

인용은 인터뷰 원문을 그대로 썼다.

> "친구가 '여기 베어링 자리인데 거칠기 없어도 돼?'라고 해서 알았어요"
> "끝나기 17분 전쯤이었어요"

다듬으면 그 사람 말이 아니라 우리 말이 된다. 이름은 `박*후`로 가렸다.

③절 판 두 장은 캡컷에서 글자를 얹는 대신 PNG로 그렸다(`docs/demo/make_boards.py`).
색은 화면 어두운 테마 값을 그대로 가져왔다. 판 2에 들어간 문장이 오늘 판단의
요약에 가깝다.

```
그 100% 는 우리가 만든 도면에서 나온 숫자다.
실제 수험생 도면은 두 장뿐이라 현장 정확도는 아직 못 쟀다.
```

운영진이 "막힌 것 하나"를 영상에 담으라고 했다. 제일 잘 되는 숫자(100%)의 한계를
그 자리에 넣는 게 맞다고 봤다.

## 오늘 배운 것

- **계획대로 새로 만들기 전에 있는 걸 읽는다.** 이벤트 넷 중 둘은 이미 있었고,
  저장할 표도 이미 있었다. 계획대로 JSON Lines를 만들었으면 D1에 안 쌓여서
  이미 한 번 고친 문제를 다시 만들 뻔했다.
- **안 터지는 숫자가 제일 무섭다.** `recheckers`는 6일 동안 아무 오류 없이
  잘못된 걸 세고 있었다. 이름과 설명을 코드에 대조해 보지 않았으면 W5 산출물에
  그대로 실렸다.
- **덜 세는 쪽을 골랐다.** 브라우저 기록이 없으면 재검사가 안 세어진다. 이건
  개인정보를 안 받기로 한 결정의 대가고, 지표가 부풀려지는 것보다 낫다.
- **못 한 건 안 했다고 적는다.** 배포 서버에서 실제로 재검사가 오르는지는
  김승준 몫이라 그대로 `⬜`로 뒀다. 로컬 시험 3건이 통과한 건 배포 확인이 아니다.

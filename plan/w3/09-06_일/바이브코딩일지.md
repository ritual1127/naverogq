# 09-06 바이브 코딩 일지

> 오늘 AI에게 무엇을 시켰고, 무엇이 나왔고, 무엇을 내가 판단했는지 남긴다.
> 코드는 git에 남지만 **왜 그렇게 시켰는지는 여기 아니면 안 남는다.**

오늘 계획은 "3분 대본 초안"과 "시연에 쓸 도면 고르기"였다. 대본은 어제 미리 써 뒀고,
**도면을 고르려다 파서가 실제 도면을 통째로 잘못 보고 있다는 걸 찾은 게** 오늘의 본론이 됐다.

## 1부 — 받은 도면 32장을 한 장도 못 열었다

실기 도면 뭉치를 받았다. Inventor `.ipt` 76개, `.idw` 32장, PDF 71개. 우리 검사기는
DXF와 DWG만 읽으니 먼저 변환기부터 시켰다(`idw2dxf.py`, Inventor COM 자동화).

32장 전부 같은 오류로 실패했다.

```
(-2147352567, '예외가 발생했습니다.', (0, None, None, None, 0, -2147467259), None)
```

`E_FAIL` 뿐이라 이유를 안 알려 준다. Inventor를 다시 띄우고 `SilentOperation`을 켜고 꺼
보고, 창을 보이게도 해 봤지만 똑같았다. 여기서 재시도를 멈추고 **파일 안을 직접 열어 봤다.**

```
2027 (Build 310192000, 192)
```

파일은 Inventor 2027로 저장됐고 이 PC에는 2026뿐이었다. Inventor는 자기보다 새 버전이
저장한 파일을 못 연다. **코드 문제가 아니라 환경 문제였다.** 같은 오류를 세 번 넘게
보면 원인을 바깥에서 찾는 게 맞다.

그래서 `idw2dxf.py`에 버전을 미리 읽는 함수를 넣었다. 열어 보고 실패하는 대신
**왜 안 되는지를 먼저 말하게** 했다.

```
A01.dxf <- 동력전달장치-10.idw: 건너뜀 — Inventor 2027로 저장한 도면인데
이 PC에는 2026뿐입니다. Inventor는 자기보다 새 버전 파일을 못 엽니다.
```

PDF 71개도 열어 봤는데 도면이 아니라 기계설계 교재 스캔이었다(둘은 암호까지 걸려 있었다).
**표본은 여전히 실기 도면 2장이다** — [P04](../../문제점/P04-표본도면.md)에 적었다.

## 2부 — 가진 도면 9장이 전부 오작이었다

시연 후보를 고르려고 가지고 있는 도면 9장을 한 번에 돌려 점수와 시간을 재게 했다.

```
1본체.dxf    42/60  실격=True
3축.dxf      56/60  실격=True
(나머지 7장)        실격=True
```

**9장 전부 실격이다.** 합성 도면 100장은 완전 일치 100장인데 실제 도면은 한 장도
통과를 못 한다. 이 시점에 시연 도면 고르기를 멈추고 원인을 봤다.

실격 사유를 뽑으니 9장 다 `DQ_NO_GEOMETRIC_TOL`이었다. 그런데 `1본체.dxf`와 `3축.dxf`는
**기하공차가 눈으로 보이는 실기 도면**이다. 여기서 "도면에 없는 게 맞나"와 "우리가
못 읽나" 둘 중 하나인데, 눈으로 보이는 이상 후자였다.

처음 짐작은 **블록 속성(ATTRIB)** 이었다. 실무 도면은 기호를 블록에 넣는 일이 많고
`virtual_entities()`는 ATTRIB을 안 준다. 확인했더니 ATTRIB이 0개였다. **틀렸다.**

그래서 도면 안 문자를 좌표·글꼴까지 전부 찍어 봤다.

```
(168.6, 198.5) 'b'      스타일 '텍스트 스타일16'  글꼴 AIGDT___.TTF
(177.0, 199.2) '0.013'  스타일 '주 문자 (ISO)'
(189.8, 199.3) 'A'      스타일 '주 문자 (ISO)'
```

**기하공차 기호가 글자 `b`로 저장돼 있었다.** 실기 도면은 기호를 유니코드(⏥ ⌭ ⊥)로
넣지 않고 GDT 전용 글꼴로 알파벳 한 글자를 찍어 모양을 만든다. 화면에는 기호로 보이지만
파일에 남는 문자는 그냥 알파벳이다. 우리 정규식은 유니코드 기호만 찾고 있었다.

## 3부 — 글자 대신 글꼴 이름을 보게 했다

고치는 방향을 두 가지로 놓고 골랐다.

1. `b`·`f`·`n` 같은 글자를 기하공차 기호 목록으로 하드코딩한다
2. **문자 스타일의 글꼴 이름**에 `gdt`가 들어가면 그 글자를 기호로 본다

1번은 표면거칠기 기호 `w`·`x`·`y`와 겹친다. 같은 도면에 둘 다 있으니 글자만으로는
구분이 안 된다. **2번을 골랐다.** `gdt.shx`·`AIGDT___.TTF`·`amgdt.shx`가 한 번에 걸린다.

기호만으로는 공차칸이 아니라서, 같은 줄 오른쪽 45mm 안의 보통 문자를 훑어 공차값과
데이텀을 붙이게 했다. 그리고 **값도 데이텀도 없으면 세지 않게** 했다. 지름 기호(⌀)도
같은 글꼴로 찍히기 때문이다. `1본체.dxf`의 `o` 두 개가 그것이었다.

한 번 더 걸렸다. 고치고 나니 `3축.dxf`가 이번엔 `EX_FCF_NO_DATUM`으로 51/60이 됐다.
데이텀 정규식이 `^[A-Z]$`였는데 이 도면은 **공통 데이텀 `E-F`**를 쓴다. 오작을 없앴더니
다른 오탐이 생긴 것이라 그 자리에서 같이 고쳤다.

```
1본체.dxf  42/60 실격=False  기하공차 5칸
3축.dxf    56/60 실격=False  기하공차 6칸
python bench.py 합성도면/labels.json  → 완전 일치 100/100
python -m pytest -q                   → 30 passed
```

**합성 도면 숫자가 그대로인 것을 반드시 확인했다.** 실제 도면을 통과시키려고 규칙을
느슨하게 만들면 그건 고친 게 아니라 검사를 끈 것이다.

## 4부 — 시험이 진짜 통계 DB에 방문 기록을 쓰고 있었다

시험을 돌리는데 같이 돌리면 깨지고 따로 돌리면 통과했다.

```
FAILED test_events.py::test_visit_and_recheck_counted - assert 2 == 1
```

돌릴 때마다 2 → 3 → 4로 커졌다. 누적된다는 건 임시 DB가 아니라 **진짜 DB를 쓰고 있다는
뜻**이다. `test_events.py`는 자기 파일 맨 위에서 임시 DB를 깔아 두는데,
`test_rules.py`가 끝나면서 그 환경변수를 `del`로 지우고 있었다.

여기서 `test_events.py`만 고치면 다음에 같은 일이 또 난다. **모든 시험보다 먼저 읽히는
`conftest.py`에 임시 DB를 깔고**, `test_rules.py`는 지우는 대신 원래 값으로 되돌리게 했다.
순서를 바꿔도 30건이 통과한다. [P18](../../문제점/P18-시험통계DB.md).

공개하는 지표에 우리 시험이 섞여 들어가고 있었다는 게 더 큰 문제다.

## 5부 — 시연 도면은 우리 도면으로 골랐다

`1본체.dxf`가 시연에 제일 좋다. 실제 실기 도면이고 지적도 잘 보인다. 그런데 **남에게
받은 도면이라 시연 동의를 받았는지 확인이 안 됐다.** 영상은 유튜브에 올라간다.
확인되기 전에는 못 쓴다고 보고, 우리가 만든 `sample_plate.dxf`로 전/후 두 벌을 만들었다.

```
시연_고치기전.dxf  41/60 (68.3%) 실격    지적 6건
시연_고친뒤.dxf    55/60 (91.7%) 오작 아님 지적 2건   검사 1초 미만
```

고친 뒤 파일은 손으로 만들지 않고 스크립트로 만들었다(`docs/demo/make_demo_pair.py`).
영상 편집 중에 도면을 다시 만들 일이 생기면 손으로 한 건 재현이 안 된다.

## 오늘 배운 것

- **같은 오류가 세 번 나오면 코드 밖을 본다.** 32장이 전부 `E_FAIL`이면 그건 코드가
  아니라 환경이다. 파일 안의 버전 문자열 한 줄로 끝났다.
- **첫 짐작이 틀린 것도 과정이다.** 블록 속성이라고 봤는데 ATTRIB이 0개였다. 그걸
  확인했기 때문에 문자를 전부 찍어 볼 생각을 했다.
- **글자를 하드코딩하지 않고 글꼴을 봤다.** 표면거칠기 `w`·`x`·`y`와 겹치기 때문이다.
  좁은 답이 더 짧아 보여도 나중에 충돌한다.
- **고친 뒤 합성 도면 숫자가 그대로인지 먼저 봤다.** 실제 도면을 통과시키려고 규칙을
  느슨하게 하면 검사를 끈 것이다.
- **시험이 깨진 곳이 아니라 깨뜨린 곳을 고쳤다.** `test_events.py`가 깨졌지만 원인은
  `test_rules.py`였다. 깨진 쪽만 고치면 다음에 또 난다.
- **합성 도면 100%로는 안 보이는 것이 있다.** 넉 달 동안 안 보였다.
  [P04](../../문제점/P04-표본도면.md)가 왜 열려 있어야 하는지를 오늘 숫자로 봤다.

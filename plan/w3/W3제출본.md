## 범위는 이렇게 잘랐습니다

핵심 행동을 한 문장으로 먼저 정했습니다. **"도면을 올려 검사 결과를 보고 고친다."**
지난주에 정한 문제 정의 한 문장에서 제품이 실제로 해 주는 동작만 남긴 것이고,
이 문장에 안 걸리는 기능은 남은 8주 동안 만들지 않기로 했습니다.

이번에 만드는 것은 여섯 가지입니다. 도면 업로드(DWG·DXF), 규칙 검사 24개,
AI 투상도 채점 30점, 지적 위치를 도면 위에 번호로 찍기, 브라우저 안에서 재검사 이력 비교,
그리고 실제 도면 기준 정확도 재측정입니다. 앞의 다섯은 이미 돌아가고 마지막 하나가
아직 안 끝났습니다.

자른 것은 아홉 가지입니다. 회원가입·로그인·계정은 안 만듭니다. 이용자 대부분이
미성년이라 개인정보를 아예 안 받는 쪽을 골랐습니다. 채팅·댓글·게시판·프로필도 안 만듭니다.
사용자끼리 만날 곳을 안 만들면 접촉이나 괴롭힘이 생길 구조 자체가 없어집니다.
Inventor 3D 파일(`.ipt`·`.idw`)은 새 파싱 모듈이 필요해서 2D 부터 안정시키기로 했고,
다른 종목으로 넓히는 것은 공개문제를 3회차 이상 확보하기 전에는 코드를 안 건드리기로 했습니다.
확인 안 된 기준으로 규칙을 만들면 응시자에게 틀린 지적을 하게 됩니다.
반 단위 화면과 학교 단위 계약은 8주 목표가 아닙니다. AI 점수를 확정 점수로 표시하는 것도
안 합니다. 편차가 있어서 확실하지 않으면 감점 대신 "사람 확인 필요"로 둡니다.
도면 자동 수정도 안 합니다. 대신 그려 주면 실기 공부가 안 됩니다.

**인터뷰에서 나온 요청인데도 자른 것이 둘 있습니다.** 재질 기입·요목표·표면거칠기
비교표 검사는 표본이 폼 응답 1명뿐이라 검사 항목을 안 늘렸습니다. A4 출력 잘림과
파일 저장 실패 대응은 최\*영 님과 폼 응답에서 나왔지만 프린터 설정은 DXF 파일 안에
없는 정보라 범위 밖으로 뒀습니다. 사용자 말을 다 들은 것이 아니라는 뜻이라
어디를 안 들었는지 그대로 적어 뒀습니다.

전문은 [`docs/mvp.md`](https://github.com/ritual1127/naverogq/blob/main/docs/mvp.md) 에 있습니다.

## 아키텍처는 이렇게 생겼습니다

브라우저에서 도면을 올리면 서버가 받습니다. DWG면 먼저 DXF로 바꿉니다. LibreDWG를
먼저 쓰고 없으면 CloudConvert, 그다음 ODA File Converter 순서이고 셋 다 없으면
변환 안내만 하고 멈춥니다. DXF면 바로 읽습니다.

읽은 뒤에는 두 갈래로 갈립니다. 한쪽은 규칙 채점 60점이고 `exam.py` 안의 순수 코드라
AI를 부르지 않습니다. 실격 판정 6가지도 여기서 합니다. 다른 한쪽은 도면을 PNG 한 장으로
바꿔 AI에게 투상도 30점을 물어보는 길입니다. 같은 그림을 전에 채점한 적이 있으면
캐시에 있는 답을 그대로 쓰고 AI를 새로 부르지 않습니다. AI는 Gemini를 먼저 부르고
막히면 Cloudflare Workers AI, Mistral, Groq 순서로 넘어갑니다. 두 갈래가 만나서
결과 화면이 됩니다. 올린 도면과 결과는 임시 폴더에 최대 1시간, 최근 20건까지만 두고
10분마다 도는 정리 작업이 지웁니다.

**개인정보가 밖으로 나가는 지점은 하나뿐입니다.** AI 채점 때 나가는 PNG 한 장과
파일 종류·투상법·뷰 개수 정도의 요약입니다. 원본 DWG나 DXF 파일 자체는 나가지 않습니다.
다만 **표제란에 이름을 적었으면 그 이름이 그림 안에 함께 찍혀 나갑니다.** 저희가 지울 수
있는 부분이 아니라서 화면 고지에 "올리기 전에 지우고 올리세요"라고 적어 뒀습니다.
나머지 경로는 전부 저희 서버 안에서만 돕니다.

그림 한 장과 상자별 설명은
[`docs/architecture.md`](https://github.com/ritual1127/naverogq/blob/main/docs/architecture.md) 에 있습니다.

## AI 체크리스트를 만들어 15칸을 확인했습니다

무슨 모델을 왜 골랐는지는 지난주에 적었고, 이번에는 **그 AI를 쓰면서 지켜야 할 것을
지켰는지**를 15칸으로 나눠 확인했습니다. **11칸이 됐고 3칸이 반쯤, 1칸은 못 했습니다.**
전부 됐다고 적힌 체크리스트는 확인한 적이 없다는 뜻이라 안 된 칸을 그대로 뒀습니다.

된 것부터 적습니다. 100점 중 AI가 만드는 것은 투상도 30점뿐이고 화면에 보라색 `AI`
표시를 붙입니다. 나머지 60점과 실격 판정은 규칙 코드라 AI를 안 부릅니다. AI가 정해진
형식을 벗어난 답을 보내면 그 답은 버리고 "사람 확인 필요"로 넘깁니다. 지적 하나가
30점을 통째로 깎지 못하게 최대 감점을 12점으로 막아 뒀습니다. 채점 지침의 가장 큰
감점 폭이 8~12점이기 때문입니다. 사용자 도면으로는 어떤 AI도 학습시키지 않습니다.
회원가입도 쿠키도 외부 추적 코드도 없고, 세는 것은 접속 수와 검사 횟수, 재검사 횟수뿐입니다.
API 키는 현재 코드와 커밋 히스토리 전체에서 0건이었습니다.

**안 된 것 셋을 적습니다.**

첫째, **같은 도면에 같은 점수가 안 나옵니다.** 같은 도면을 다섯 번 검사했더니
0점, 0점, 5점, 9점, 18점이 나왔습니다. 폭이 18점이고 표준편차가 7.50점입니다.
처음에는 도면이 백지로 렌더링되는 버그 때문이라고 봤는데 그걸 고친 뒤에도 폭이 그대로라
원인은 프롬프트와 모델 쪽이었습니다. 아직 못 줄였습니다.

둘째, **저희가 공개한 정확도 100%는 실제 시험 도면 숫자가 아닙니다.** 저희가 직접 만든
합성 도면 100장에서 나온 숫자이고, 도면을 만든 사람과 검사 규칙을 만든 사람이 같습니다.
이 한계를 문서와 발표 대본에 그대로 적어 뒀습니다.

셋째, **실제 도면 정확도를 아직 못 쟀습니다.** 라벨을 사람이 눈으로 붙여야 하는데
비어 있고, 실기 도면 표본이 2장뿐입니다.

그리고 배포 서버에서 올린 도면이 1시간 뒤 실제로 지워지는지를 눈으로 확인하는 것도
아직 못 했습니다. 로직은 로컬에서 확인했고 시험도 통과합니다.

전문은 [`docs/ai_checklist.md`](https://github.com/ritual1127/naverogq/blob/main/docs/ai_checklist.md) 에 있고,
모델을 고른 이유는 [`docs/ai_usage.md`](https://github.com/ritual1127/naverogq/blob/main/docs/ai_usage.md),
키 점검은 [`docs/security_check.md`](https://github.com/ritual1127/naverogq/blob/main/docs/security_check.md) 에 있습니다.

## 이번 주에 실제로 겪은 일

**"합성 도면 100%"가 왜 위험한지를 이번 주에 숫자로 봤습니다.**

9월 6일에 데모 영상에 쓸 도면을 고르려고 가지고 있는 도면 9장을 한 번에 검사했습니다.
**9장이 전부 오작(실격)으로 찍혔습니다.** 그중 실기 도면 두 장은 기하공차가 눈으로 보이는데도
저희 파서는 하나도 못 찾았습니다.

도면 안의 문자를 전부 뽑아 보고 알았습니다. 실기 도면은 기하공차 기호를 유니코드 기호로
넣지 않고 **GDT 전용 글꼴로 알파벳 한 글자를 찍어서** 모양을 만듭니다. 화면에는 기호로
보이지만 파일에 남는 문자는 그냥 `b` 입니다. 저희 코드는 유니코드 기호만 찾고 있어서
기하공차가 0개가 됐고, 기하공차가 하나도 없으면 오작이라 실기 도면은 무조건 실격이 됐습니다.

글자가 아니라 글꼴 이름을 보도록 고쳤습니다. 고친 뒤 실기 도면 두 장에서 기하공차가
5칸과 6칸 잡히고 둘 다 오작에서 빠졌습니다. 합성 도면 100장은 고치기 전과 똑같이
100장 전부 일치합니다. **합성 도면으로는 넉 달 동안 안 보였던 결함입니다.**
도면을 만든 사람과 규칙을 만든 사람이 같으면 무엇이 안 보이는지를 이번 주에 확인했습니다.

시험을 돌리다가 하나 더 찾았습니다. **시험이 진짜 통계 DB에 방문 기록을 쓰고 있었습니다.**
시험 파일을 같이 돌리면 방문자 수가 쌓여서 깨지고 따로 돌리면 통과했습니다.
공개하는 지표에 저희 시험이 섞여 들어간 것이라 그날 고쳤습니다.

## 지난주 피드백에 대해

지난주에 받은 보완할 점 셋 중 둘은 아직 그대로입니다.

**인터뷰 대상이 한 학교 2학년에 몰려 있는 것** — 아직 못 넓혔습니다. 이번 주는 MVP·아키텍처·
AI 윤리 산출물에 시간을 썼습니다.

**실제 수험생 도면 확보** — 한 뭉치를 받긴 했는데 **한 장도 못 열었습니다.** Inventor 파일
32장인데 2027 버전으로 저장돼 있고 저희 PC에는 2026이 깔려 있습니다. Inventor는 자기보다
새 버전이 저장한 파일을 못 엽니다. 변환기는 만들어 뒀고 2027이 깔린 PC에서 한 번 돌리면
됩니다. 같이 온 PDF 71개는 도면이 아니라 기계설계 교재 스캔이라 측정에 못 씁니다.
**표본은 여전히 실기 도면 2장입니다.**

**채점자 질문 세 개** — 아직 답을 못 받았습니다.

## 못 한 것과 다음 주 계획

이번 주에 못 한 것은 넷입니다. MVP 범위표를 네 명이 모여 동의하는 절차를 아직 안 밟았습니다.
배포 서버에서 1시간 뒤 삭제를 눈으로 확인하지 못했습니다. 실제 도면 정확도를 못 쟀고,
AI 점수 편차도 못 줄였습니다.

다음 주에는 Inventor 2027이 있는 PC에서 도면 32장을 DXF로 바꿔 라벨을 붙이고 실제 도면
정확도를 처음으로 재겠습니다. 배포 서버에 도면을 올려 1시간 뒤 지워지는지 직접 보겠습니다.
채점자 질문 세 개를 선생님께 다시 여쭙고, 인터뷰 대상을 다른 학년과 다른 학교로 넓히겠습니다.
9월 9일 데모데이 영상은 이번 주에 만든 시연 도면 두 벌로 찍습니다.

## 할 일

### 1. `render_png`가 도면 단위를 반영하게 고치기 — 박지완

- 위치: `ai_review.py`의 `render_png()`. 지금은 `dlayout.Page(0, 0, ...)`로 도면 범위를 **그대로 밀리미터로** 보고 페이지를 만든다.
- `sample_075em07z.dwg`의 `$EXTMIN`~`$EXTMAX`는 약 0.12 × 0.12다. 여기에 사방 5mm 여백을 붙이면 페이지가 거의 전부 여백이 되고 그림은 1픽셀 밑으로 짜부라진다.
- 고치는 방향 두 가지 — ① `$INSUNITS`를 읽어 mm로 환산(1=인치, 4=mm, 6=m 등) ② 단위를 알 수 없으면 도면 범위에 맞춰 페이지를 채우도록 배율을 준다.
- A3(420 × 297)로 그린 도면이 지금처럼 멀쩡히 나오는지도 같이 확인할 것. **회귀 주의.**

### 2. 고친 그림을 저장해 눈으로 확인 — 박지완

- `ai_review.render_png(경로)` 결과를 파일로 써서 실제로 열어 본다.
- **파일 크기만 보고 넘어가지 말 것.** 201바이트면 백지지만 5KB라고 도면이 다 보이는 건 아니다.
- `samples/` 세 개 전부 확인한다.

### 3. `variance.py`로 다시 재기 — 박지완

- `python variance.py samples/sample_075em07z.dwg -n 5`
- 진짜 도면을 봤을 때 지적이 무엇으로 바뀌는지가 핵심이다. "투상도 전체 누락"이 사라져야 정상이다.
- 폭이 줄었으면 줄었다고, 안 줄었으면 안 줄었다고 `docs/accuracy.md`에 적는다.

### 4. 감점 폭 눌러 주기 — 박지완

- 프롬프트는 "형상 표현이 불가능할 정도의 누락: 8~12점"이라고 범위를 줬는데 30점을 다 깎았다.
- 스키마에서 `deduct` 상한을 걸거나 `_to_findings()`에서 항목당 상한을 둔다.
- **상한을 걸었다는 사실을 문서에 적을 것.** 안 적으면 나중에 왜 점수가 안 내려가는지 모른다.

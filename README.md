# CADLens

전산응용기계제도기능사 실기 도면을 제출 전에 스스로 점검하는 서비스입니다.

DWG나 DXF 도면을 올리면 24개 항목을 자동으로 확인하고, 문제가 있는 위치를 도면 위에 번호로 찍어서 보여줍니다. 지적할 때마다 왜 틀렸는지와 어떻게 고치는지도 같이 알려줍니다.

**[CADLens 바로가기](https://naverogq.onrender.com)** · 한국어 / English / 日本語 / 中文 · 밝은 화면과 어두운 화면 지원

---

## 문제 정의

실기 시험은 **4시간 안에 도면을 다 그려서 그 자리에서 제출**합니다. 내고 나면 고칠 수 없습니다.

그런데 떨어지는 이유는 대부분 "그릴 줄 몰라서"가 아닙니다. 도면은 다 그렸는데 **표면거칠기 값을 안 적었거나, 기하공차에 데이텀을 빼먹었거나, 구멍에 지름 치수를 안 넣은** 경우입니다. 이 중 몇 가지는 감점도 아니고 바로 **오작(실격)** 입니다.

이런 실수가 혼자서는 잘 안 보이는 이유가 세 가지 있습니다.

1. **확인할 게 너무 많습니다.** 채점 항목이 7가지로 나뉘고, 그 안에서 봐야 할 세부 항목은 20개가 넘습니다.
2. **틀렸다고 말해주는 사람이 없습니다.** 혼자 연습하면 뭘 빠뜨렸는지 알 방법이 없습니다. 시험 결과도 합격인지 아닌지만 나옵니다.
3. **틀린 걸 모르고 하는 연습은 실수를 굳힙니다.** 틀린 채로 100장을 그리면 101장째도 똑같이 틀립니다.

그래서 **CADLens는 도면을 대신 그려주지 않습니다.** 내기 직전에 빠진 걸 찾아주고, 왜 틀렸는지 알려주는 것만 합니다. 혼자 연습하는 사람도 선생님 없이 `검사 → 고치기 → 다시 검사`를 반복할 수 있게 하는 게 목표입니다.

## 아키텍처

```mermaid
flowchart LR
    A["도면 파일<br/>DWG · DXF"] --> B["웹 화면"]
    B --> C["서버"]
    C --> D["도면 읽기"]
    D --> E["규칙으로 채점<br/>60점"]
    D --> F["AI가 채점<br/>30점"]
    D --> G["도면 그림 만들기"]
    E --> H["결과 화면"]
    F --> H
    G --> H
```

1. **도면을 올립니다.** 웹 화면에서 파일을 끌어다 놓으면 서버로 보냅니다.
2. **DWG면 DXF로 바꿉니다.** `dwg2dxf`로 변환한 뒤 읽습니다. 처음부터 DXF면 건너뜁니다. zip으로 올리면 압축을 풀고 안에서 도면을 찾습니다.
3. **도면에서 정보를 뽑습니다.** 치수 개수, 표면거칠기 기호, 기하공차의 데이텀, 표제란 내용 같은 것들입니다.
4. **채점합니다.** 90점 중 **60점은 규칙으로**, **30점은 AI로** 채점합니다. 실격 조건 5가지는 점수와 상관없이 따로 먼저 확인합니다.
5. **결과를 그림과 같이 돌려줍니다.** 도면을 그려서 문제 자리에 번호를 찍고, 지적 목록과 점수를 같이 보냅니다.

**왜 60점과 30점을 나눴나** — "표면거칠기 값이 비어 있다" 같은 건 답이 정해져 있어서 규칙이 더 빠르고 항상 같은 답을 냅니다. 반대로 "정면도를 잘 골랐나", "뷰가 균형 있게 놓였나"는 규칙으로 만들기 어려워서 이 부분만 AI에 맡겼습니다.

| 파일 | 하는 일 |
|---|---|
| `static/index.html` | 웹 화면 전체. HTML·CSS·JS가 이 파일 하나에 다 들어 있음 |
| `main.py` | 서버. 파일을 받고 결과를 돌려줌 |
| `check.py` | 읽기 → AI 채점 → 규칙 채점 순서를 이어주는 부분 |
| `dwg.py` | 도면 읽기. DWG 변환, 정보 뽑기, 도면 그림 그리기 |
| `exam.py` | 채점. 검사 규칙 24개와 배점표 |
| `ai_review.py` | AI에게 투상도 배열을 물어보는 부분 |
| `bench.py`, `test_rules.py` | 검사가 제대로 되는지 확인 |

웹 화면 쪽에는 React 같은 걸 안 썼습니다. 따로 빌드하는 과정 없이 파일 하나만 열면 되게 하고 싶었습니다.

**배점** — 투상도 선택과 배열 30점(AI) / 치수 15점 / 끼워맞춤·치수공차 10점 / 표면거칠기 10점 / 기하공차 10점 / 주서·표제란 8점 / 재료·열처리 7점, 합쳐서 90점. 각 항목이 어느 KS 규격에서 나왔는지는 [검사 항목과 근거](docs/rule_standards.md)에 정리했습니다.

## 실행 방법

**그냥 쓰려면 [naverogq.onrender.com](https://naverogq.onrender.com) 에 들어가면 됩니다.** 설치할 게 없습니다.

직접 돌려야 한다면(예: 학교에서 도면을 밖으로 안 내보내고 쓰고 싶을 때) Docker로 띄우면 됩니다.

```bash
git clone https://github.com/ritual1127/naverogq.git
cd naverogq
docker build -t cadlens .
docker run -p 7860:7860 cadlens          # AI 없이
docker run -p 7860:7860 -e GOOGLE_API_KEY=... cadlens   # AI까지
```

Dockerfile이 LibreDWG를 알아서 설치해서 DWG가 바로 열립니다. 빌드 마지막에 예제 DWG로 변환이 되는지 한 번 돌려보기 때문에, 변환이 깨진 상태로는 배포되지 않습니다.

| 환경 변수 | 꼭 필요한가 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` 또는 `GOOGLE_API_KEY` | 아니요 | 넣으면 투상도 30점을 Gemini가 채점 |
| `ANTHROPIC_API_KEY` | 아니요 | Gemini 키가 없을 때 Claude가 채점 |
| `AI_PROVIDER` | 아니요 | `gemini` 또는 `claude`로 직접 지정 |

**AI 키를 안 넣어도 돌아갑니다.** 투상도 30점이 "사람 확인 필요"로 비워지고, 나머지 60점 검사와 실격 확인은 그대로 됩니다.

## 검사 내용

24개 항목을 봅니다. 결과는 실격 / 오류 / 경고 / 참고로 나눠서 보여주고, 번호를 누르면 도면에서 그 위치로 이동합니다.

| 무엇을 | 어떤 걸 확인하나 |
|---|---|
| 치수 (15점) | 치수가 하나도 없는지, 지름 치수가 없는 원·구멍이 있는지 |
| 끼워맞춤·치수공차 (10점) | H7·h6·js5 같은 끼워맞춤 기호가 있는지, 공차가 붙은 치수가 너무 적은지 |
| 표면거칠기 (10점) | 기호는 있는데 값이 비었는지, 한 종류만 써서 다듬질 구분이 없는지, 기호 수가 부족한지 |
| 기하공차 (10점) | 데이텀이 붙어 있는지, 공차값이 비었는지, 개수가 부족한지 |
| 주서·표제란 (8점) | 주서가 있는지, 일반공차·모떼기·열처리 같은 필수 문구가 빠졌는지, 표제란·도면양식이 있는지 |
| 재료·열처리 (7점) | 열처리·표면처리 지시가 있는지 |
| 투상도 (30점) | **점수는 AI가 매깁니다** — 정면도를 잘 골랐는지, 개수가 모자라거나 넘치는지, 제3각법 배치가 맞는지, 배치가 치우치지 않았는지. 여기에 더해 투상도 개수 부족, 중심선·중심마크 없음, 상세도·단면도 문자 표기 없음, 척도 표기 없음은 규칙으로도 잡습니다 |

**실격 조건 5가지**는 점수와 별도로 먼저 확인합니다. 표면거칠기 기호가 아예 없음 / 기하공차 기호가 아예 없음 / 투상법이 제3각법이 아님 / 도면 크기가 요구와 다름 / 표준에 없는 척도. 실제 판정은 그 회차의 공개문제와 지시사항을 우선합니다.

지원 형식은 DWG와 DXF고, 앞으로 ipt, idw, iam도 지원하려고 합니다.

> 항목 24개가 각각 **어느 KS 규격과 채점 기준에서 나왔는지**는 [검사 항목과 근거](docs/rule_standards.md)에서 보세요.

## 정확도

**답을 미리 정해 둔 연습용 도면**으로 잽니다. "치수를 일부러 빼놓은 도면"을 넣고 그걸 정확히 찾아내는지 보는 방식입니다.

| 연습용 도면 | 정확히 맞힘 | 찾아야 할 문제를 찾은 비율 | 없는 문제를 있다고 함 |
|---|---|---|---|
| 18장 | 18장 | 100% (17건 중 17건) | 0건 |

**이 100%가 실제 시험 도면에서도 100%라는 뜻은 아닙니다.** 저희가 직접 만든 도면이라 실제 수험생 도면보다 단순하고, 도면을 만든 사람과 검사 규칙을 만든 사람이 같습니다. 이 표가 보장하는 건 "18가지 상황에서 잡을 걸 잡는다"와 "멀쩡한 도면에 헛지적을 안 한다" 두 가지뿐입니다.

**아직 못 잡는 것도 알고 있습니다.**

- 표면거칠기 기호를 **문자로** 찾기 때문에, 선으로만 그리고 문자를 안 넣으면 못 봅니다.
- 기하공차도 마찬가지로, 기입틀을 선과 문자로 직접 그리면 못 봅니다.
- 중심선을 **레이어·선종류 이름으로** 찾기 때문에, 이름이 CENTER나 중심 계열이 아니면 못 셉니다.
- 윤곽선을 닫힌 사각형으로 찾아서, 선 4개로 그린 윤곽선은 못 봅니다.
- 순수 DXF는 뷰 경계를 알 수 없어서 투상도 개수·배치를 못 셀 때가 있습니다. 이럴 땐 "없다"고 하지 않고 검사를 건너뜁니다.
- 무엇보다 **라벨이 붙은 실제 수험생 도면 표본이 아직 없습니다.**

> 어떻게 쟀는지, 도면 18장이 각각 뭘 확인하는지, 남은 약점 표는 [검사 정확도](docs/accuracy.md)에서 보세요.

## 제출한 뒤에 고친 것

제출하고 나서도 실제 도면을 계속 넣어 보면서 잘못된 걸 찾아 고쳤습니다.

위 연습용 도면으로 확인해 보니 **DXF 도면은 거의 무조건 실격으로 나오고 있었습니다.** 도면에 분명히 있는 내용을 못 읽고 "없다"고 판단하고 있었습니다. 거칠기 기호, 기하공차, 중심선, 투상도, 표제란을 전부 못 읽었고, 반대로 글자가 하나만 있어도 주서가 있다고 봤습니다. 전부 읽게 고쳤고, **알 수 없는 항목은 "없다"고 단정하지 않고 검사를 건너뛰도록** 바꿨습니다.

특히 위험했던 두 가지가 있었습니다.

1. **실격인 도면을 통과시키던 문제** — 방향 표시로 쓰는 `X`, `Y`, `Z` 글자를 표면거칠기 기호로 착각해서, 기호가 하나도 없는(= 실격인) 도면을 "기호가 있다"고 통과시켰습니다. 잘못 지적하는 것보다 **실격을 놓치는 쪽이 더 위험**해서 먼저 고쳤습니다.
2. **표면거칠기 기호에 "치수를 넣으세요"라고 하던 문제** — 거칠기 기호(∇)의 동그라미를 구멍으로 착각했습니다. 처음엔 "기호 옆에 글자가 있으면 넘어가자"로 고쳤는데 글자 없는 기호에서 또 나와서, **모양 차이**로 구분하게 다시 고쳤습니다. 기호의 동그라미는 기호를 이루는 두 선에 딱 붙어 있고, 진짜 구멍은 중심선이 한가운데를 가로지릅니다.

기능도 더 넣었습니다. **다시 검사해서 비교하기**(같은 이름으로 다시 올리면 `고쳐짐 / 그대로 / 새로 생김`과 점수 변화를 보여줌, 기록은 브라우저에만 저장), **지적한 곳으로 바로 이동**, **도면 확대·이동**, 그리고 어두운 화면을 추가했습니다.

> 무엇이 왜 틀렸고 어떻게 고쳤는지 표로 정리한 건 [검사 정확도](docs/accuracy.md)의 `측정으로 잡은 문제`에서 보세요.

## 사용자 수와 지표

**솔직하게 적겠습니다. 아직 사용자가 몇 명인지 세지 않고 있습니다.**

지금은 사람을 모으는 것보다 **먼저 고쳐야 할 게 남아 있다고 봤습니다.** 위 `정확도`에 적었듯이 저희가 만든 도면 18장으로만 검증했고, 실제 수험생 도면으로는 아직 못 재봤습니다. AI가 매기는 30점도 같은 도면에서 점수가 흔들립니다. 이 상태로 홍보해서 사람을 데려오면, 저희 실수가 그대로 수험생 도면에 옮겨갑니다. 그래서 홍보를 하지 않았고, 지금 세어봐야 의미 있는 숫자도 안 나옵니다.

**빠른 시일 안에 품질을 끌어올리고, 그때부터 사용자 수를 집계하려고 합니다.** 실제 수험생 도면으로 정확도를 다시 재고 AI 점수 편차를 줄이는 게 먼저입니다. 집계를 시작하더라도 쓰는 사람 대부분이 미성년 수험생이라, **개인을 알아볼 수 있는 정보는 빼고 검사 횟수 같은 최소한만** 모을 생각입니다.

그래서 지금은 "사용자가 몇 명이다"라고 쓸 수 없습니다. 대신 두 가지를 나눠서 적습니다.

| 기준 도면 정확도 | 18장 중 18장 일치 | [`docs/accuracy.md`](docs/accuracy.md) |
| 문제를 찾은 비율 / 헛지적 | 100% (17건 중 17건) / 0건 | `bench.py`로 자동 측정 |

|---|---|---|---|

| 2022 | 8,562명 | 3,557명 | 51.1% |
| 2023 | 10,180명 | 3,234명 | 50.1% |
| 2024 | 10,044명 | 3,100명 | 53.0% |
| 2025 | 9,752명 | 3,399명 | 50.6% |

매년 1만 명 정도가 필기를 보고 3천 명 넘게 실기를 봅니다. **실기 합격률이 5년째 45~53%라서, 매년 1,500명 정도가 실기에서 떨어집니다.** 이 중 상당수는 그리는 실력이 아니라 표기를 빠뜨려서 떨어집니다. 필기 1만 명 중 실기를 보는 사람이 3천 명뿐인 것도, 준비하다 포기하는 사람이 많다는 뜻으로 봅니다.

## 사회적 가치

하고 싶은 건 하나입니다. **혼자 연습하는 사람도 피드백을 받게 하는 것.**

- **학원에 못 다녀도 피드백을 받습니다.** 실기 준비에서 제일 큰 차이는 틀린 걸 짚어주는 사람이 옆에 있느냐입니다. CADLens는 무료고 가입도 필요 없습니다. 학원 선생님을 대신할 순 없지만 "표면거칠기 값이 비어 있다" 같은 건 아무 때나 잡아줍니다.
- **선생님이 반복하는 확인을 줄여줍니다.** 실습 시간에 선생님 한 명이 학생 30명 도면을 다 보는데, 대부분은 매번 똑같은 확인입니다. 이걸 먼저 걸러주면 선생님은 "왜 이 면을 정면도로 골랐나" 같은, 기계가 못 하는 걸 가르치는 데 시간을 쓸 수 있습니다. 구미전자공업고등학교 김민정 선생님께 수업에서 도면을 어떻게 확인하시는지 여쭤보고 검사 항목에 반영했습니다.
- **채점을 결과가 아니라 공부로 만듭니다.** 공식 시험은 붙었는지만 알려주고 왜 떨어졌는지는 안 알려줍니다. CADLens는 `뭐가 / 어디서 / 왜 틀렸고 / 어떻게 고치는지`를 같이 보여주고, 다시 검사해서 비교하는 기능도 넣었습니다.
- **정직하게 만드는 것도 가치라고 생각했습니다.** 공부용 도구가 틀린 걸 자신 있게 말하면 학생은 틀린 걸 배웁니다. 그래서 잘 되는 것보다 [안 되는 걸 문서로 공개하는 데](docs/accuracy.md) 더 신경 썼습니다. 확실하지 않으면 감점하지 않고 "사람 확인 필요"로 남기고, AI 키가 없으면 30점을 비워두고 아는 척하지 않습니다.
- **오픈소스로 공개했습니다.** MIT라서 다른 학교나 다른 자격증에서 규칙만 바꿔 다시 쓸 수 있고, 저희가 틀렸으면 누구든 지적할 수 있습니다.

## 사업화 가능성

**먼저 밝힙니다. 지금은 돈을 버는 구조가 없고 매출도 없습니다.** 아래는 실적이 아니라 생각해 본 가능성입니다.

**될 만한 이유** — 시험이 1년에 4번 있고 실기 응시자가 5년째 3천 명대로 꾸준합니다. 같은 목적으로 이미 학원·인강·교재에 수십만 원씩 쓰는 시장이고, 개인이 아니라 학교가 사는 구조입니다. 채점 규칙(`exam.py`)만 바꾸면 다른 자격증에도 쓸 수 있고, 서버 1대로 돌아가는 데다 같은 도면을 다시 검사하면 캐시가 답해서 AI 비용이 0입니다.

**생각해 본 방식**

1. **학교에 파는 방식 (제일 현실적)** — 반 단위 화면을 제공합니다. 학생별 제출 기록, 반에서 제일 많이 틀리는 항목, 과제 내주고 걷기. 선생님 채점 시간을 줄여주는 대가로 1년 단위 계약. **미성년자한테 직접 결제를 붙이지 않아도 된다**는 점에서도 이게 낫습니다.
2. **개인은 계속 무료, 추가 기능만 유료** — 기본 검사는 계속 무료로 두고 AI 상세 첨삭, 기록 무제한 보관, PDF 리포트만 유료로. 다만 결제는 보호자나 학교 계정으로만 열어야 합니다.
3. **비슷한 자격증으로 넓히기** — 전산응용건축제도기능사, 기계설계산업기사도 파일 형식과 채점 구조가 거의 같아서 규칙만 추가하면 됩니다.
4. **회사 도면 검토 자동화 (한참 나중에)** — 실제 회사 도면에서 빠진 표기를 찾는 건 제조 회사 설계팀이 실제로 하는 일입니다. 돈은 더 되겠지만 요구 정확도가 훨씬 높아서 지금은 이릅니다.

**팔기 전에 해결해야 하는 것** — 솔직히 지금 상태로는 못 팝니다.

- **정확도 검증이 부족합니다.** 저희가 만든 도면 18장으로만 재봤습니다. 실제 수험생 도면 수백 장으로 다시 재야 합니다.
- **AI 점수가 매번 똑같이 안 나옵니다.** 돈 받고 팔려면 규칙으로 옮기거나 얼마나 차이 나는지부터 재야 합니다.
- **DWG 변환이 GPL 프로그램에 기대고 있고, PyMuPDF가 AGPL입니다.** 소스를 안 열고 팔려면 라이선스를 다시 봐야 합니다.
- **미성년자한테 돈을 받는 건 규제 대상입니다.** 결제를 붙이면 법정대리인 동의 같은 조건이 붙습니다.

## 개인정보 처리

**한 줄로 줄이면 이렇습니다. 회원가입이 없고, 개인정보를 받지 않고, 올린 도면은 검사가 끝나면 서버에서 지웁니다.**

**안 받는 것** — 계정도 로그인도 회원가입도 없습니다. 이름, 이메일, 전화번호, 학교, 수험번호를 묻지 않습니다. 쿠키를 안 씁니다. Google Analytics, 광고 SDK, 방문자 추적, 오류 수집 도구도 전부 없습니다. 외부 사이트에서 파일을 불러오는 것도 없어서 three.js까지 저희 서버에 직접 올려 뒀습니다.

**올린 도면**

| | |
|---|---|
| 뭐에 쓰나 | **그 검사 한 번에만** 씁니다 |
| 얼마나 두나 | **최대 1시간, 최근 20건까지만.** 넘으면 폴더째 지웁니다 |
| 남이 볼 수 있나 | 폴더 이름이 아무렇게나 만든 값이고, 올린 파일을 다시 내려받는 기능 자체가 없습니다 |
| AI 학습에 쓰나 | **안 씁니다.** 사용자 도면으로 어떤 AI도 학습시키지 않습니다 |
| 팔거나 남한테 주나 | 안 합니다 |

**밖으로 나가는 것 — 이건 꼭 알아두세요.** 투상도 30점을 채점할 때 **도면을 그림(PNG)으로 바꿔서 Google Gemini에 보냅니다.** 지금 공개 서버에서 이 기능이 켜져 있습니다. 보내는 건 도면 그림 1장과 파일 종류·투상법·뷰 개수 정도의 요약이고, **원본 DWG나 DXF 파일 자체는 안 보냅니다.** 보낸 뒤로는 Google의 개인정보처리방침과 Gemini 약관을 따르며, 저희가 어떻게 할 수 있는 부분이 아닙니다. 같은 도면을 다시 검사하면 저장해 둔 답을 써서 다시 보내지 않습니다. 이게 싫으면 Docker로 AI 키 없이 직접 돌리면 됩니다.

**도면 안에 들어 있는 개인정보 — 주의.** 도면 표제란에 이름을 적었으면 **그 이름이 결과 화면에 그대로 뜹니다.** CADLens가 표제란의 작성자·설계자 칸(`DESIGNER`, `DRAWN BY`, `작성자`, `설계자`)을 읽어서 "파일 정보"에 보여주기 때문입니다. 저희가 따로 모으는 게 아니라 도면 파일 안에 원래 들어 있는 값입니다. **남기기 싫으면 올리기 전에 지우고 올리세요.**

**브라우저에만 저장되는 것** — 아래 4개는 내 브라우저에만 있고 서버로 안 갑니다. `cadcheck.lang`(언어), `cadcheck.theme`(밝은/어두운 화면), `cadcheck.enabled`(켜 둔 검사 항목), `cadcheck.history`(다시 검사해서 비교하려고 남기는 기록 — 파일 이름, 시각, 점수, 지적 항목. 최근 20건까지).

문의나 삭제 요청은 [GitHub 이슈](https://github.com/ritual1127/naverogq/issues)로 남겨 주세요. 최대 1시간만 두기 때문에 대부분은 말씀하실 때쯤 이미 지워져 있습니다.

## AI 생성물 표기

**AI가 만드는 건 90점 중 30점입니다.**

| 채점 항목 | 배점 | 누가 만드나 |
|---|---|---|
| **투상도 선택과 배열** | **30점** | **AI (Gemini 또는 Claude)** |
| 치수 / 공차 / 표면거칠기 / 기하공차 / 주서·표제란 / 재료 | 60점 | 규칙 코드 |
| 실격 판정 5가지 | — | 규칙 코드 |

- **투상도 30점과 "AI 총평" 문장이 AI가 만든 결과입니다.** 나머지 60점과 실격 판정은 AI를 전혀 안 씁니다.
- 화면에서 AI가 매긴 항목에는 **보라색 `AI` 표시**를 붙이고, 총평 상자에도 **AI가 쓴 문장**이라고 적어 둡니다. 화면 위쪽에 AI가 켜졌는지도 나옵니다.
- **AI 점수는 매번 똑같이 안 나옵니다.** 같은 도면을 다시 올려도 점수가 달라질 수 있습니다. 그래서 AI한테 "확실하지 않으면 감점하지 말고 참고로만 남겨라"라고 지시해 뒀고, 이 지시문도 코드에 그대로 공개돼 있습니다.
- **AI 키가 없으면 AI를 안 씁니다.** 30점이 "사람 확인 필요"로 뜨고, AI가 없다는 것도 화면에 그대로 나옵니다. 없는데 있는 척하지 않습니다.

**코드와 문서를 쓸 때도 AI를 썼습니다.** Claude Code(Claude Opus 5 / Sonnet 5 / Sonnet 4.8), GPT-5.6 Sol, Gemini를 썼습니다. 사람이 한 건 뭘 만들지 정하기, 검사 항목 고르고 KS 규격과 대조하기, 배점 정하기, 실제 도면으로 돌려보며 오류 찾기, 기준 도면 만들기, 마지막에 읽어보고 고칠지 결정하기입니다. AI가 한 건 코드 초안, 코드 정리, 문서와 번역 초안이고 **전부 사람이 확인한 다음에 넣었습니다.**

**AI가 만들지 않은 것** — 검사 규칙 24개의 판정 부분(`exam.py`, `dwg.py`)은 실행할 때 AI를 부르지 않는 순수 규칙 코드입니다. 배점표는 공개된 채점 기준을 보고 사람이 정했고, 정확도 숫자는 `bench.py`로 실제로 잰 값입니다. 로고와 화면 디자인도 직접 만들었습니다.

## 미성년자 안전

**주로 쓰는 사람이 특성화고 학생을 포함한 미성년자라는 걸 전제로 만들었습니다.**

| 걱정되는 것 | CADLens는 어떻게 했나 |
|---|---|
| 개인정보 수집 | **회원가입도 로그인도 없습니다.** 이름·나이·학교·연락처를 묻는 칸 자체가 없습니다 |
| 행동 추적 | **추적 코드가 없습니다.** 쿠키, 분석 도구, 광고 SDK 전부 안 씁니다 |
| 결제 | **없습니다.** 전부 무료고 결제 화면이 아예 없습니다 |
| 광고 | **없습니다.** 배너도 외부 광고 코드도 한 줄 없습니다 |
| 유해한 내용 | 다루는 게 기계 도면뿐입니다. 이미지나 글을 마음대로 만들어내는 기능이 없습니다 |
| 사용자끼리 접촉 | **채팅·댓글·게시판·프로필·친구 기능이 전부 없습니다.** 사용자끼리 만날 곳이 아예 없어서 괴롭힘이나 접근이 생길 구조가 아닙니다 |
| 외부 링크 | 화면에서 나가는 링크는 프로젝트 GitHub 저장소 하나뿐입니다 |

**AI가 안전한 이유** — AI한테 도면 그림 1장을 주고 투상도 배열만 채점하라고 역할을 고정했습니다. 학생이 AI한테 아무 말이나 보낼 수 있는 입력칸이 없습니다. 답변도 정해진 형식(`severity`, `title`, `detail`, `fix`, `deduct`)으로만 받아서, 형식을 벗어난 아무 말이 화면에 뜨지 않습니다. AI가 형식을 안 지키거나 답변을 거부하면 그 결과를 버리고 "사람 확인 필요"로 처리하고, AI가 매기는 감점은 30점을 넘을 수 없게 코드에서 막아 뒀습니다.

**학생을 보호하려고 넣은 표시** — 결과 화면에 "제출 전 확인용 보조 도구고, 최종 제출 전에는 공식 기준을 봐야 한다"는 안내를 항상 띄웁니다. AI가 채점한 항목에는 AI 표시를 붙여 확정 점수가 아니라는 걸 알 수 있게 했고, 확실하지 않은 항목은 감점하지 않고 "사람 확인 필요"로 남깁니다. **틀린 지적으로 학생을 엉뚱한 방향으로 보내지 않는 것**을 제일 중요하게 봤습니다.

**보호자와 선생님께** — 학생이 올린 도면은 서버에 최대 1시간 있다가 지워집니다. 투상도 채점 때 도면 그림이 Google Gemini로 가는데(위 `개인정보 처리` 참고), 밖으로 나가는 게 걱정되시면 **Docker로 학교 서버에 AI 키 없이 띄우시면** 도면이 학교 밖으로 안 나갑니다. 도면 표제란에 학생 이름이 있으면 결과 화면에 뜨니, 수업에서 다 같이 쓰실 때는 **이름을 지우고 올리라고** 안내해 주세요. 걱정되는 점은 [GitHub 이슈](https://github.com/ritual1127/naverogq/issues)로 알려주시면 확인하겠습니다.

- **시험 문제와 채점 기준** — KS 제도 규격, Q-Net이 공개한 [공개문제](https://www.q-net.or.kr/cst006.do?artlSeq=5198906&brdId=Q006&code=1204&gSite=Q&id=cst00602), 공개된 채점 기준만 보고 만들었습니다. **한국산업인력공단의 비공개 채점표를 베끼거나 본 적이 없습니다.** 배점은 `exam.py` 맨 위에 근거와 같이 적어 뒀고, 공개문제 파일을 저장소에 다시 올리지 않았습니다. **CADLens는 공식 채점이 아니고 한국산업인력공단·Q-Net과 아무 관계가 없습니다.**
- **예제 도면** — 저장소에 넣은 예제와 정확도 측정용 도면은 저희가 직접 만들었거나 개인정보를 지운 것입니다. 남의 도면을 함부로 넣지 않았습니다.
- **상표** — `AutoCAD`와 `Inventor`는 Autodesk의 상표, `Q-Net`은 한국산업인력공단의 서비스입니다. 뭘 지원하는지 설명하려고 이름을 쓴 것뿐이고 각 회사와 관계가 없습니다.
- **폰트** — 홈 화면 3D 글자는 Segoe UI Black의 글자 모양을 미리 좌표로 바꿔 쓴 것이고, **폰트 파일 자체는 저장소에 안 넣었습니다.**
- **남의 프로그램** — **LibreDWG(GPL-3.0)** 는 별도 프로그램으로 실행만 하고 코드를 가져다 붙이지 않아서 저희 MIT 코드에 GPL이 옮겨붙지 않습니다. **PyMuPDF(AGPL-3.0)** 는 저희가 소스를 전부 공개하고 있어서 조건을 지키고 있고, 소스를 안 열고 파는 경우엔 상용 라이선스가 필요합니다. 자세한 건 [`NOTICE.md`](NOTICE.md)에 있습니다.

**주의사항** — CADLens는 마지막에 확인하는 걸 도와주는 보조 도구입니다. 도면의 기능이 맞는지, 실제로 가공할 수 있는지, 그 회차의 특별 지시사항까지는 대신 판단할 수 없습니다. 제출 전에는 꼭 그 회차의 공개문제와 지급 자료, 감독위원 지시사항을 같이 확인하세요.

# CADLens

CADLens는 전산응용기계제도기능사 실기 도면을 스스로 점검할 수 있는 서비스입니다.

DWG나 DXF 도면을 올리면 빠진 항목과 잘못된 부분을 찾아주고, 문제가 있는 위치를 도면 위에 번호로 찍어서 보여줍니다. 지적할 때마다 왜 틀렸는지와 어떻게 고치는지도 같이 알려줍니다.

[CADLens 바로가기](https://naverogq.onrender.com)

---

## 문제 정의

전산응용기계제도기능사 실기는 **4시간 안에 도면을 다 그려서 그 자리에서 제출**합니다. 내고 나면 고칠 수 없습니다.

그런데 이 시험에서 떨어지는 이유는 대부분 "그릴 줄 몰라서"가 아닙니다. 도면은 다 그렸는데 **표면거칠기 값을 안 적었거나, 기하공차에 데이텀을 빼먹었거나, 구멍에 지름 치수를 안 넣은** 경우입니다. 이 중 몇 가지는 감점도 아니고 바로 **오작(실격)** 입니다.

이런 실수는 혼자서는 잘 안 보입니다. 이유가 세 가지 있습니다.

1. **확인할 게 너무 많습니다.** 채점 항목이 7가지로 나뉘어 있고, 그 안에서 봐야 할 세부 항목은 20개가 넘습니다. 시험 끝날 때쯤 눈으로 다 훑기가 어렵습니다.
2. **틀렸다고 말해주는 사람이 없습니다.** 학원이나 학교 실습에서는 선생님이 봐주지만, 혼자 연습할 때는 뭘 빠뜨렸는지 알 방법이 없습니다. 시험 결과도 합격인지 불합격인지만 나오고 어디가 틀렸는지는 안 알려줍니다.
3. **연습을 많이 해야 느는데, 틀린 걸 모르고 하는 연습은 실수를 굳힙니다.** 틀린 채로 100장을 그리면 101장째도 똑같이 틀립니다.

그래서 **CADLens는 도면을 대신 그려주지 않습니다.** 내기 직전에 빠진 걸 찾아주고, 왜 틀렸는지 알려주는 것만 합니다. 도면을 올리면 24개 항목을 자동으로 확인하고, 문제 위치를 도면 위에 번호로 표시합니다. 혼자 연습하는 사람도 선생님 없이 `검사 → 고치기 → 다시 검사`를 반복할 수 있게 하는 게 목표입니다.

## 아키텍처

### 전체 흐름

```mermaid
flowchart LR
    A["도면 파일<br/>DWG · DXF"] --> B["웹 화면"]
    B --> C["서버"]
    C --> D["도면 읽기"]
    D --> E["규칙으로 채점<br/>60점"]
    D --> F["AI가 채점<br/>30점"]
    D --> G["도면 그림 만들기"]
    E --> H["결과 화면"]
    F --> H
    G --> H
```

말로 풀면 이렇게 됩니다.

1. **도면을 올립니다.** 웹 화면에서 파일을 끌어다 놓으면 서버로 보냅니다.
2. **DWG면 DXF로 바꿉니다.** DWG는 그대로 읽기 어려워서, `dwg2dxf`라는 변환 프로그램을 돌려 DXF로 바꾼 다음 읽습니다. 처음부터 DXF면 이 단계는 건너뜁니다. zip으로 올리면 압축을 풀고 안에 있는 도면을 찾습니다.
3. **도면에서 필요한 정보를 뽑습니다.** 치수가 몇 개인지, 표면거칠기 기호가 있는지, 기하공차에 데이텀이 붙어 있는지, 표제란에 뭐가 적혀 있는지 같은 것들입니다.
4. **뽑아낸 정보로 채점합니다.** 90점 중 **60점은 규칙으로**, **30점은 AI로** 채점합니다. 실격 조건 5가지는 점수와 상관없이 따로 먼저 확인합니다.
5. **결과를 그림과 같이 돌려줍니다.** 도면을 그림으로 그려서 문제가 있는 자리에 번호를 찍고, 지적 목록과 점수를 같이 보냅니다.

### 왜 60점과 30점을 나눴나

규칙으로 확인할 수 있는 건 규칙으로 했습니다. "표면거칠기 기호에 값이 비어 있다" 같은 건 답이 정해져 있어서 AI를 쓸 이유가 없고, 규칙이 훨씬 빠르고 항상 같은 답을 냅니다.

반대로 "정면도를 잘 골랐나", "뷰가 균형 있게 놓였나"는 규칙으로 만들기 어렵습니다. 이런 부분만 AI에 맡겼습니다.

### 파일별로 하는 일

| 파일 | 하는 일 |
|---|---|
| `static/index.html` | 웹 화면 전체. HTML, CSS, JS가 이 파일 하나에 다 들어 있습니다 |
| `main.py` | 서버. 파일을 받고, 결과를 돌려줍니다 |
| `check.py` | 순서를 정해주는 파일. 읽기 → AI 채점 → 규칙 채점을 차례로 부릅니다 |
| `dwg.py` | 도면을 읽는 부분. DWG 변환, 정보 뽑기, 도면 그림 그리기 |
| `exam.py` | 채점하는 부분. 검사 규칙 24개와 배점표가 여기 있습니다 |
| `ai_review.py` | AI에게 투상도 배열을 물어보는 부분 |
| `bench.py`, `test_rules.py` | 검사가 제대로 되는지 확인하는 부분 |

웹 화면 쪽에는 React 같은 걸 안 썼습니다. 따로 빌드하는 과정 없이 파일 하나만 열면 되게 하고 싶었습니다.

### 주소 목록

| 방식 | 주소 | 하는 일 |
|---|---|---|
| `GET` | `/` | 웹 화면 |
| `GET` | `/api/health` | 지금 뭐가 되는지 알려줌 (지원 형식, AI 켜짐 여부, 검사 목록) |
| `GET` | `/api/samples` | 예제 도면 목록 |
| `POST` | `/api/analyze` | 올린 도면 검사 (최대 200MB) |
| `POST` | `/api/analyze-sample` | 예제 도면 검사 |
| `POST` | `/api/analyze-path` | 내 컴퓨터에 있는 파일 검사 — **같은 컴퓨터에서만 됩니다** |

### 배점

| 항목 | 배점 | 누가 채점하나 |
|---|---|---|
| 투상도 선택과 배열 | 30점 | AI |
| 치수 기입 | 15점 | 규칙 |
| 끼워맞춤·치수공차 | 10점 | 규칙 |
| 표면거칠기 | 10점 | 규칙 |
| 기하공차 | 10점 | 규칙 |
| 주서·표제란 | 8점 | 규칙 |
| 재료·열처리 | 7점 | 규칙 |

합쳐서 90점이고, 실격 조건 5가지는 점수와 별개로 먼저 확인합니다.

## 실행 방법

### 1. 내 컴퓨터에서 실행하기

```bash
git clone https://github.com/ritual1127/naverogq.git
cd naverogq

python -m venv .venv
.venv\Scripts\activate          # 윈도우
# source .venv/bin/activate     # 맥 / 리눅스

pip install -r requirements.txt
python main.py
```

브라우저에서 `http://127.0.0.1:8000` 을 엽니다.

DXF는 바로 열립니다. **DWG를 열려면 LibreDWG의 `dwg2dxf`가 따로 필요합니다.** 없으면 화면에서 DWG가 지원 형식에서 빠집니다. 이럴 땐 CAD에서 `다른 이름으로 저장 > DXF`로 내보내면 그냥 검사할 수 있습니다.

### 2. Docker로 실행하기 (DWG까지 됨)

```bash
docker build -t cadlens .
docker run -p 7860:7860 -e GOOGLE_API_KEY=... cadlens
```

Dockerfile이 LibreDWG를 알아서 설치해서 DWG가 바로 열립니다. 빌드 마지막에 예제 DWG로 변환이 되는지 한 번 돌려보기 때문에, 변환이 깨진 상태로는 배포되지 않습니다.

### 3. 명령줄에서 검사하기

```bash
python check.py drawing.dxf
```

### 4. 테스트 돌려보기

```bash
pytest -q test_rules.py     # 규칙이 안 망가졌는지 확인
python bench.py             # 정확도 측정
python bench.py --check     # 정확도가 떨어지면 실패로 처리 (자동 검사에서 사용)
```

### 환경 변수

| 변수 | 꼭 필요한가 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` 또는 `GOOGLE_API_KEY` | 아니요 | 넣으면 투상도 30점을 Gemini가 채점합니다 |
| `ANTHROPIC_API_KEY` | 아니요 | Gemini 키가 없을 때 Claude가 채점합니다 |
| `AI_PROVIDER` | 아니요 | `gemini` 또는 `claude`로 직접 지정 |
| `CADCHECK_PORT` | 아니요 | 포트 번호 (기본 8000) |

**AI 키를 하나도 안 넣어도 서비스는 돌아갑니다.** 대신 투상도 30점이 "사람 확인 필요"로 비워지고, 나머지 60점 검사와 실격 확인은 그대로 됩니다.

## 전산응용기계제도기능사란?

전산응용기계제도기능사는 CAD로 기계 부품과 조립품 도면을 그리는 능력을 보는 국가기술자격입니다.

한국산업인력공단 Q-Net은 이 자격을 제품 개발, 설계, 생산에 필요한 도면과 모델 파일을 산업 표준에 맞게 만드는 일이라고 설명합니다.

실기는 부품 모양만 그린다고 끝나지 않습니다. 다른 사람이 도면만 보고도 그 부품을 똑같이 만들 수 있게, 크기와 공차와 재료와 가공 방법과 표면 상태까지 다 표시해야 합니다.

공식 시험 내용과 공개문제는 [Q-Net 전산응용기계제도기능사 공개문제](https://www.q-net.or.kr/cst006.do?artlSeq=5198906&brdId=Q006&code=1204&gSite=Q&id=cst00602)에서 볼 수 있습니다.

## 실기 도면에서 확인해야 할 내용

### 투상도

- 부품 모양을 충분히 설명할 수 있는 정면도, 평면도, 측면도가 있는지 확인합니다.
- 필요한 곳에 단면도와 상세도를 사용합니다.
- 제3각법과 도면의 투상법 표시가 서로 맞는지 확인합니다.
- 확대하거나 축소한 뷰에는 척도를 표시합니다.

### 치수

- 부품을 만들 때 필요한 길이, 지름, 반지름과 각도를 빠짐없이 표시합니다.
- 같은 크기의 구멍이 여러 개면 개수와 지름을 함께 표시합니다.
- 치수가 서로 겹치거나 같은 내용을 반복하지 않도록 정리합니다.
- 원과 구멍에는 중심선 또는 중심마크를 표시합니다.

### 끼워맞춤과 치수공차

- 축과 구멍이 결합되는 곳에는 H7, h6, js5 같은 끼워맞춤 표시를 사용합니다.
- 실제 기능에 중요한 치수에는 허용할 수 있는 오차 범위를 표시합니다.
- 공차의 위쪽 값과 아래쪽 값이 바르게 입력됐는지 확인합니다.

### 표면거칠기

- 가공할 면에 표면거칠기 기호와 값을 표시합니다.
- 끼워맞춤면, 접촉면, 일반 가공면의 다듬질 정도를 구분합니다.
- 기호만 있고 거칠기 값이 비어 있지 않은지 확인합니다.

### 기하공차와 데이텀

- 부품의 기준이 되는 면과 축에 데이텀 A, B, C를 표시합니다.
- 필요한 곳에 직각도, 평행도, 동심도, 위치도 등을 표시합니다.
- 기하공차 기호에 공차값과 기준 데이텀이 들어 있는지 확인합니다.

### 주서와 표제란

- 일반공차, 모떼기, 라운드, 열처리와 표면처리 내용을 적습니다.
- 표제란에 품명, 재료, 척도와 필요한 정보를 입력합니다.
- 도면 크기와 윤곽선이 요구 조건에 맞는지 확인합니다.

## 수험생이 자주 놓치는 부분

- 도면 모양은 완성했지만 치수가 빠진 경우
- 구멍에 지름 치수나 중심마크가 없는 경우
- 끼워맞춤 공차를 표시하지 않은 경우
- 표면거칠기 기호만 넣고 값을 적지 않은 경우
- 기하공차에 데이텀이 없는 경우
- 단면도와 상세도에 이름이나 척도가 없는 경우
- 주서의 일반공차, 모떼기 또는 열처리 문구가 빠진 경우
- 표제란과 도면 크기를 마지막에 확인하지 않은 경우

작은 누락 하나는 화면에서 찾기 어렵고, 출력한 뒤에도 지나치기 쉽습니다. CADLens는 이런 실수를 제출 전에 한 번 더 확인하도록 돕습니다.

## CADLens 검사 내용

CADLens는 24개 검사 항목을 사용합니다.

- 치수 누락과 치수 없는 원·구멍
- 끼워맞춤 공차와 치수공차
- 표면거칠기 기호와 값
- 기하공차와 데이텀
- 주서, 표제란과 도면 양식
- 재료, 열처리와 표면처리
- 투상도 개수, 이름, 척도와 배치
- 도면 크기, 투상법과 비표준 척도

검사 결과는 실격, 오류, 경고, 참고로 나눠서 보여줍니다. 문제 번호를 누르면 도면에서 그 위치와 설명을 같이 볼 수 있습니다.

각 검사 항목이 어느 KS 규격과 채점 기준에서 나왔는지는 [검사 항목과 근거](docs/rule_standards.md)에 하나씩 정리해 뒀습니다.

## 검사가 맞는지 확인한 방법

"잘 맞는다"고 말하려면 확인할 방법이 있어야 한다고 생각했습니다. 그래서 **답을 미리 정해 둔 연습용 도면**을 만들었습니다. 예를 들어 "치수를 일부러 빼놓은 도면"을 넣고, CADLens가 그걸 정확히 찾아내는지 봅니다.

| | |
|---|---|
| 연습용 도면 | 18장 (실수 유형별로 한 가지씩) |
| 정확히 맞힌 도면 | 18장 |
| 찾아야 할 문제를 찾은 비율 | 100% (17건 중 17건) |
| 없는 문제를 있다고 한 경우 | 0건 |

다만 이 도면들은 저희가 직접 만든 거라서 실제 수험생 도면보다 단순합니다. **이 100%가 실제 시험 도면에서도 100%라는 뜻은 아닙니다.** 어떻게 쟀는지와 아직 부족한 점은 [검사 정확도](docs/accuracy.md)에 솔직하게 적어 뒀습니다.

## 실격 가능성이 큰 항목

CADLens는 다음 항목을 점수와 별도로 먼저 확인합니다.

- 표면거칠기 기호가 전혀 없는 도면
- 기하공차 기호가 전혀 없는 도면
- 요구한 투상법과 다른 도면
- 요구한 도면 크기와 다른 도면
- 표준에 맞지 않는 척도를 사용한 도면

실제 판정은 해당 회차의 공개문제와 시험 지시사항을 우선합니다.

## 지원 파일

- DWG
- DXF

한국어, 영어, 일본어, 중국어 화면을 지원합니다. 밝은 화면과 어두운 화면을 모두 지원하며, 처음 방문하면 운영체제 설정을 따릅니다.

앞으로 ipt, idw, iam 파일등을 지원하기 위해 노력하겠습니다

## 제출한 뒤에 고친 것

제출하고 나서도 실제 도면을 계속 넣어 보면서 잘못된 부분을 찾아 고쳤습니다. 무엇이 문제였고 어떻게 바꿨는지 남겨 둡니다.

### 잘못 지적하던 문제들을 찾아서 고쳤습니다

위에서 만든 연습용 도면으로 확인해 보니, **DXF 도면은 거의 무조건 실격으로 나오고 있었습니다.** 도면에는 분명히 있는 내용을 CADLens가 읽지 못하고 "없다"고 판단하고 있었습니다.

| 잘못 나오던 것 | 왜 그랬나 |
|---|---|
| 모든 DXF가 "표면거칠기 기호 없음"으로 실격 | 도면에서 거칠기 기호를 읽지 못했습니다 |
| 모든 DXF가 "기하공차 없음"으로 실격 | 기하공차 기호를 읽지 못했습니다 |
| 모든 DXF가 "중심선 없음" | 중심선을 세지 못했습니다 |
| 모든 DXF가 "투상도 0개" | 투상도를 알아보지 못했습니다 |
| 모든 DXF가 "표제란 없음" | 표제란을 알아보지 못했습니다 |
| 글자가 하나만 있어도 "주서 있음" | 도면의 모든 글자를 주서로 착각했습니다 |

전부 읽을 수 있게 고쳤고, 알 수 없는 항목은 "없다"고 단정하지 않고 검사를 건너뛰도록 바꿨습니다.

### 특히 위험했던 두 가지

**1. 실격인 도면을 통과시키던 문제**

도면에 방향 표시로 쓰는 `X`, `Y`, `Z` 같은 글자를 CADLens가 표면거칠기 기호로 착각했습니다. 그래서 거칠기 기호가 하나도 없는(= 실격인) 도면인데도 "기호가 있다"고 통과시켰습니다. 잘못 지적하는 것보다 **실격을 놓치는 쪽이 더 위험**해서 우선 고쳤습니다.

**2. 표면거칠기 기호에 "치수를 넣으세요"라고 하던 문제**

표면거칠기 기호(∇)에도 동그라미가 들어갑니다. CADLens가 그 동그라미를 구멍으로 착각해서 "치수가 빠졌다"고 지적했습니다.

처음에는 "기호 옆에 글자가 있으면 넘어가자"로 고쳤는데, 글자가 없는 기호에서 똑같은 문제가 다시 나왔습니다. 그래서 **모양의 차이**로 구분하도록 다시 고쳤습니다. 기호의 동그라미는 기호를 이루는 두 선에 딱 붙어 있고, 진짜 구멍은 중심선이 한가운데를 가로지릅니다.

### 새로 추가한 기능

- **다시 검사해서 비교하기** — 도면을 고쳐서 같은 이름으로 다시 올리면, 지난번과 비교해서 `고쳐짐 / 그대로 / 새로 생김`과 점수 변화를 보여 줍니다. 한 번 검사하고 끝나는 게 아니라 `검사 → 고치기 → 다시 검사`를 반복할 수 있습니다. 비교 기록은 사용자 브라우저에만 저장되고 서버로 보내지 않습니다.
- **지적한 곳으로 바로 이동** — 지적사항의 번호를 누르면 도면에서 그 위치가 확대됩니다.
- **도면 확대·이동** — 미리보기를 마우스로 끌어서 움직이고, 휠로 확대할 수 있습니다.
- 결과 화면에서 지적사항을 채점 항목보다 먼저 보여 주도록 순서를 바꿨습니다. 수험생이 가장 먼저 볼 내용이라고 생각했습니다.

### 화면

- 화면을 새로 만들고 **어두운 화면**을 추가했습니다. 처음 들어오면 사용자 기기 설정을 따라가고, 오른쪽 위 버튼으로 바꿀 수 있습니다.
- 홈 화면의 CADLens 글자를 입체로 만들어 돌아가게 했습니다.
- 브라우저 탭에 아이콘이 안 나오던 문제를 고쳤습니다.

### 검사 근거 정리

- [검사 항목과 근거](docs/rule_standards.md) — 검사 항목 24개가 각각 어느 KS 규격과 채점 기준에서 나왔는지 정리했습니다.
- 코드를 고칠 때마다 위의 연습용 도면 검사가 자동으로 돌아가서, 고치다가 다른 걸 망가뜨리면 바로 알 수 있게 했습니다.

## 사용자 수와 지표

### 실제 사용자 수는 아직 없습니다

**솔직하게 적겠습니다. CADLens는 지금 인터넷에 올려두기만 했고, 사용자가 몇 명인지 세지 않습니다.**

세지 않는 이유가 두 가지 있습니다.

1. **셀 수 있는 코드를 일부러 안 넣었습니다.** Google Analytics도, 방문자 카운터도, 쿠키도 없습니다. 코드를 다 뒤져도 사용자를 추적하는 부분이 한 줄도 없습니다. 쓰는 사람 대부분이 미성년 수험생이라, 숫자를 자랑하려고 추적 코드를 넣는 것보다 **아무것도 안 모으는 쪽**이 낫다고 생각했습니다.
2. **넣었어도 지금 숫자는 의미가 없습니다.** 홍보를 한 적이 없고, 시험 시즌도 아닙니다.

그래서 "사용자가 몇 명이다"라고는 쓰지 않겠습니다. 대신 **저희가 진짜로 측정한 것**과 **이 문제를 겪는 사람이 몇 명인지**를 나눠서 적습니다.

### 저희가 진짜로 측정한 것

| 무엇 | 값 | 어디서 나온 숫자인가 |
|---|---|---|
| 검사 항목 개수 | 24개 | `exam.py`의 `CHECKS` |
| 기준 도면 정확도 | 18장 중 18장 정확히 일치 | [`docs/accuracy.md`](docs/accuracy.md) |
| 찾아야 할 문제를 찾은 비율 | 100% (17건 중 17건) | `bench.py`로 자동 측정 |
| 없는 문제를 있다고 한 경우 | 0건 | `bench.py`로 자동 측정 |
| 자동 테스트 | 코드를 고칠 때마다 GitHub Actions에서 실행 | `.github/workflows/tests.yml` |
| 검사 한 번에 걸리는 시간 | 몇 초 (AI 채점까지 하면 수십 초) | 직접 재봤습니다 |

이 숫자가 어디까지만 믿을 수 있는지는 [`docs/accuracy.md`](docs/accuracy.md)에 그대로 적어 뒀습니다.

### 이 문제를 겪는 사람은 몇 명인가

사용자 수 대신, **매년 이 시험을 실제로 보는 사람 수**를 근거로 씁니다.

| 연도 | 필기 응시자 | 실기 응시자 | 실기 합격률 |
|---|---|---|---|
| 2021 | 10,856명 | 5,464명 | 45.3% |
| 2022 | 8,562명 | 3,557명 | 51.1% |
| 2023 | 10,180명 | 3,234명 | 50.1% |
| 2024 | 10,044명 | 3,100명 | 53.0% |
| 2025 | 9,752명 | 3,399명 | 50.6% |

여기서 읽을 수 있는 건 이렇습니다.

- **매년 1만 명 정도가 필기를 보고, 3천 명 넘게 실기 시험장에 앉습니다.** CADLens가 직접 도우려는 건 이 실기 응시자입니다.
- **실기 합격률이 5년째 45~53%입니다.** 매년 **1,500명 정도가 실기에서 떨어집니다.** 앞에서 적었듯이 이 중 상당수는 그리는 실력이 아니라 표기를 빠뜨려서 떨어집니다.
- 필기를 본 1만 명 중 실기를 보는 사람이 3천 명뿐이라는 건, 필기에 붙고도 실기 준비하다가 포기하는 사람이 많다는 뜻이기도 합니다. 연습할 때 피드백이 없는 문제가 여기에도 걸려 있다고 봅니다.

## 사회적 가치

CADLens로 하고 싶은 건 하나입니다. **혼자 연습하는 사람도 피드백을 받게 하는 것.**

### 1. 학원에 못 다녀도 피드백을 받을 수 있습니다

실기를 준비할 때 제일 큰 차이는 **틀린 걸 짚어주는 사람이 옆에 있느냐**입니다. 학원에 다니면 선생님이 도면을 봐주지만, 학원비를 못 내거나 근처에 학원이 없으면 혼자 해야 합니다. 혼자 하면 자기가 뭘 빠뜨렸는지 모릅니다.

CADLens는 **무료고, 가입도 안 해도 되고, 브라우저만 있으면 됩니다.** 학원 선생님을 대신할 수는 없지만 "표면거칠기 값이 비어 있다" 같은 건 아무 때나 잡아줍니다. 이것만 걷어내도 혼자 하는 사람이 조금은 덜 불리해집니다.

### 2. 선생님이 반복해서 하는 확인을 줄여줍니다

기계과 실습 시간에 선생님 한 명이 학생 30명 도면을 다 봅니다. 그런데 그중 대부분은 "치수 빠짐", "데이텀 없음" 같은 매번 똑같은 확인입니다.

이런 걸 CADLens가 먼저 걸러주면, 선생님은 **기계가 못 하는 것**을 가르치는 데 시간을 쓸 수 있습니다. 왜 이 면을 정면도로 골랐는지, 이 공차가 실제로 말이 되는지 같은 것들입니다. 실제로 구미전자공업고등학교 김민정 선생님께 수업에서 도면을 어떻게 확인하시는지 여쭤보고 검사 항목에 반영했습니다.

### 3. 채점을 결과가 아니라 공부로 만듭니다

공식 시험은 붙었는지 떨어졌는지만 알려줍니다. 떨어진 사람은 **왜 떨어졌는지도 모른 채** 다음 시험을 준비합니다.

CADLens는 지적할 때마다 `뭐가 / 어디서 / 왜 틀렸고 / 어떻게 고치는지`를 같이 보여주고, 각 항목이 어느 KS 규격에서 나왔는지까지 [문서](docs/rule_standards.md)로 공개합니다. 다시 검사해서 비교하는 기능을 넣은 것도 같은 이유입니다. 점수 매기는 도구가 아니라 **공부하는 도구**로 쓰였으면 합니다.

### 4. 정직하게 만드는 것도 가치라고 생각했습니다

공부용 도구가 틀린 걸 자신 있게 말하면, 학생은 틀린 걸 배웁니다. 그래서 잘 되는 것보다 **안 되는 걸 문서로 공개하는 데** 더 신경 썼습니다.

- 정확도를 어떻게 쟀고 어디까지만 믿을 수 있는지 — [`docs/accuracy.md`](docs/accuracy.md)
- 제출한 뒤에 저희가 찾은 오류와 고친 내용 — 위의 `제출한 뒤에 고친 것`
- 확실하지 않으면 감점하지 않고 "사람 확인 필요"로 남기게 만든 것
- AI 키가 없으면 30점을 비워두고, 아는 척하지 않는 것

### 5. 오픈소스로 공개했습니다

코드를 전부 MIT로 공개했습니다. 다른 학교나 다른 자격증(전산응용건축제도기능사 같은)에서 규칙만 바꿔서 다시 쓸 수 있습니다. 채점 근거도 문서로 공개했으니, 저희가 틀렸으면 누구든 지적하고 고칠 수 있습니다.

## 사업화 가능성

**먼저 밝힙니다. 지금 CADLens는 돈을 버는 구조가 없고, 매출도 없습니다.** 아래는 실적이 아니라 저희가 생각해 본 가능성입니다.

### 사업이 될 만한 이유

| 조건 | 지금 상황 |
|---|---|
| 매년 반복되는 수요 | 시험이 1년에 4번 있고, 실기 응시자가 5년째 3천 명대로 꾸준함 |
| 이미 돈을 쓰는 시장 | 같은 목적으로 학원, 인강, 교재에 이미 수십만 원씩 쓰고 있음 |
| 개인이 아니라 학교가 사는 구조 | 특성화고 기계과, 폴리텍대학, 직업훈련기관 |
| 다른 자격증에도 쓸 수 있음 | 채점 규칙(`exam.py`)만 바꾸면 됨 |
| 운영비가 적게 듦 | 서버 1대 + AI 호출. 같은 도면을 다시 검사하면 캐시가 답해서 AI 비용이 0 |

### 생각해 본 수익 모델

1. **학교에 파는 방식 (제일 현실적)**
   학교나 훈련기관에 반 단위 화면을 제공합니다. 학생별 제출 기록, 반에서 제일 많이 틀리는 항목, 과제 내주고 걷기 같은 기능입니다. 선생님 채점 시간을 줄여주는 대가로 1년 단위로 계약합니다. **미성년자한테 직접 결제를 붙이지 않아도 된다**는 점에서도 이게 낫다고 봅니다.

2. **개인은 계속 무료, 추가 기능만 유료**
   기본 검사는 계속 무료로 두고, AI 상세 첨삭이나 기록 무제한 보관, PDF 리포트 같은 것만 유료로 합니다. 다만 쓰는 사람이 대부분 미성년자라, 유료로 하더라도 결제는 **보호자나 학교 계정**으로만 열어야 한다고 생각합니다.

3. **비슷한 자격증으로 넓히기**
   전산응용건축제도기능사나 기계설계산업기사도 파일 형식(DXF)과 채점 구조가 거의 같습니다. 규칙만 추가하면 같은 프로그램을 그대로 쓸 수 있습니다.

4. **회사 도면 검토 자동화 (한참 나중에)**
   시험 채점이 아니라 **실제 회사 도면에서 빠진 표기를 찾는 일**은 제조 회사 설계팀이 실제로 하는 업무입니다. 회사마다 정해둔 도면 규격을 규칙으로 등록해서 납품 전에 확인하는 방식입니다. 돈은 더 되겠지만 요구하는 정확도가 훨씬 높아서, 지금 실력으로는 이르다고 봅니다.

### 팔기 전에 해결해야 하는 것

솔직히 말하면 지금 상태로는 못 팝니다.

- **정확도 검증이 부족합니다.** 저희가 만든 기준 도면 18장으로만 재봤습니다. 실제 수험생 도면 수백 장으로 다시 재보지 않으면 "잘 맞는다"고 말하면서 팔 수 없습니다.
- **AI 점수가 매번 똑같이 나오지 않습니다.** 투상도 30점은 AI가 매기니까 같은 도면인데 점수가 달라질 수 있습니다. 돈 받고 팔려면 이 부분을 규칙으로 옮기거나, 얼마나 차이 나는지부터 재야 합니다.
- **DWG 변환이 GPL 프로그램에 기대고 있습니다.** 상용으로 팔려면 라이선스 구조를 다시 봐야 합니다([`NOTICE.md`](NOTICE.md) 참고).
- **PyMuPDF가 AGPL입니다.** 지금은 소스를 공개하고 있어서 괜찮지만, 소스를 안 열고 팔려면 상용 라이선스를 사야 합니다.
- **미성년자한테 돈을 받는 건 규제 대상입니다.** 결제를 붙이는 순간 법정대리인 동의 같은 조건이 붙습니다. 학교에 파는 방식을 먼저 생각한 이유이기도 합니다.

## 개인정보 처리

**한 줄로 줄이면 이렇습니다. 회원가입이 없고, 개인정보를 받지 않고, 올린 도면은 검사가 끝나면 서버에서 지웁니다.**

### 안 받는 것

- **계정도 로그인도 회원가입도 없습니다.** 이름, 이메일, 전화번호, 학교, 수험번호를 묻지 않습니다.
- **쿠키를 안 씁니다.**
- **접속 분석 도구가 없습니다.** Google Analytics, 광고 SDK, 방문자 추적, 오류 수집 도구 전부 없습니다. 외부 사이트에서 파일을 불러오는 것도 없어서, three.js까지 저희 서버에 직접 올려 뒀습니다.

### 올린 도면 파일은 어떻게 되나

| | |
|---|---|
| 어디로 가나 | 브라우저에서 CADLens 서버로 갑니다 |
| 뭐에 쓰나 | **그 검사 한 번에만** 씁니다 |
| 어디 저장되나 | 서버의 임시 폴더 (`uploads/` 안에 아무 글자 12개로 만든 폴더) |
| 얼마나 두나 | **최대 1시간, 그리고 최근 20건까지만** 둡니다. 넘으면 폴더째 지웁니다 |
| 남이 볼 수 있나 | 폴더 이름이 아무렇게나 만든 값이고, 올린 파일을 다시 내려받는 기능 자체가 없습니다 |
| AI 학습에 쓰나 | **안 씁니다.** 사용자 도면으로 어떤 AI도 학습시키지 않습니다 |
| 팔거나 남한테 주나 | 안 합니다 |

### 밖으로 나가는 것 — 이건 꼭 알아두세요

**투상도 30점을 채점할 때, 도면을 그림(PNG)으로 바꿔서 Google Gemini에 보냅니다.**

- 지금 공개 서버에서 이 기능이 **켜져 있습니다.**
- 보내는 것: 도면을 그린 PNG 그림 1장 + 파일 종류, 투상법, 뷰 개수 정도의 요약. **원본 DWG나 DXF 파일 자체는 안 보냅니다.**
- 보낸 뒤로는 **Google의 개인정보처리방침과 Gemini 약관**을 따릅니다. 저희가 어떻게 할 수 있는 부분이 아닙니다.
- 같은 도면을 다시 검사하면 서버에 저장해 둔 답을 쓰기 때문에 다시 보내지 않습니다.
- **이게 싫으면**: 직접 설치해서 AI 키 없이 돌리면 됩니다(위 `실행 방법` 참고). 30점만 비워지고 나머지는 그대로 됩니다.

이것 말고 사용자 데이터가 밖으로 나가는 곳은 없습니다.

### 도면 안에 들어 있는 개인정보 — 주의

**도면 표제란에 이름을 적었으면, 그 이름이 결과 화면에 그대로 뜹니다.**

CADLens는 표제란에서 품번, 재질과 함께 **작성자·설계자 칸(`DESIGNER`, `DRAWN BY`, `작성자`, `설계자`)을 읽어서 "파일 정보"에 보여줍니다.** 저희가 따로 모으는 게 아니라 **도면 파일 안에 원래 들어 있는 값**입니다.

- 이름이나 수험번호를 남기기 싫으면 **올리기 전에 표제란에서 지우고 올리세요.**
- 이 값도 다른 데이터와 똑같이 최대 1시간 뒤에 서버에서 지워집니다.

### 브라우저에만 저장되는 것

아래 4가지는 **내 브라우저에만 저장되고 서버로 안 갑니다.** 브라우저에서 사이트 데이터를 지우면 같이 사라집니다.

| 이름 | 내용 |
|---|---|
| `cadcheck.lang` | 고른 언어 (한국어/영어/일본어/중국어) |
| `cadcheck.theme` | 밝은 화면인지 어두운 화면인지 |
| `cadcheck.enabled` | 켜 둔 검사 항목 |
| `cadcheck.history` | 다시 검사해서 비교하려고 남기는 기록 — 파일 이름, 시각, 점수, 지적 항목. 최근 20건까지 |

### 문의

개인정보 관련해서 물어보거나 지워달라고 하실 게 있으면 [GitHub 이슈](https://github.com/ritual1127/naverogq/issues)에 남겨 주세요. (최대 1시간만 두기 때문에, 대부분은 말씀하실 때쯤 이미 지워져 있습니다.)

## AI 생성물 표기

이 프로젝트에서 **AI가 만든 것**과 **사람이 만든 것**을 나눠서 밝힙니다.

### 1. 검사 결과 중에 AI가 만드는 부분

| 채점 항목 | 배점 | 누가 만드나 |
|---|---|---|
| **투상도 선택과 배열** | **30점** | **AI (Gemini 또는 Claude)** |
| 치수 기입 | 15점 | 규칙 코드 (`exam.py`) |
| 끼워맞춤·치수공차 | 10점 | 규칙 코드 |
| 표면거칠기 | 10점 | 규칙 코드 |
| 기하공차 | 10점 | 규칙 코드 |
| 주서·표제란 | 8점 | 규칙 코드 |
| 재료·열처리 | 7점 | 규칙 코드 |
| 실격 판정 5가지 | — | 규칙 코드 |

- **90점 중 30점, 그리고 "AI 총평" 문장이 AI가 만든 결과입니다.** 나머지 60점과 실격 판정은 AI를 전혀 안 쓰고 규칙으로만 합니다.
- 화면에서도 AI가 매긴 항목에는 **보라색 `AI` 표시**를 붙이고, 총평 상자에는 AI가 쓴 문장이라고 적어 둡니다. 화면 위쪽에도 AI가 켜졌는지 꺼졌는지 나옵니다.
- **AI 점수는 매번 똑같이 나오지 않습니다.** 같은 도면을 다시 올려도 점수가 달라질 수 있습니다. 그래서 AI한테 "확실하지 않으면 감점하지 말고 참고로만 남겨라"라고 지시해 뒀습니다. 이 지시문도 코드에 그대로 공개돼 있습니다.
- **AI 키가 없으면 AI를 안 씁니다.** 이때 30점은 "사람 확인 필요"로 뜨고, AI가 없다는 것도 화면에 그대로 나옵니다. 없는데 있는 척하지 않습니다.

### 2. 코드와 문서를 쓸 때 사용한 AI

이 프로젝트의 **코드, README, 화면 문구는 AI 코딩 도구를 써서 만들었습니다.**

- 쓴 도구: Claude Code (Claude Opus 5 / Sonnet 5 / Sonnet 4.8), GPT-5.6 Sol, Gemini
- 사람이 한 것: 뭘 만들지 정하기, 검사 항목 고르고 KS 규격이랑 대조하기, 배점 정하기, 실제 도면으로 돌려보면서 오류 찾기, 기준 도면 만들기, 마지막에 읽어보고 고칠지 결정하기
- AI가 한 것: 코드 초안, 코드 정리, 문서 초안, 번역 초안
- **AI가 만든 건 전부 사람이 읽어보고 확인한 다음에 넣었습니다.** 특히 채점 규칙은 [`docs/rule_standards.md`](docs/rule_standards.md)에서 항목마다 KS 규격이 맞는지 사람이 직접 대조했습니다.

### 3. AI가 만들지 **않은** 것

- 검사 규칙 24개의 판정 부분 (`exam.py`, `dwg.py`) — 실행할 때 AI를 부르지 않는 순수 규칙 코드입니다.
- 배점표 — 공개된 채점 기준을 보고 사람이 정해서 코드에 적었습니다.
- 정확도 숫자 — `bench.py`로 실제로 잰 값이고, AI가 추측한 게 아닙니다.
- 로고와 화면 디자인 — 직접 만들었습니다.

## 미성년자 안전

**CADLens를 주로 쓰는 사람은 특성화고 학생을 포함한 미성년자입니다.** 이걸 전제로 만들었습니다.

### 원칙: 미성년자한테서 아무것도 안 받습니다

| 걱정되는 것 | CADLens는 어떻게 했나 |
|---|---|
| 개인정보 수집 | **회원가입도 로그인도 없습니다.** 이름, 나이, 학교, 연락처를 묻는 칸 자체가 없습니다 |
| 행동 추적 | **추적 코드가 없습니다.** 쿠키, 분석 도구, 광고 SDK 전부 안 씁니다 |
| 결제 | **없습니다.** 전부 무료고 결제 화면이 아예 없습니다. 유료 전환 팝업도 없습니다 |
| 광고 | **없습니다.** 배너도, 외부 광고 코드도 한 줄 없습니다 |
| 유해한 내용 | 다루는 게 기계 도면뿐입니다. 이미지나 글을 마음대로 만들어내는 기능이 없습니다 |
| 사용자끼리 접촉 | **채팅, 댓글, 게시판, 프로필, 친구 기능이 전부 없습니다.** 사용자끼리 만날 수 있는 곳이 아예 없어서, 괴롭힘이나 접근 같은 게 생길 구조가 아닙니다 |
| 외부 링크 | 화면에서 나가는 링크는 프로젝트 GitHub 저장소 하나뿐입니다 |

### AI가 안전한 이유

- AI한테 **도면 그림 1장을 주고 투상도 배열만 채점하라**고 역할을 고정해 뒀습니다. 학생이 AI한테 아무 말이나 보낼 수 있는 입력칸이 없습니다.
- AI 답변은 **정해진 형식(`severity`, `title`, `detail`, `fix`, `deduct`)으로만 받습니다.** 형식을 벗어난 아무 말이나 화면에 뜨지 않습니다.
- AI가 형식을 안 지키거나 답변을 거부하면 그 결과를 **버리고** "사람 확인 필요"로 처리합니다.
- AI가 매기는 감점은 30점을 넘을 수 없게 코드에서 막아 뒀습니다.

### 학생을 보호하려고 넣은 표시

- 결과 화면에 **"이건 제출 전에 확인하는 보조 도구고, 최종 제출 전에는 공식 기준과 지시사항을 봐야 한다"**는 안내를 항상 띄웁니다.
- AI가 채점한 항목에는 AI 표시를 붙여서, 이 점수가 확정된 점수가 아니라는 걸 알 수 있게 했습니다.
- 확실하지 않은 항목은 그냥 감점하지 않고 "사람 확인 필요"로 남깁니다. **틀린 지적으로 학생을 엉뚱한 방향으로 보내지 않는 것**을 제일 중요하게 봤습니다.

### 보호자와 선생님께

- 학생이 올린 도면은 서버에 **최대 1시간** 있다가 지워집니다.
- 투상도를 채점할 때 도면 그림이 Google Gemini로 갑니다(위 `개인정보 처리` 참고). **밖으로 나가는 게 걱정되시면, 학교에서 소스를 받아 AI 키 없이 학교 서버로 돌리시면 됩니다.** 이러면 도면이 학교 밖으로 안 나갑니다.
- 도면 표제란에 학생 이름이나 수험번호가 있으면 결과 화면에 뜹니다. 수업에서 다 같이 쓰실 때는 **표제란의 이름을 지우고 올리라고** 안내해 주세요.
- 걱정되는 점이 있으면 [GitHub 이슈](https://github.com/ritual1127/naverogq/issues)로 알려주시면 확인하겠습니다.

## 저작권

### 사용자가 올린 도면

**도면 저작권은 그린 사람 것입니다.** CADLens는 검사하려고 잠깐 처리할 뿐, 소유권이나 사용권을 주장하지 않습니다. 학습에 쓰지 않고, 다시 배포하거나 팔지 않고, 최대 1시간 뒤에 지웁니다.

### 시험 문제와 채점 기준

- 검사 규칙은 **공개된 자료만** 보고 만들었습니다. KS 제도 규격, Q-Net이 공개한 공개문제, 공개된 채점 기준입니다.
- **한국산업인력공단의 비공개 채점표를 베끼거나 본 적이 없습니다.** 배점은 `exam.py` 맨 위에 근거와 같이 적어 뒀습니다.
- **CADLens는 공식 채점이 아니고, 한국산업인력공단이나 Q-Net과 아무 관계가 없습니다.** 실제 합격 여부와도 상관없습니다.
- Q-Net 공개문제 파일을 저장소에 다시 올리지 않았습니다. 필요하면 [공식 페이지](https://www.q-net.or.kr/cst006.do?artlSeq=5198906&brdId=Q006&code=1204&gSite=Q&id=cst00602) 링크로 대신했습니다.

### 예제 도면

저장소에 넣은 예제(`samples/`)와 정확도 측정용 도면은 **저희가 직접 만들었거나 개인정보를 지운 것**입니다. 남의 도면을 함부로 넣지 않았습니다.

### 상표

`AutoCAD`와 `Inventor`는 Autodesk의 상표고, `Q-Net`은 한국산업인력공단의 서비스입니다. 이 프로젝트에서는 **뭘 지원하는지 설명하려고** 이름을 쓴 것뿐이고, 각 회사와 아무 관계가 없습니다.

### 폰트

홈 화면의 3D 글자는 Segoe UI Black(마이크로소프트 폰트)의 글자 모양을 미리 좌표로 바꿔서 쓴 것입니다. **폰트 파일 자체는 저장소에 안 넣었습니다.**
